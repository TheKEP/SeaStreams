## 3. Storage Bounds & Cache Management
SeaStreams never grows device storage without bound. Everything it caches lives in `context.cacheDir` under fixed LRU caps, so the worst case is ~250 MB regardless of how much free space the TV has:

| Cache | Location | Cap | Owner |
|---|---|---|---|
| HTTP (TMDB / MDBList / addon JSON, 6–12h TTLs via `CacheTtlInterceptor`) | `cacheDir/http_cache` | `100 MB` LRU (`NetworkModule.HTTP_CACHE_SIZE_BYTES`) | OkHttp `Cache` |
| Images (posters, backdrops, logos) | `cacheDir/image_cache` | `150 MB` LRU (`IMAGE_DISK_CACHE_BYTES`), never a percentage of free disk | Coil 3 `DiskCache` (`ImageLoaderSetup.kt`) |
| Decoded bitmaps | RAM | 25% of the app's memory class (`IMAGE_MEMORY_CACHE_PERCENT`) | Coil 3 `MemoryCache` |
| Usenet segments (Milestone 8) | `cacheDir/nntp_segments` | Performance profile cap (512 MB / 1 GB / 2 GB, Custom ≤ 4 GB), further limited to 25% of free space and never leaving < 2 GB free (`StatFs`) | `SegmentDiskCache` (`ManagedCache`) |
| NZB files (Milestone 8) | `cacheDir/nntp_nzb` | 40 files, 14 days, gzip | `NzbFileCache` (`ManagedCache`) |
| Newznab caps (Milestone 9) | `cacheDir/newznab_caps` | one small XML per indexer (≤ 256 KB), 14 days | `NewznabCapsCache` (`ManagedCache`) |

From Milestone 8, `CacheManager.MANAGED_DIRS` also holds `nntp_segments` and `nntp_nzb` (Milestone 9: `newznab_caps`), so the orphan sweep never deletes them. `clearAll()` calls each injected `ManagedCache.clear()` through its own API. Readers that are open keep their file handles until they finish; their index entries are dropped at once.

- **Playback is memory-only:** ExoPlayer (`SeaStreamsPlayerManager`), `ParallelRangeDataSource`/`ParallelRangeReader`, inline trailers (`InlineTrailerPlayerManager`) and NewPipe (`OkHttpDownloader`) all use `OkHttpClient.withoutDiskCache()` (`UncachedHttpClient.kt`) and buffer in RAM via `LoadControl` / the read-ahead ring. There is no Media3 `SimpleCache` / `CacheDataSource`, and no HTTP stream bytes are written to disk. **The only exception** is the bounded Usenet segment cache above: decoded NNTP articles are written through so seeking back and re-watching don't re-download, within the caps in the table.
- **Coil keeps its own fetcher client**, so images are cached once (in `image_cache`), not again in the HTTP cache. Both Coil caches are created lazily on Coil's dispatchers, so building the singleton never does disk I/O on the main thread.
- **Startup orphan sweep:** `SeaStreamsApp` calls `CacheManager.sweepOrphans()` in its `ApplicationScope` launch: top-level `cacheDir` entries other than `http_cache`/`image_cache` that are older than 1 hour are deleted (newer ones are left in case a library is mid-write).
- **Clear Cache (General Settings → `Other` → `Clear cache`):** `CacheManager.clearAll()` clears Coil's memory + disk caches and `Cache.evictAll()`s OkHttp through their own APIs (their live journals stay valid), then deletes every other `cacheDir` entry. `totalSizeBytes()` sums every file under `cacheDir`. All work runs on the injected `@IoDispatcher` (`Context.getCacheDir()` included, since it may create the folder); the OkHttp `Cache` is a `dagger.Lazy` resolved there too.

## 5. Audio Output Pipeline
- **Renderers** (`PlayerEngineFactory` + `AudioRendererPolicy`): `EXTENSION_RENDERER_MODE_ON`. `MediaCodecAudioRenderer` comes first, then NextLib's `FfmpegAudioRenderer` is appended (Media3's reflection only looks for `androidx.media3.decoder.ffmpeg`, so it's added explicitly). `DefaultTrackSelector` keeps the first renderer that handles a track:
  - Passthrough **on** + sink takes the codec → bitstreamed untouched.
  - Otherwise a hardware decoder (MediaCodec) when the device has one.
  - Otherwise FFmpeg decodes to PCM, so playback never fails or goes silent.
  - A missing native library (`LinkageError`) leaves only the MediaCodec renderers.
- **Sink:** one context-aware `DefaultAudioSink` (16-bit output: FFmpeg's s16 conversion saturates, never wraps) wrapped in `PassthroughGateSink`. While passthrough is off the gate reports every non-PCM format unsupported, so the renderers decode to PCM. This replaces the earlier context-less PCM-only builder (`Builder(context)` ignores `setAudioCapabilities`).
- **Passthrough during playback:** `SeaStreamsPlayerManager.setPassthrough` flips the gate, then `AudioRendererReset` disables `TRACK_TYPE_AUDIO`, waits for `onTracksChanged` to show no audio selected (500 ms fallback) and re-enables it. The renderer then re-decides bitstream vs decode. Both changes can't be sent at once (ExoPlayer would merge them), and the video keeps playing with a brief audio gap.
- **Effects switch passthrough off:** `engagesDsp(before, after)` is true when a change turns Dialogue Boost to a non-Off level, Night Mode on, or Audio Delay to a new non-zero value. `SettingsDataStore.updateAudio` applies `AudioSettings.withPassthroughAutoOff` (repository layer, per profile). In the player, `SessionAudio.withPassthroughAutoOff` plus `setPassthrough` do the same for the session only. Only the engaging change turns it off, so the user can switch passthrough back on (Settings row or the Audio overlay's session toggle) and it stays on.
- **Processor chain** (PCM only; `DefaultAudioSink` bypasses processors for bitstream): `SpeechActivityTap` → `SafeDownmixProcessor` (only when `AudioCapabilities.maxChannelCount ≤ 2`) → `DialogueNightAudioProcessor`. The tap is first so Audio Delay can't skew its timing; the downmix is clip-safe by construction, and the DSP soft limiter still guards boosted peaks.
- **PCM or bitstream:** `SeaStreamsPlayerManager.pcmOutput` (from `AnalyticsListener.onAudioTrackInitialized`, encoding is linear PCM) drives `PlayerUiState.dspAvailable`. The Audio overlay always shows the effect rows; its session passthrough row says whether the current track is bitstreamed (effects pending) or PCM.

## 6. External Subtitle Auto-Sync
Per-profile setting `SubtitleSettings.autoSyncExternal` (`p{id}/subs_auto_sync`, default `true`; General Settings → `Subtitles` → last row *Auto-sync external subtitles*). When it's on and an external (addon) track becomes active, `SubtitleAutoSync` runs on the session scope (analysis on `Dispatchers.Default`) without pausing, re-preparing or seeking:

```text
external cues ─▶ SyncCueFilter ─▶ SyncRate clocks ─▶ ActivityGrid (100 ms cells, ±60 s margin) ──┐
                                                                      ├─▶ OffsetCorrelator.estimate (lags −600..+600 = ±60.0 s, 0.1 s)
reference ─┬─ embedded track: same language, else any full one        │     └─▶ OnsetRefiner ─▶ HalfAgreement ─▶ gate (EARLY/FULL) ─▶ RateFit
           │    ReferenceCueCollector ← onCues(CueGroup.presentationTimeUs, playhead)   ─▶ subtitleOffsetMs + subtitleRate ─▶ refreshCue()
           └─ audio VAD fallback: SpeechActivityTap → SpeechEnergyLog → ActivityGrid.fromSpeech    onStatus ─▶ subtitleSyncStatus
```

- **Fast path:** `ReferenceTrackPicker.pick` returns a `ReferencePick`: an embedded track whose ISO 639 language matches (`en`/`eng`/`en-US`, 639-2/B aliases), else the first full embedded track of any language (also for an `und`/unknown external language; `otherLanguage` is then its 639-2 code). Partial tracks are never used: labels containing forced, signs, songs, foreign or commentary (Matroska often names them without role/forced flags). If only partial tracks exist, auto-sync goes straight to audio. An other-language reference locks only on two consecutive agreeing gated passes (scan and refine), like audio, and `Locked.referenceLanguage` names it in Info. `SeaStreamsPlayerManager.setReferenceTrack` enables it in the background. Its cues are never drawn (the overlay ignores embedded cues while an external track is active), and the HUD/Info read the session's chosen track, never ExoPlayer's text selection. Media3 delivers its cues through `Player.Listener.onCues` while the external track is active: `TextRenderer` stamps each `CueGroup` with `rendererPosition − streamOffset`, the period position. A cue counts as shown when it has text **or a bitmap** (`hasVisibleCue`): Blu-ray PGS cues carry no text, and counting text only once left the reference with zero cues while its span kept growing ("96 s heard", never locking). Events more than 2 s from `player.currentPosition` are dropped as leftovers from before a seek, and `onPositionDiscontinuity` (seek) closes the observed span. Scanned every 5 s; the first gated result locks. The embedded reference is correlated on **cue starts** (`ActivityGrid.fromCueStarts`: ±0.2 s pulses on both sides), not on coverage. An addon file and the disc's track differ in display durations, line merges and SDH lines; in tests that pulled an overlap correlation from the true +5.0 s to +4.5 s, while start times agree. It hands over to audio when the reference has fewer than 5 cues after 20 s (signs-only, silent or bitmap-less tracks), or hasn't locked after 30 s. The audio tap runs from the start, so audio can lock on its first passes after a handover. A same-language reference that timed out (rather than being too sparse) stays enabled until 120 s from the start (`embeddedRateTimeoutMs`): on every rate-search pass of the audio scan it is analysed too, and a FULL result from it locks directly (source embedded). Audio locking first releases it at once. This is what lets a PAL-timed file lock against the disc track mid-film, where no unit-rate result exists and a non-unit rate needs a minute of reference.
- **Analysis cues (`SyncCueFilter`):** before anything is rasterised, cues that are blank or letter/digit-free after `SdhSubtitleCleaner.clean` (sound captions, `♪`-only lines), or last ≥ 10 s, are dropped; if fewer than 20 would remain, all are kept. Display is untouched and the Clean SDH toggle doesn't matter.
- **Frame-rate clocks (`SyncRate`, `RateFit`):** media = subtitle × factor − offset, scaled about t = 0 so the offset stays the file's real intercept. Candidates are `UNIT`, `PAL_TO_FILM` (25/23.976), `PAL_TO_24` (25/24), `FILM_TO_PAL` and `TWENTYFOUR_TO_PAL`. The 1.001 family is left to drift tracking, since a 5-minute window can't separate it from an offset. `SubtitleAutoSync` precomputes the cues on every clock per run. `RateFit.best` analyses the current rate first; only when it is `UNIT`, has no gated result, rate search is on and ≥ 600 cells are covered are the four others tried. A non-unit rate wins only with a FULL result, peak ≥ unit peak + 0.10 and ≥ 1.25 × the best rate of the opposite `family` (25→23.976 and 25→24 differ by 0.1 % and never rival each other). Scanning searches on every 4th pass (`RATE_SEARCH_EVERY`, bounding CPU to 5 analyses per 20 s), and on the pass after a non-unit result so audio's two-pass agreement can complete. Refine and tracking always search while the lock is `UNIT`; a non-unit lock keeps its rate. `PlayerUiState.subtitleRate` holds it, and `PlayerSubtitles.textAt` looks cues up at `rate.toSubtitleUs((position + offset) µs)`.
- **VAD fallback:** the tap logs voice-band energy per media-time cell. A cell counts as speech when its energy is ≥ the 20th-percentile noise floor + 9 dB and its voice share is ≥ 0.3, plus a hangover cell (audio timing therefore resolves to ±0.1 s). The window is the last 5 min before the most recently logged cell, so it follows the playhead after a seek back. Scanned every 5 s for up to 15 min; a lock needs **two consecutive** gated results agreeing within ±0.2 s.
- **Confidence gate, two tiers** (otherwise the offset stays where it is, `0.0s` by default). The cue count is the external cues whose midpoint, at the found offset, lands on a covered reference cell. Onset agreement is the share of those cues starting within ±0.3 s of a reference onset (an active cell after two inactive ones).

  | | EARLY (fast lock) | FULL (confirm/refine) |
  |---|---|---|
  | Covered reference | ≥ 15 s (150 cells) | ≥ 60 s (600 cells) |
  | Cues | ≥ 5 | ≥ 12 |
  | Peak Pearson (embedded / audio) | ≥ 0.45 / 0.5 | ≥ 0.35 / 0.35 |
  | Peak ÷ best outside main lobe | ≥ 1.5 | ≥ 1.5 |
  | z-score | ≥ 3.5 | ≥ 6 |
  | Onset agreement | ≥ 0.8 | ≥ 0.5 |
  | Both halves agree (`HalfAgreement`) | — | each ≥ 5 cues, local peak within ±0.4 s |
  | Offset beyond ±30 s | rejected | allowed |

  Both tiers reject a best lag on the ±60 s edge. **Split-half check:** the covered window is split where half its covered cells lie, and each half is correlated alone within ±3 s (`SEARCH_CELLS = 30`) of the coarse lag via `OffsetCorrelator.estimate(…, lagCells)`. The local peak must lie within ±0.4 s of the coarse lag and off that local range's edge. It is computed once ≥ 600 cells are covered and passed as `WindowEvidence.halvesAgree`; a failure leaves EARLY possible. A wrong rate, a timing jump inside the window, or a chance match carried by one dense stretch fails it. Calibration on synthetic data: with 2–4 lines (15–20 s) another title's dialogue can correlate almost as well as the true match, so EARLY relies on cue starts landing on speech/cue onsets. FULL also needs half of them, because long shared silence (credits, quiet stretches) inflates Pearson on its own. Music, noise, periodic and unrelated dialogue never pass either tier in the tests. Conversation-paced dialogue (a line every ~2.8 s) locks after a median of 20 s.
- **Onset snap (`OnsetRefiner`):** every coarse lag (100 ms cells) is refined before gating. External cue starts are matched to reference onsets: embedded cue start times, or audio speech onsets (an active cell after two inactive ones; the hangover only lengthens ends). The search runs in 50 ms steps within ±1.5 s with a Gaussian score (σ 120 ms). The matched starts' mean signed error then gives a continuous estimate, rounded to 0.1 s; it applies only when ≥ 60 % of cues land within ±150 ms. Cue count and onset agreement are judged at the refined offset; peak, ratio and z stay the coarse ones. Lingering display time can bias the coarse lag by 0.3–0.8 s, and in tests the snap brings embedded and audio locks onto the exact offset.
- **Audio correlated two ways:** speech onsets vs cue-start pulses (immune to display durations) and speech activity vs cue coverage. Either may lock, both through the full gate; a test runs 20 unrelated soundtracks × 5 window sizes through the refinement path and none locks.
- **Refine:** an EARLY lock is applied at once (status `Locked(refining)`), then re-analysed every 20 s for up to 5 min until a FULL result confirms it (audio: two agreeing). A different FULL value is re-applied.
- **Drift tracking:** after the final lock (`Locked(tracking)`), the last 2 min (embedded spans/intervals, or 1,200 audio cells) are re-analysed every 60 s on the locked rate. Two consecutive FULL results agreeing within ±0.2 s (same rate) that differ from the applied offset by 0.1–1.5 s re-centre it, so a 23.976-vs-24 fps file stays in sync. Two agreeing ones on another rate switch the rate (status re-emitted). A larger jump re-centres only after `JUMP_CONFIRMATIONS = 3` consecutive agreeing FULL results (a different cut, an inserted scene). A pass without a FULL result resets the history. The reference track and tap stay on until a stop (manual nudge, track change, session end).
- **Status** (`AutoSyncStatus`, via `onStatus`): `Scanning(source, heardSeconds, cues, bestOffsetMs, bestPeak, onsetPercent, embeddedCues)` → `Locked(source, refining, tracking, rate, referenceLanguage)` → `Locked`, or `NoMatch`. `syncInfoText(offset, status, rate)` adds `· 25→23.976 fps` for a non-unit rate (also after a nudge: `+1.6s · Manual · 25→23.976 fps`) and `(embedded subtitles, fra)` for an other-language reference. A manual nudge sets `Manual`; the setting off or no external track is `Off`. The HUD caption under the sync value reads `Syncing…` / `Auto` / none; the Info row reads e.g. `Syncing… · embedded (0 cues), 20 s`, `Syncing… · audio (18 cues, best +5.1s @ 0.42, 60% onsets), 25 s · embedded gave 2 cues` (the best candidate is shown even below the gate) or `+2.3s · Auto (embedded subtitles) · refining`.
- **Applying:** offsets under 0.1 s apply as `0.0s`. The value is snapped to 0.1 s and clamped to ±60 s, then `PlayerSubtitles.textAt` looks cues up at `position + offset` µs (each cue's start/end shifted) before `CleanSdhTextRenderer`. The current cue is refreshed immediately.
- **Stops** on a manual `−`/`+` nudge (which then wins for the rest of that track), a track change, the setting being off, or session end. Stopping turns the reference track and the tap off synchronously.
- **New stream** of the same title (fallback/switch): an auto offset and rate are dropped and re-detected once the new stream's tracks are known; a manual offset (and its rate) is kept.
- **Session result cache (`AutoSyncSession`, PlayerAutoSync.kt):** `CachedSync(offsetMs, rate, source, manual)` is kept per `syncKey` (playing stream URL + external option id), LRU of 32, cleared by `AutoSyncSession.clear()` in `releaseManager`. `rememberAuto` writes the shown offset/rate on `Locked(tracking)` and on every tracking re-centre. It never writes while `manualOverride` is set or over a `manual` entry. `rememberManual` runs on each HUD nudge, after `autoSync.stop()` has cancelled detection synchronously, and stores the user's offset with the rate in use as `manual = true`. On (re)selection `startAutoSync` checks the cache first:
  - a `manual` entry is restored with `withManualSync` (status `Manual`, `manualOverride = true`, no controller, even with the setting off);
  - an auto entry starts `SubtitleAutoSync.start(…, resume = SyncLock)`, which applies it at once, emits `Locked(tracking)` and goes straight to drift tracking (embedded if the reference is available, else audio).

## 7. Video Output & HDR (PRD §10)
- **Surface:** `PlayerScreen.VideoSurface` is a plain `SurfaceView` bound with `setVideoSurfaceView`. It is the hardware-overlay path, so HDR static/dynamic metadata and Dolby Vision reach HWC/HDMI untouched. `TextureView` (GPU-composited, no HDR passthrough) is used only by inline catalog previews, which are SDR-only: `TrailerStreamSelector` (ResolveTrailerStreamUseCase.kt) skips every candidate `isHdrVideoCodec` flags (PQ/HLG transfer field, else VP9 Profile 2 / >8-bit AV1, and any DV codec), for full-screen and inline trailers alike. Its order: an adaptive SDR video-only + M4A audio pair (`MergingMediaSource`); otherwise the tallest decodable SDR progressive/muxed stream (`audio = null`, single `MediaSource`); otherwise `null`, which `ResolveTrailerStreamUseCase` treats as a failed candidate and moves to the next TMDB key (up to 3). Nothing is drawn over the picture except the player UI.
- **Window:** `Window.colorMode` stays `COLOR_MODE_DEFAULT`. `COLOR_MODE_HDR` only affects how the app's own UI layer is rendered (Ultra HDR graphics) and would brighten the SDR UI; HDR video in a `SurfaceView` doesn't need it. `ResetHdrWindowOnExit` (PlayerWindowReset.kt) puts `colorMode`, `screenBrightness` (`BRIGHTNESS_OVERRIDE_NONE`) and, on API 35+, the desired HDR headroom back to their defaults when the player leaves composition. It writes only values that differ (pure `windowResetNeeded`).
- **Dynamic range:** `VideoDynamicRange.ofSession(track, decoderInput)` classifies `DOLBY_VISION` (MIME `video/dolby-vision` or `dvhe`/`dvh1`/`dvav`/`dva1`/`dav1` codecs), `HDR10` (PQ, so HDR10+ too), `HLG`, else `SDR`. The source track wins, so DV played as its base layer still reads `DOLBY_VISION`. `SeaStreamsPlayerManager.dynamicRange` (StateFlow) updates from `onTracksChanged` (selected video track) and `AnalyticsListener.onVideoInputFormatChanged`, and resets to `SDR` on `playStream`/`playTrailer`/`stop`. `PlayerViewModel` copies it into `PlayerUiState.dynamicRange`; `PlayerUiState.dimUi = hdrWhiteDimming && dynamicRange.isHdr`.
- **HDR White Dimming:** `PlayerSettings.hdrWhiteDimming` (`p{id}/player_hdr_white_dimming`, default `true`). `Modifier.hdrUiDim(enabled)` = `graphicsLayer(compositingStrategy = Offscreen)` + `drawWithContent { drawContent(); drawRect(Black @ HDR_UI_DIM, blendMode = SrcAtop) }`. `SrcAtop` darkens only the pixels the UI drew (whites → 75%), so transparent areas, and the video behind them, are untouched. `PlayerScreen` applies it to one layer holding the loading overlay, subtitle cue, centre indicator, status pill, HUD and every panel (Streams included); `TransientMessages.hdrDim` (set by `PlayerScreen`, cleared on dispose) dims toasts in `TransientMessageHost`. Draw-only: focus and keys are untouched.
- **Teardown order:** `PlayerViewModel.exit()` sets `PlayerUiState.videoDetached` and calls `SeaStreamsPlayerManager.stop()` (`clearVideoSurface()` → `stop()` → `clearMediaItems()`) before sending `exits`. `PlayerScreen` stops composing `VideoSurface` while `videoDetached`, so the SurfaceView (and its last HDR-tagged frame) is destroyed in the same frame, before `PlaybackHost` removes the player and restores focus. `close()` then `release()`s (`clearVideoSurface()` → `release()`). Every exit path (Back, `CANCEL_LOADING`, `onEnded`, fallback exhausted, trailer failure) goes through `exit()`.
- **Dolby Vision:** `PlayerSettings.dolbyVisionPlayback` (`p{id}/player_dolby_vision_playback`: `AUTO` default / `NATIVE` / `HDR10_BASE_LAYER`) plus the separate `convertDvProfile7ToHdr` toggle. `PlayerEngineConfig` carries both and `displaySupportsDolbyVision` (`DisplayHdrSupport`, read once per session). `DolbyVisionCompatVideoRenderer` runs `DolbyVisionPolicy.decide(profile, baseLayerTransfer, …)` in `supportsFormat` / `getDecoderInfos` / `onInputFormatChanged`: P5 and AVC/AV1 profiles → native; P7 → base layer when the toggle is on or the mode is `HDR10_BASE_LAYER`; P8 → base layer for `HDR10_BASE_LAYER`, or `AUTO` without display DV support, but only with a known PQ/HLG transfer. `BASE_LAYER` rewrites the format to HEVC Main10 (`hvc1`/`hev1`), keeping the container `ColorInfo` (incl. HDR static info); a missing `ColorInfo` is filled in (BT.2020/PQ/limited) for P7 only. `PlayerInfo`'s *Dynamic range* row (`VideoDynamicRange.label`) shows the path (`Dolby Vision 8 → HDR10 base layer`, `Dolby Vision 5 (native)`, …).
- **Cancel during initial load:** `open()` returns before building a player when `exit()` already ran during the settings/client load, so a cancelled session never attaches a surface.

## 8. Stream Fallback & Automatic Stream Failover (PRD §9)
- **Setting:** `PlayerSettings.autoStreamFailover` (`p{id}/player_auto_stream_failover`, default `true`; General Settings → `Playback` → *Automatic stream failover*, with its indented sub-setting *Failover timeout duration* `p{id}/player_fallback_timeout_s` directly beneath, options `PlayerSettings.FALLBACK_TIMEOUT_OPTIONS` = 10/15/20s, default `10s`; `SettingsDataStore.clampFallbackTimeout` snaps any stored or written value to the nearest option, so legacy 1–10s values read as 10s; the row's stepper moves one option and stops at the ends, a click cycles 10→15→20→10). The timeout row is shown only while failover is on; turning failover off keeps the stored timeout. Like every General Settings key it is in `ProfileSettingsKeys.ALL` (legacy migration) and removed by `clearProfile`.
- **Who decides:** `SeaStreamsPlayerManager` only emits `PlayerEvent.Ready` / `PlayerEvent.Failed(error, generation)`. `generation` is bumped by every `playStream` / `playTrailer`, and `PlayerViewModel.onEvent` drops a `Failed` whose generation is no longer current, so an error still queued in the event buffer from a replaced stream can never fail or skip the stream now starting. `PlayerViewModel` feeds them to `StreamFallbackController`, which reads `failover()` (the session's settings snapshot) each time `playIndex` starts a stream. Trailers set `enabled = false` and bypass it entirely.
- **On:** a timer of `fallbackTimeoutSeconds` runs until `Ready`. A timeout or a `Failed` event calls `onAdvance(from, to, reason, detail)` (status `Stream N didn't start/failed (<detail>). Trying stream N+1 of T…`), and at the end of the list `onExhausted(reason, lastDetail)` shows a toast (`None of the streams would play (last: <detail>)`, or `None of the streams started in time` for a timeout) and exits. `current` is cleared on every advance, exhaustion and stop, so duplicate or late errors in a burst report nothing until the next stream starts: one advance per stream, one exhaustion.
- **Failure reasons:** `StreamFailureReason` turns a failure into a brief reason.
  - `fromPreflight` takes `PreflightResult.Skip` messages.
  - `fromPlayback` first walks the `PlaybackException` cause chain for `ArchiveRefusedException`, `UsenetUnplayableException`, `DebridException`, `InvalidResponseCodeException` (`HTTP <code>`), socket timeouts and unknown hosts. It then falls back to the Media3 error code: network, parsing, decoder (`unsupported video|audio codec (<name>)` from `ExoPlaybackException.rendererFormat`), audio output, DRM. Anything else is `playback error`.
  - Secrets: classification runs on the stripped text, and unknown messages are shown only via `sanitize`. It replaces URLs, `key=value` credentials and ≥20-char hex/base64 runs with `[hidden]`, collapses whitespace and caps the text at 60 chars. Signed links, API keys and tokens never reach the status, toasts or logs.
  - `StreamFailureMessages` holds every wording.
  - The same reasons flow through `firstPlayable` (`onSkip(from, to, total, reason)`, `NonePlayable(noneWouldPlay(last))`), `PlayerStreamGate` (`onStopped(index, reason)`, `onExhausted(message)`) and the external-player `prepare` failure path. Each gate runs one cancellable job, so a whole source refused in milliseconds reports each skip once and in order.
- **Off:** no timer is started. `Failed` calls `onStopped(index, detail)` and never advances or exhausts. `PlayerStreamFailure.onStreamStopped` sets `PlayerUiState.streamFailed`, shows the status `Stream N of T couldn't play (<detail>). Automatic failover is off — pick another stream.` and opens the in-player Streams overlay (from an event, not a key, so no trailing `KeyUp` acts). While `streamFailed` the initial-loading key gate lets Select/D-pad open the HUD, there is no Pause badge or rebuffering logo, and `selectStream` on the same index retries it. Any new stream (`onNewStream`) clears `streamFailed`. Back keeps its tiers: overlay → HUD → leave.

## 10. Usenet Sources & NNTP Engine (PRD §12)
Ported from two references:
- **AIOStreams** (`packages/core/src/usenet/`): scheduling, failover ranking, CRC rules, locator, holes and profiles.
- **Nabrio/POV** (`dev.pov.tv.usenet`): Android sockets/TLS, in-buffer yEnc, NZB scanner, RAR readers, DataSource, loopback proxy and warm connections.

**Configuration (Milestone 7, built):**
- **Room v7, app-wide** (no `profileId`, no FK; every profile shares them):
  - `usenet_providers` (PK `id` autoincrement): `name`, `host`, `port`, `tls`, `username`, `passwordCipher`, `maxConnections` (1..100), `pipelineDepth` (1..16), `priority` (0..99), `isBackup`, `enabled`, `sortOrder`. Index on `sortOrder`.
  - `newznab_indexers` (PK `id`): `name`, `baseUrl`, `apiPath`, `apiKeyCipher`, `priority`, `backupOnly`, `enabled`, `sortOrder`. Index on `sortOrder`.
  - Secrets are stored only as `SecretCipher` output; plain text never touches disk.
- **`UsenetSettingsStore`** holds the performance JSON and the header choices and versions, outside the `p{id}/` scope (ProfileSettingsMigrator never copies them).
- **`UsenetPerformance`:**
  - `withProfile(p)` copies the template.
  - `edited(transform)` applies the change and sets `profile = CUSTOM`.
  - `clamped()` bounds every field to the PRD §12 ranges on read and write; an unreadable or old JSON decodes to the defaults (Conservative).
  - Templates are capped for a 512 MB Android TV heap (Google TV Streamer 4K): Conservative 16 / 30 / census 4, Balanced 24 / 36 / 6, High 32 / 48 / 6 (read-ahead / max concurrent downloads / census concurrency). No template uses `0` = auto downloads, which on many connections meant hundreds of ~0.7 MB decodes in flight and the `OutOfMemoryError`s seen in `SegmentBufferPool.acquire` / `YencDecoder.decode` under the old High.
- **`HeaderVersionUpdater`:**
  - `checkIfDue(now)` runs when `now − checkedAt ≥ 24 h`; `updateNow()` always runs.
  - Six GitHub `releases/latest` calls run in parallel on the uncached client with UA `SeaStreams`. A `tag_name` matching `^v?\d+(\.\d+){1,3}$` is stored without the `v`.
  - `checkedAt` is written only when at least one tool answered.
  - `RequestHeaderPresets.headersFor(preset, versions)` builds the header map that M9's Newznab client and NZB grabber send. A missing version falls back to the baked one.

**Engine (Milestone 8, built):**
- **Entry points for Milestone 9:** `UsenetSourcesRepository.enabledEndpoints()` (decrypted `NntpEndpoint`s, undecryptable ones skipped) → `NntpEngine.configure(endpoints, performance.engineSettings())` (also sets the disk-cache cap) → `UsenetFile(nzbFile, engine.cachedSource, SegmentArena(SegmentArena.sizeFor(window)), readAheadSegments, segmentTimeoutMs)`. `NntpEngine.warmUp()` when a stream search starts; `NntpEngine.stat()` for the census. Every timed class takes a `clock: () -> Long` so tests run on virtual time; `testutil/FakeNntpServer` is a real localhost NNTP server.
- **Ownership:** a `DecodedSegment`'s bytes are reachable only via `copyTo`/`writeTo`/`toByteArray`, which hold a reference; the `SegmentArena` owns segments and releases them on eviction, returning buffers to the `SegmentBufferPool`. A copy that loses that race returns `false` and the reader fetches again. Every path that ends up holding a segment nobody owns releases it: `SegmentArena.put` returns the copy it holds and releases a duplicate download; a result that lands after its fetch was cancelled is released (`ProviderSelector.failover(discard)`, `CachedSegmentSource`); the yEnc decoder and disk-cache reader return their buffer when the socket or file fails mid-read. Hashed keys and fingerprints use `core/util/Hashing.sha1Hex`; the cache's background threads come from `core/util/daemonExecutor`.
- **Provider `Test`:** `NntpConnectionTester` (one sign-in + `DATE`, never through a pool) → `ProviderTestResult` Success / BadLogin / ConnectionLimit / Unreachable. TV: the `Test connection` button on each `Usenet providers` row (`SourcesViewModel.testProvider`, toast). Portal: `POST /api/usenet/providers/test` with the form (a blank password on a saved provider uses the stored one; failures answer 400).
- **Sockets:** a plain socket (`tcpNoDelay`, 512 KB receive buffer, dial timeout) wrapped by `SSLSocketFactory.createSocket(plain, host, port, true)` with endpoint identification `HTTPS`.
- **Auth:** greeting 200/201, then `AUTHINFO USER/PASS` (281 accepted without PASS too). No `MODE READER` (reader-only servers take AUTHINFO straight after the greeting). 480/481 are auth failures. A reply *worded* as a connection limit ("too many connections/sessions", "connection limit", "maximum … connections") is a *connection limit*, whatever its code, which drives the AIMD throttle (allowed connections drop to the open count, then +1 every 5 s) and is never an account failure. A bare 482/502 is not: Highwinds (Newshosting, Eweka …) sends 502 for refused logins and blocked accounts, so a 482/502 about the login or account, or any other 482/502 in answer to AUTHINFO, is an auth failure; an unexplained 502 greeting is a refused connection. Errors and the `Test` result quote the server's reply line.
- **Pipelining:** `pipelineDepth` `BODY <id>` commands in flight, answered in strict FIFO. A 4xx fails only that request; a desync or stall drops the connection and re-queues its requests.
- **Scheduling:**
  - A `PrioritySemaphore` of `maxConcurrentDownloads` permits (0 = Σ connections × depth) shares contended permits HIGH:LOW at `streamingPriority` (playback vs. census).
  - The circuit breaker opens after `threshold` consecutive failures and stays open for `cooldown`.
  - Warm connections are opened when a stream search starts, kept alive with `DATE`, and closed after `idleConnectionTtl`.
- **Failover:** primaries (by priority group, healthy first) → backups. A 430/423 moves to the next provider. "Missing" is reported only if a provider actually answered 430. There is a 60 s negative cache.
- **yEnc:** single-pass decode on the receive buffer into a pooled buffer. Checks `pcrc32`, or `crc32` only for single-part posts, the `=ypart` span and `wrong_part`. A CRC failure moves on to the next provider when *Verify article checksums* is on.
- **NZB:** an `indexOf` byte/char scanner (no XML parser, no DTD), message-ID guard (no CR/LF/`<>`/space, ≤ 250 chars), password meta, segment backfill and dedupe, one-file-per-article merge, SHA-1 of the sorted IDs as the NZB key.
- **Locating bytes:** an interpolation-search `SegmentLocator`. The part size locks once a segment proves the grid; RAR middle volumes reuse a sibling's grid.
- **Read-ahead:** the window is `readAheadSegments`, clamped so it uses ≤ `maxMemory/10` bytes, and pins the head and 5 MB tail. `SegmentArena` is an LRU sized `clamp(32 MB, n × 1.5 MB, 64 MB)` and ≤ `maxMemory/10` (≤ 51 MB on a 512 MB heap). In a multi-volume release only the volume being read runs its window (`ReadAheadFocus`, M9): every `UsenetFile` starts with `readAhead` suspended, `JoinedData.onVolumeChange` moves the focus as playback crosses into (or seeks to) another volume, and `suspendReadAhead` → `ReadAheadWindow.idle()` cancels the previous volume's queued downloads (pinned head/tail kept). Header probes and lazy-RAR checks of other volumes fetch only the articles they touch.
- **Buffer pool:** `SegmentBufferPool` keeps at most 16 MB and 16 idle buffers (none over 2 MB); the rest go to the GC. `acquire` drops the idle buffers and retries once on `OutOfMemoryError`. `DecodedSegment` clears its array reference on the final release, so a segment object still held by a finished fetch, a read-ahead slot or a queued disk write never pins its bytes. A session's close and `trimMemory` also `trim()` the engine's pool.
- **Disk cache:** `SegmentDiskCache` stores one file per SHA-1(message-id) and uses background write-through, dropping writes when it falls behind (§3 caps). The free-space terms use the space the cache may occupy (`File.usableSpace` + its own bytes), so the cap stays stable as the cache fills: ≤ 25% of it, and it always leaves ≥ 2 GB free. Files are read with NIO channels, which allow deletion while open, so `Clear cache` never waits for a reader.
- **Interrupts:** futures map `InterruptedException` to `InterruptedIOException`, so Media3 loader cancellation is clean.

**Playback (Milestone 9, built):**
- **Search:** `UsenetStreamSearch` asks every enabled non-backup indexer in parallel and the *Backup only* ones only when none of those returned a release; results rank by priority tier, then indexer order, then the indexer's own order, and the same release (normalised name + size) is kept once from the better tier. Passworded releases (`newznab:attr password`) are kept, since the NZB may carry the password a 7z set needs, but rank after the clean releases of the same priority tier (stable); ones `ReleaseHealthCache` knows broken are dropped. Search is NZB-grab-free: `UsenetStreamSearch` has no `NzbGrabber` and sends only `t=caps` and search queries, so 7z / passworded uploads disguised under clean titles are found at Play (pre-playback resolution below), never by spending grab quota during search. `NewznabQueries.plan` builds `t=movie&imdbid` / `t=tvsearch&imdbid&season&ep` (`cat` 2000 / 5000, `extended=1`, `limit=100`) when the caps say so, then a `q=` fallback that runs only when the id query is unsupported or empty; `ReleaseMatch` checks the year (±1) / `SxxEyy` (`-Ezz`, `1x02`; season packs rejected), strictly for `q=` results. `NewznabClient` caches `t=caps` 14 days (`NewznabCapsCache`), appends the API key only when the request is built, and maps `<error code>` to `NewznabException` (100–104 = account problems). `UsenetHttp` sends the `Search` preset on queries and the `Download` preset on NZB grabs (`NzbGrabber`: *Max NZB size*, must contain `<segment`, *Max concurrent imports* permits, `NzbFileCache`). The stream search starts `UsenetEngineSetup.warmUp()`.
- **Indexer `Test`:** `NewznabClient.test` (fresh `t=caps`) → `IndexerTestResult`. TV: the `Test connection` button on each `Indexers` row (`SourcesViewModel.testIndexer`). Portal: `POST /api/usenet/indexers/test` with the form (a blank key on a saved indexer uses the stored one, `UsenetSourcesRepository.indexerEndpointForDraft`).
- **Stream entries:** results become `StreamSource(addonUrl = "usenet://builtin", addonName = "Usenet", url = "seastreams-nntp://<token>")`. `UsenetStreamRegistry` maps the token to the `UsenetGrab` (indexer + guid, or addon + `nzbUrl` + its `servers`), so API keys and NNTP logins never reach URLs, intents or `last_used_streams`. The token is the first 32 hex chars of SHA-1(identity), so the same release found again has the same URL and LAST USED matches it exactly. `ResolveStreamsUseCase` searches the built-in addon alongside the Stremio addons (20 s timeout) and lists its card last, only while `UsenetStreamSearch.configured()` (≥ 1 usable provider and indexer). Stremio streams with an `nzbUrl` (`StremioResourceParser`) are registered under their own addon; their `servers` (`AddonServers`: `nntp(s)://user:pass@host:port/connections`) get a private `NntpEngine` without the disk cache.
- **Sessions:** `UsenetSessionOpener` (blocking `open`, used by `NntpDataSource` and the proxy): grab → NZB → `NzbParser` → one `UsenetFile` per posted file on a shared `SegmentArena`, behind a `HoleFillingSource` → `ReleaseAssembler` → *Verify file contents* sniff (`ContentSniffer`) → `SessionVerification`. Lasting refusals are `UsenetUnplayableException` / `ArchiveRefusedException` and are remembered as `NotStreamable`. `UsenetSessionRegistry` keeps ≤ 4 sessions (acquire/release refcounts; concurrent first opens share one; past the limit the least recently used idle one closes) and a daemon reaper closes sessions idle for *Stream idle timeout*. `UsenetSession` serialises reads; `fail()` makes later reads throw.
- **Archives:** `ObfuscatedSetResolver` keeps recognisable subject names, else takes the first article's yEnc `name=`, else identifies RAR volumes by signature (ordered by RAR5 volume number / the RAR4 first-volume flag, then NZB order). `MediaSelector` groups plain videos, RAR sets (`.partNN`, `.rar` + `.rNN` with the `.s00–.z99` rollover), `.001` splits, 7z sets (`.7z`, `.7z.001…`) and zip files (duplicate volume indices collapse to the larger copy), ignores par2/nfo/sfv/…, excludes `sample`/`proof` groups under 5% of the largest, and picks the largest; a zip winner, a set without its first volume or a volume gap is refused. `RarArchive` (RAR4 `RarHeaders` with CRC16 checks, RAR5 `Rar5Headers` with CRC32 + vints) picks the largest video entry and refuses encrypted headers, encrypted entries and compressed entries (encrypted sets are refused even with an NZB password). Eager mode parses every volume (first articles fetched in parallel); *Lazy RAR resolution* (3+ volumes) parses the first, second and last and checks each middle volume's header just before its first read, re-resolving eagerly on a mismatch. *Strict archive membership* refuses a volume that doesn't hold the entry (else it is skipped). Middle volumes and splits with the reference's stated size borrow its article grid (`UsenetFile.adoptGrid`), so a seek into them needs no probe. `JoinedData` maps the entry / splits onto the volumes' spans.
- **7z (stored and password-protected):** a 7z set (or a 7z signature inside `.001` splits, or an obfuscated file named `obfuscated-N.7z` by signature) is joined end to end like splits and opened by `SevenZipArchive`: commons-compress (§4) reads the directory over `SevenZipChannel` (a read-only `SeekableByteChannel` on the `JoinedData`) with the NZB password (`Nzb.password`, passed `UsenetSessionOpener` → `ReleaseAssembler.assemble(volumes, password)`; never logged or put in messages). The largest video entry is picked and `SevenZipLayout` reads its folder's pack-stream offset, size, solid skip and coder chain. A Copy entry becomes `JoinedData.slice(...)`: exact volume offsets, no decoding, random access like a stored RAR. An AES + Copy entry (7-Zip always encrypts the contents when a password is set; `-mhe` adds header encryption) becomes `SevenZipAesData`: AES-256-CBC decrypted on demand in 256 KB windows (a seek decrypts from the block holding the position, IV = the previous ciphertext block), key derived once from the password (2^`cyclesPower` SHA-256 rounds hashed in large chunks; power > 20 refused), the decrypted head must sniff as a video container. While commons-compress derives an encrypted header's key, `BufferedSha256` (a ref-counted, scoped JCA provider) batches its tiny digest updates. Refusals (`ArchiveRefusedException`): any other coder (LZMA/LZMA2/BCJ/…: `The 7z archive is compressed`), several pack streams, no password (`password-protected`), a wrong password (header-encrypted: the directory needs a password and won't parse with this one; content-only: the head doesn't sniff), a truncated set, no video, or an unrecognised commons-compress layout. Errors thrown by the volumes themselves (network, missing articles) pass through `SevenZipChannel.sourceFailure` unchanged, so they stay retryable. `AssembledMedia.follow` is the volume-level `JoinedData` the read-ahead focus tracks under a decrypting entry; the session closes the `SevenZipAesData` (zeroing key and window).
- **Damage:** `CensusVerifier` STATs every article of the files being read through `NntpEngine.stat` (LOW priority, failover like BODY: a primary's 430 asks the backups), at most *Census background concurrency* in flight, first articles then a widening stride, for at most *Census max lifetime*; a failed STAT is unknown, never missing. `DamagePolicy.judge`: Strict = any missing article is broken; Tolerant = `HoleFiller.withinLimits` (≤ 4 consecutive per file, ≤ 64, ≤ 2% of all articles) and never a file's first article. `SessionVerification` waits up to *Verify budget* (a broken verdict refuses the open), then keeps going in the background: broken → `ReleaseHealthCache` (6 h) and, within 60 s of opening, `UsenetSession.fail` so failover moves on early. At read time `HoleFillingSource` turns an article no provider has into filler of its exact size under Tolerant within a `HoleBudget`: zeros, or one EBML Void element (`MatroskaHoleRepair`, ID `0xEC` + 8-byte size vint) for Matroska/WebM when *Matroska hole repair* is on.
- **Pre-playback resolution:** `UsenetPreflight.check(stream)` opens the release before any player sees it (`UsenetSessionRegistry.acquire` + `release`, on IO). The NZB grab, `NzbFileCache`, `NzbParser`, `ReleaseAssembler` and the *Verify budget* census all run there, and the session stays open so the player's first read reuses it.
  - A release `ReleaseHealthCache` already holds as `Broken` / `NotStreamable` is skipped without opening.
  - An `ArchiveRefusedException` / `UsenetUnplayableException` is recorded (the opener records refusals; the preflight records an `ArchiveRefusedException` the opener didn't), and the stream becomes `PreflightResult.Skip`.
  - Network `IOException`s also skip but are not remembered.
  - Callers:
    - `PlaybackViewModel.start` → `firstPlayable` (`PlaybackStartGate.kt`): with *Automatic stream failover* on, refused releases are passed over before `PlaybackRequest.Media` exists (built-in player) or before `ExternalStreamUrls.prepare` (external). `PlaybackUiState.loadingStatus` shows `Stream N didn't start (<reason>). Trying stream N+1 of T…` over the loading screen, and `None of the streams would play (last: <reason>)` ends it (a single stream: its sanitized full reason).
    - In the open player, `PlayerViewModel.playIndex` sends Usenet streams through `PlayerStreamGate` (`openThroughGate`; the fallback timer is cancelled while the release opens). This covers fallback advances, Streams-overlay picks and episode switches. Only `onPlay` → `handOff` calls `SeaStreamsPlayerManager.playStream`, so a refused release never prepares ExoPlayer (no `ExoPlayerImplInternal` error, no audio-focus churn).
    - With failover off the gate stops the player and calls `onStreamStopped` (Streams overlay, PRD §9). `PlaybackViewModel` does no skipping then, so the player is opened at the chosen stream and its gate stops there.
- **ExoPlayer:** `NntpDataSource` (length always known; every open shares the token's session, so seeks reuse its arena and read-ahead) is picked by `PlaybackDataSources.mediaSourceFactory` from the URI scheme in `SeaStreamsPlayerManager.playStream`; `UsenetLoadErrorPolicy` returns no retry for lasting failures (refusals, all-provider 430s, bad login, no providers, layout errors) so `StreamFallbackController` fails over at once.

## 11. Stream Processing Pipeline (PRD §13, Milestone 10)
- **Where it runs:** `ProcessStreamsUseCase` (domain/streams, on `@DefaultDispatcher`) runs inside `ResolveStreamsUseCase` after collection and before `topStream`, for `StreamQuery.profileId` only: parse (`StreamFacts` + `ReleaseParser`, AIOStreams `PARSE_REGEX` tables) → `StreamFilterEngine` → preferred regex / keyword annotation → `StreamDeduplicator` → `StreamSorter` → `ResultLimiter` → `StreamFormatter`. With default settings, or with every stage switched off by its master toggle, the list is returned untouched (no parsing). Auto-play, failover order, LAST USED and the Addons column counts all read `StreamResolution.streams`, so they follow the processed list.
- **Parsing:** AIOStreams parses titles with `parse-torrent-title`, which isn't approved, so `ReleaseParser` covers title / year / S·E / season packs / anime ` - 12` / `-GROUP` or `[Group]` / editions / network with small patterns, then cuts the title out (titles over 4 chars) before testing the tag tables, as AIOStreams does. Java can't look behind by `.*`, so `(?<!remux.*)` became `.{0,255}`. Stream facts: `StreamHints` (Stremio `behaviorHints.filename` / `videoSize`; Newznab title / size / publish time / indexer) win over text; sizes in text are 1024-based; seeders `👤/👥 N`; age `📅 Nd` or `N days old`; indexer after `🌐 ⚙️ 🔗 🔎 🔍 ☁️`; languages = release tags then flag emojis; bitrate = size ÷ TMDB runtime (`StreamQuery.runtimeMinutes`, episode runtime for shows); type = Usenet / Live (`.m3u8`) / Debrid (`[RD+]`…) / HTTP. Anime = TMDB Animation genre + `original_language` `ja` (`TitleDetails.isAnime`).
- **Filter semantics:** *Included* (any list, regex, keyword, seeder or age range) keeps a stream regardless of every other filter. A missing attribute is `Unknown`. Multi-valued tags: excluded when any tag is excluded, required when any tag matches; synthesised `HDR+DV` / `DV Only` / `HDR Only` visual tags are filter/sort-only. Languages / subtitles: excluded only when every language is excluded. Regex: `/pattern/flags` with `n` = negate (matches streams the pattern matches none of: file name, release group, indexer); invalid patterns are ignored (the portal refuses to save them). Seeders, age, size and bitrate only judge streams that state the value; size/bitrate use the stream resolution's range, else the global one, movie range for movies, series range for series and anime.
- **Dedup / sort / limits:** dedup keys file name (normalised) / URL / smart (tags + ~10% size bucket), per addon or across addons, first stream wins and a dropped duplicate's keys still count. Sort keys follow AIOStreams (`multiplier × value`, stable): preferred-list criteria rank by position in the attribute's *Preferred* list (unlisted last); a non-empty Movies/Series/Anime list replaces Global. Limits (total / per resolution / per quality / per addon) apply after sorting; the TV steppers cycle Off → 1, 2, 3, 5, 10, 20, 30, 40, 50.
- **Formatter:** AIOStreams template engine port (`format/`): `::` modifiers (conditionals incl. `=2160p`, `>0`, `~`, `exists`; `join`, `replace`, `rbytes`, `sbytes`, `time`, `truncate`, `default`, …), `["true"||"false"||"absent"]` checks, `and`/`or` comparators, `{? … ?}` groups, `{tools.newLine}` / `{tools.removeLine}`, blank lines dropped; JS number printing and rounding. Unknown fields render `{invalid_expression(…)}`. Presets are AIOStreams' definitions except that `{addon.name}` becomes `PredefinedFormatters.SOURCE` (`{stream.indexer}` when the addon is the built-in `Usenet` and an indexer is known, else the addon name) and Minimalistic GDrive gains `{?🔍 {stream.indexer}?}`; `stream.indexer` comes from `StreamFacts` (Newznab `StreamHints.indexer` = the indexer's name, or the text after an indexer emoji in a Stremio description). Custom defaults to the `aio-formatter.png` template (golden test), whose last line is `| {indexer}` for Usenet streams and `| Addon · Indexer` when another addon states an indexer. Card lines are trimmed at the end (name both ends).
- **Usenet in the addon order:** `BuiltInAddons.USENET_URL` (`usenet://builtin`) is an `AddonEntity` row per profile (protected from removal, `canDisable` = true, minimal manifest with `resources:["stream"]`, skipped by catalogs and Stremio queries because it isn't `http`). `UsenetAddonState.configured` (≥ 1 enabled provider and indexer, read from the DAOs) decides whether it is listed (`BuiltInAddons.isListed`: `AddonRepository.observeAddons` for the portal, `SettingsViewModel` for Manage addons / Preferred auto-play addon via `streamAddons`). `ResolveStreamsUseCase` (`UsenetSlot`) inserts the Usenet results and card at the entry's place among the enabled addons (the bottom when the profile has no entry yet), passes that order to `StreamContext.addonOrder` (the `Addon` sort criterion), and skips the Usenet search when the profile disabled the entry; `AddonStreamGroups` and `topStream` follow from the ordered `streamAddons` / streams. **M12 (built):** `UsenetSlot` became `BuiltInSlot(url, name, disabled)` (`domain/usecase/BuiltInSlot.kt`) for both `usenet://builtin` and `debrid://builtin`; `streamOrder(enabled, answered)` = the enabled rows' URLs plus every built-in source that answered without a row yet (Usenet, then Debrid), and results, cards and `StreamContext.addonOrder` all follow it. `PredefinedFormatters.SOURCE` is `{addon.name::=Usenet::or::addon.name::=Debrid::and::stream.indexer::exists[…]}` (conditions fold left to right), so Debrid streams show the service name (`StreamHints.indexer`) as Usenet ones show the indexer; the Custom default's last line does the same. Debrid `StreamFacts.type` = Debrid from the addon URL / `seastreams-debrid://` (not only from `[RD+]`-style text), and `{stream.library}` is true for them (Prism's `📌 Library`).
- **Data model:** `StreamSource` gains `hints`, `parsed` and `display`. The raw `label`/`description` are kept unchanged for the LAST USED matcher, and `StreamResultCard` (`streamCardText`) renders `display` when present.
- **Master toggles:** `StreamProcessingSettings.filteringEnabled` / `sortingEnabled` / `formattingEnabled` (default `true`). Each is stored inside its own key's JSON object as `"enabled": false` (omitted while `true`; a key holding only `{"enabled":false}` is kept, and is removed again when re-enabled with default rules). The rule classes don't declare the field, so they decode it as an unknown key (`ignoreUnknownKeys`) and pre-toggle JSON reads as `ON`. `StreamProcessingStore.updateFilters/updateSort/updateFormatter(profileId, enabled = null, transform)` change rules and/or the flag in one edit (`null` keeps the stored flag); `setFilteringEnabled/…` wrap them. `StreamProcessingSettings.effective()` replaces each bypassed stage's rules with their defaults (filtering `OFF` → `StreamFilters()`, which also empties the *Preferred* lists the sorter and formatter read). `ProcessStreamsUseCase` / `StreamPipeline` return the list untouched when `effective().isDefault` (no `StreamFacts`/`ReleaseParser`), and otherwise run filter + preferred annotation + dedup + limits only for non-default filters, `StreamSorter` only for non-empty sort lists and `StreamFormatter` only for a formatter other than `ORIGINAL` (else `display` stays `null`). TV: `streamProcessingItems` lists each toggle (`RowTrailing.Toggle`, `StreamProcessingActions` callbacks) with its panel row as an indented sub-setting beneath it while `ON`; `settingsEntryOrdinals` follows the list, so the wrap edge follows visibility, and `streamReturnRow` gives `Back` the toggle as a fallback when the panel's row was hidden meanwhile. Portal: `StreamPortalState` carries the three flags; `StreamFiltersRequest` / `StreamSortRequest` / `StreamFormatterRequest` take nullable rules plus a nullable flag (`null` = unchanged, both `null` → 400), so a checkbox posts only its flag.
- **Settings:** per-profile JSON ScopedKeys `stream_filters`, `stream_sort`, `stream_formatter` (`StreamProcessingStore`). TV: `UI` (bottom, below the trailer rows; `streamProcessingItems` in SettingsItems.kt) → `Stream filters` (`SectionedRowsPanel`: attribute groups → Required/Excluded/Included/Preferred → `MultiChoicePanel`, ordered with Move up/down for Preferred; portal-typed values shown read-only; result-limit steppers; deduplicator), `Stream sorting` (list stepper + criteria with toggle / Move up / Move down / direction), `Stream formatter` (radio list + live preview of the focused formatter). `Back` walks `SettingsPanel.parent()` (values → group → filters → the `UI` list) and each parent reopens on the row it was left from. Each match → `StreamSource(addonUrl = "debrid://builtin", addonName = "Debrid", url = "seastreams-debrid://<token>", label = "Real-Debrid · 1080p", description = "<file>\n<size> · <service>", hints = StreamHints(filename, size, indexer = service name))`.
- **`DebridStreamRegistry`:** token = first 32 hex chars of SHA-1(`kind` + item id + file id) → `DebridFileRef(providerId, kind, itemId, fileId, restrictedLink?, name)` (LRU 2,000; `clear()` on Clear). Stable across searches, so LAST USED matches exactly; no key, token or temporary link ever enters a URL, intent or `last_used_streams`. An unknown token (e.g. LAST USED after a restart) is re-registered by the next search of that title before playback.
- **`DebridLinkResolver`:** `resolve(token)` → `DebridSwitchedOffException` while `Enable Debrid` is off, not-found when the token or its (enabled) account is gone; else the client's `resolve` through the refresher (a revoked key marks *Sign-in needed*), cached 20 min per token and credential generation (LRU 256). A not-found answer also drops that provider's cached library. `resolveBlocking` (loader thread) turns every refusal into an `IOException`; `clear()` on Clear.
- **Addon order:** `BuiltInAddons.DEBRID_URL` (`debrid://builtin`): protected, `canDisable` = true, minimal manifest `resources:["stream"]`, skipped by catalogs and Stremio queries (not `http`). `DebridAddonState.listed` drives `BuiltInAddons.isListed` (Manage addons, Preferred auto-play addon via `streamAddons`, portal via `observeAddons`); `BuiltInAddonGuard.keepDebridEntries` → `AddonRepository.ensureDebrid` adds it at the bottom of every profile while listed (started in `SeaStreamsApp`). `ResolveStreamsUseCase` `BuiltInSlot` (§11) places it and skips the search for a profile that disabled the entry.
- **Pipeline:** `ProcessStreamsUseCase` runs on Debrid streams unchanged (§11). `StreamFacts` takes filename / size / indexer from the hints; type = Debrid.
- **Pre-playback resolution:** `player/StreamPreflight` (`handles(url)` = Usenet or Debrid) dispatches to `UsenetPreflight` or `DebridPreflight`; `PlaybackStartGate.firstPlayable`, `PlayerStreamGate` (and `PlayerViewModel.playIndex` / `PlaybackViewModel.start` via `handles`) take it. `DebridPreflight.check` resolves the link: any `DebridException` (deleted file, revoked key, refused or non-HTTPS link, switched off) or `IOException` → `PreflightResult.Skip` (silent skip + `Stream N didn't start…` status; failover off → Streams overlay). Nothing is remembered beyond the dropped library cache.
- **ExoPlayer / external players:** `PlaybackDataSources` wraps the HTTP factory (parallel range reader) in a `ResolvingDataSource` for `seastreams-debrid://`, swapping the token for its cached HTTPS link on every open (a refusal fails the load, so `StreamFallbackController` moves on). `ExternalStreamUrls.prepare` hands external players the resolved HTTPS URL directly (no loopback proxy, no foreground service; a refusal is an `IOException`, so failover moves on). LAST USED records the `seastreams-debrid://` URL.
- **Age enforcement:** unchanged; Debrid results are only fetched for titles that already passed the profile's age filter upstream (`ResolveStreamsUseCase` is only reached from age-filtered Details / Continue Watching targets).
