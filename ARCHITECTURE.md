## 2. Launcher Resources (App Icon & TV Banner)
Generated from `docs/ui-references/tv_icon.png` (512x512) and `docs/ui-references/tv_banner.png` (1280x720) by `tools/launcher-assets/Generate-LauncherAssets.ps1` (PowerShell + built-in .NET `System.Drawing`, no Gradle dependency). Re-run it whenever either reference changes; never hand-edit the generated PNGs.

- `AndroidManifest.xml`: `<application>` sets `android:enableOnBackInvokedCallback="false"` (targetSdk 37 would otherwise enable predictive back on Android 16+, where `ViewRootImpl` routes `KEYCODE_BACK` to `OnBackInvokedCallback` before the Activity/Compose see the key, breaking `MainActivity`'s long-press gate and the player's `onPreviewKeyEvent` Back handling; TV remotes have no back gesture), and sets `android:icon="@mipmap/ic_launcher"`, `android:roundIcon="@mipmap/ic_launcher_round"`, `android:banner="@drawable/tv_banner"`; the `LEANBACK_LAUNCHER` `MainActivity` repeats `android:banner` (launchers read either `ActivityInfo.banner` or `ApplicationInfo.banner`) and inherits the icon.
- `AndroidManifest.xml` also sets `android:networkSecurityConfig="@xml/network_security_config"`. `res/xml/network_security_config.xml` has one `<base-config cleartextTrafficPermitted="true">` that trusts only `system` CAs (user-installed CAs stay untrusted). Cleartext is permitted globally rather than per domain because:
  - targetSdk 28+ blocks cleartext by default. OkHttp then fails with `UnknownServiceException: CLEARTEXT … not permitted`, which the addon installer reports as "Couldn't reach the addon server".
  - Self-hosted and LAN Stremio addons are often plain `http://` on IP literals, and `<domain-config>` matches host names only, not IP ranges.
  - The stream and subtitle URLs that addons return can point at any HTTP host.

  The policy covers every outbound client: the shared `OkHttpClient` (and the Ktor `HttpClient` on top of it) used for addon JSON, external subtitles, `ParallelRangeDataSource`/`OkHttpDataSource` playback and trailers. `android:usesCleartextTraffic` is deliberately left out because API 24+ ignores it when a network security config is present (minSdk 26). `NetworkSecurityConfigTest` guards both files.
- The Android 12+ system splash never shows the launcher icon: `values-v31/themes.xml` pins `windowSplashScreenAnimatedIcon` to `@android:color/transparent`.

## 3. Storage Bounds & Cache Management
SeaStreams never grows device storage without bound. Everything it caches lives in `context.cacheDir` under fixed LRU caps, so the worst case is ~250 MB regardless of how much free space the TV has:

| Cache | Location | Cap | Owner |
|---|---|---|---|
| HTTP (TMDB / MDBList / addon JSON, 6–12h TTLs via `CacheTtlInterceptor`) | `cacheDir/http_cache` | `100 MB` LRU (`NetworkModule.HTTP_CACHE_SIZE_BYTES`) | OkHttp `Cache` |
| Images (posters, backdrops, logos) | `cacheDir/image_cache` | `150 MB` LRU (`IMAGE_DISK_CACHE_BYTES`), never a percentage of free disk | Coil 3 `DiskCache` (`ImageLoaderSetup.kt`) |
| Decoded bitmaps | RAM | 25% of the app's memory class (`IMAGE_MEMORY_CACHE_PERCENT`) | Coil 3 `MemoryCache` |

- **Playback is memory-only:** ExoPlayer (`SeaStreamsPlayerManager`), `ParallelRangeDataSource`/`ParallelRangeReader`, inline trailers (`InlineTrailerPlayerManager`) and NewPipe (`OkHttpDownloader`) all use `OkHttpClient.withoutDiskCache()` (`UncachedHttpClient.kt`) and buffer in RAM via `LoadControl` / the read-ahead ring. There is no Media3 `SimpleCache` / `CacheDataSource`, and no stream bytes are written to disk.
- **Coil keeps its own fetcher client**, so images are cached once (in `image_cache`), not again in the HTTP cache. Both Coil caches are created lazily on Coil's dispatchers, so building the singleton never does disk I/O on the main thread.
- **Startup orphan sweep:** `SeaStreamsApp` calls `CacheManager.sweepOrphans()` in its `ApplicationScope` launch: top-level `cacheDir` entries other than `http_cache`/`image_cache` that are older than 1 hour are deleted (newer ones are left in case a library is mid-write).
- **Clear Cache (General Settings → `STORAGE`):** `CacheManager.clearAll()` clears Coil's memory + disk caches and `Cache.evictAll()`s OkHttp through their own APIs (their live journals stay valid), then deletes every other `cacheDir` entry. `totalSizeBytes()` sums every file under `cacheDir`. All work runs on the injected `@IoDispatcher` (`Context.getCacheDir()` included, since it may create the folder); the OkHttp `Cache` is a `dagger.Lazy` resolved there too.

## 5. Audio Output Pipeline
- **Renderers** (`PlayerEngineFactory` + `AudioRendererPolicy`): `EXTENSION_RENDERER_MODE_ON`. `MediaCodecAudioRenderer` comes first, then NextLib's `FfmpegAudioRenderer` is appended (Media3's reflection only looks for `androidx.media3.decoder.ffmpeg`, so it's added explicitly). `DefaultTrackSelector` keeps the first renderer that handles a track:
  - Passthrough **on** + sink takes the codec → bitstreamed untouched.
  - Otherwise a hardware decoder (MediaCodec) when the device has one.
  - Otherwise FFmpeg decodes to PCM, so playback never fails or goes silent.
  - A missing native library (`LinkageError`) leaves only the MediaCodec renderers.
- **Sink:** one context-aware `DefaultAudioSink` (16-bit output: FFmpeg's s16 conversion saturates, never wraps) wrapped in `PassthroughGateSink`. While passthrough is off the gate reports every non-PCM format unsupported, so the renderers decode to PCM. This replaces the earlier context-less PCM-only builder (`Builder(context)` ignores `setAudioCapabilities`).
- **Passthrough during playback:** `SeaStreamsPlayerManager.setPassthrough` flips the gate, then `AudioRendererReset` disables `TRACK_TYPE_AUDIO`, waits for `onTracksChanged` to show no audio selected (500 ms fallback) and re-enables it. The renderer then re-decides bitstream vs decode. Both changes can't be sent at once (ExoPlayer would merge them), and the video keeps playing with a brief audio gap.
- **Effects switch passthrough off:** `engagesDsp(before, after)` is true when a change turns Dialogue Boost to a non-Off level, Night Mode on, or Audio Delay to a new non-zero value. `SettingsDataStore.updateAudio` applies `AudioSettings.withPassthroughAutoOff` (repository layer, per profile). In the player, `SessionAudio.withPassthroughAutoOff` plus `setPassthrough` do the same for the session only. Only the engaging change turns it off, so the user can switch passthrough back on (Settings row or the Audio overlay's session toggle) and it stays on.
- **Processor chain** (PCM only; `DefaultAudioSink` bypasses processors for bitstream): `SpeechActivityTap` → `SafeDownmixProcessor` (only when `AudioCapabilities.maxChannelCount ≤ 2`) → `DialogueNightAudioProcessor`. The tap is first so Audio Delay can't skew its timing; the downmix is clip-safe by construction, and the DSP soft limiter still guards boosted peaks.
- **PCM or bitstream:** `SeaStreamsPlayerManager.pcmOutput` (from `AnalyticsListener.onAudioTrackInitialized`, encoding is linear PCM) drives `PlayerUiState.dspAvailable`. The Audio overlay always shows the effect rows; its session passthrough row says whether the current track is bitstreamed (effects pending) or PCM.

## 6. External Subtitle Auto-Sync
Per-profile setting `SubtitleSettings.autoSyncExternal` (`p{id}/subs_auto_sync`, default `true`; General Settings → `SUBTITLES` → last row *Auto-sync external subtitles*). When it's on and an external (addon) track becomes active, `SubtitleAutoSync` runs on the session scope (analysis on `Dispatchers.Default`) without pausing, re-preparing or seeking:

```text
external cues ─▶ ActivityGrid.fromCues (100 ms cells, ±30 s margin) ──┐
                                                                      ├─▶ OffsetCorrelator.estimate (lags −300..+300 = ±30.0 s, 0.1 s)
reference ─┬─ embedded same-language track (fast path)                │     └─▶ gate (EARLY/FULL) ─▶ subtitleOffsetMs ─▶ refreshCue()
           │    ReferenceCueCollector ← onCues(CueGroup.presentationTimeUs, playhead)     onStatus ─▶ subtitleSyncStatus
           └─ audio VAD fallback: SpeechActivityTap → SpeechEnergyLog → ActivityGrid.fromSpeech
```

- **Fast path:** `ReferenceTrackPicker` picks an embedded track whose ISO 639 language matches (`en`/`eng`/`en-US`, 639-2/B aliases). Partial tracks are never used: labels containing forced, signs, songs, foreign or commentary (Matroska often names them without role/forced flags). If only partial tracks match, auto-sync goes straight to audio. `SeaStreamsPlayerManager.setReferenceTrack` enables it in the background. Its cues are never drawn (the overlay ignores embedded cues while an external track is active), and the HUD/Info read the session's chosen track, never ExoPlayer's text selection. Media3 delivers its cues through `Player.Listener.onCues` while the external track is active: `TextRenderer` stamps each `CueGroup` with `rendererPosition − streamOffset`, the period position. A cue counts as shown when it has text **or a bitmap** (`hasVisibleCue`): Blu-ray PGS cues carry no text, and counting text only once left the reference with zero cues while its span kept growing ("96 s heard", never locking). Events more than 2 s from `player.currentPosition` are dropped as leftovers from before a seek, and `onPositionDiscontinuity` (seek) closes the observed span. Scanned every 5 s; the first gated result locks. The embedded reference is correlated on **cue starts** (`ActivityGrid.fromCueStarts`: ±0.2 s pulses on both sides), not on coverage. An addon file and the disc's track differ in display durations, line merges and SDH lines; in tests that pulled an overlap correlation from the true +5.0 s to +4.5 s, while start times agree. It hands over to audio when the reference has fewer than 5 cues after 20 s (signs-only, silent or bitmap-less tracks), or hasn't locked after 30 s. The audio tap runs from the start, so audio can lock on its first passes after a handover.
- **VAD fallback:** the tap logs voice-band energy per media-time cell. A cell counts as speech when its energy is ≥ the 20th-percentile noise floor + 9 dB and its voice share is ≥ 0.3, plus a hangover cell (audio timing therefore resolves to ±0.1 s). The window is the last 5 min before the most recently logged cell, so it follows the playhead after a seek back. Scanned every 5 s for up to 15 min; a lock needs **two consecutive** gated results agreeing within ±0.2 s.
- **Confidence gate, two tiers** (otherwise the offset stays where it is, `0.0s` by default). The cue count is the external cues whose midpoint, at the found offset, lands on a covered reference cell. Onset agreement is the share of those cues starting within ±0.3 s of a reference onset (an active cell after two inactive ones).

  | | EARLY (fast lock) | FULL (confirm/refine) |
  |---|---|---|
  | Covered reference | ≥ 15 s (150 cells) | ≥ 60 s (600 cells) |
  | Cues | ≥ 5 | ≥ 12 |
  | Peak Pearson (embedded / audio) | ≥ 0.45 / 0.5 | ≥ 0.35 / 0.35 |
  | Peak ÷ best outside main lobe | ≥ 1.5 | ≥ 1.5 |
  | z-score | ≥ 3.5 | ≥ 6 |
  | Onset agreement | ≥ 0.8 | ≥ 0.5 |

  Both tiers reject a best lag on the ±30 s edge. Calibration on synthetic data: with 2–4 lines (15–20 s) another title's dialogue can correlate almost as well as the true match, so EARLY relies on cue starts landing on speech/cue onsets. FULL also needs half of them, because long shared silence (credits, quiet stretches) inflates Pearson on its own. Music, noise, periodic and unrelated dialogue never pass either tier in the tests. Conversation-paced dialogue (a line every ~2.8 s) locks after a median of 20 s.
- **Onset snap (`OnsetRefiner`):** every coarse lag (100 ms cells) is refined before gating. External cue starts are matched to reference onsets: embedded cue start times, or audio speech onsets (an active cell after two inactive ones; the hangover only lengthens ends). The search runs in 50 ms steps within ±1.5 s with a Gaussian score (σ 120 ms). The matched starts' mean signed error then gives a continuous estimate, rounded to 0.1 s; it applies only when ≥ 60 % of cues land within ±150 ms. Cue count and onset agreement are judged at the refined offset; peak, ratio and z stay the coarse ones. Lingering display time can bias the coarse lag by 0.3–0.8 s, and in tests the snap brings embedded and audio locks onto the exact offset.
- **Audio correlated two ways:** speech onsets vs cue-start pulses (immune to display durations) and speech activity vs cue coverage. Either may lock, both through the full gate; a test runs 20 unrelated soundtracks × 5 window sizes through the refinement path and none locks.
- **Refine:** an EARLY lock is applied at once (status `Locked(refining)`), then re-analysed every 20 s for up to 5 min until a FULL result confirms it (audio: two agreeing). A different FULL value is re-applied.
- **Drift tracking:** after the final lock (`Locked(tracking)`), the last 2 min (embedded spans/intervals, or 1,200 audio cells) are re-analysed every 60 s. Two consecutive FULL results agreeing within ±0.2 s that differ from the applied offset by 0.1–1.5 s re-centre it, so a 23.976-vs-24 fps file stays in sync; larger jumps are ignored. The reference track and tap stay on until a stop (manual nudge, track change, session end).
- **Status** (`AutoSyncStatus`, via `onStatus`): `Scanning(source, heardSeconds, cues, bestOffsetMs, bestPeak, onsetPercent, embeddedCues)` → `Locked(source, refining)` → `Locked`, or `NoMatch`. A manual nudge sets `Manual`; the setting off or no external track is `Off`. The HUD caption under the sync value reads `Syncing…` / `Auto` / none; the Info row reads e.g. `Syncing… · embedded (0 cues), 20 s`, `Syncing… · audio (18 cues, best +5.1s @ 0.42, 60% onsets), 25 s · embedded gave 2 cues` (the best candidate is shown even below the gate) or `+2.3s · Auto (embedded subtitles) · refining`.
- **Applying:** offsets under 0.1 s apply as `0.0s`. The value is snapped to 0.1 s and clamped to ±60 s, then `PlayerSubtitles.textAt` looks cues up at `position + offset` µs (each cue's start/end shifted) before `CleanSdhTextRenderer`. The current cue is refreshed immediately.
- **Stops** on a manual `−`/`+` nudge (which then wins for the rest of that track), a track change, the setting being off, or session end. Stopping turns the reference track and the tap off synchronously.
- **New stream** of the same title (fallback/switch): an auto offset is dropped and re-detected once the new stream's tracks are known; a manual offset is kept.

## 7. Video Output & HDR (PRD §10)
- **Surface:** `PlayerScreen.VideoSurface` is a plain `SurfaceView` bound with `setVideoSurfaceView`. It is the hardware-overlay path, so HDR static/dynamic metadata and Dolby Vision reach HWC/HDMI untouched. `TextureView` (GPU-composited, no HDR passthrough) is used only by inline catalog previews, which are SDR-only: `TrailerStreamSelector` (ResolveTrailerStreamUseCase.kt) skips every candidate `isHdrVideoCodec` flags (PQ/HLG transfer field, else VP9 Profile 2 / >8-bit AV1, and any DV codec), for full-screen and inline trailers alike. Nothing is drawn over the picture except the player UI.
- **Window:** `Window.colorMode` stays `COLOR_MODE_DEFAULT`. `COLOR_MODE_HDR` only affects how the app's own UI layer is rendered (Ultra HDR graphics) and would brighten the SDR UI; HDR video in a `SurfaceView` doesn't need it. `ResetHdrWindowOnExit` (PlayerWindowReset.kt) puts `colorMode`, `screenBrightness` (`BRIGHTNESS_OVERRIDE_NONE`) and, on API 35+, the desired HDR headroom back to their defaults when the player leaves composition. It writes only values that differ (pure `windowResetNeeded`).
- **Dynamic range:** `VideoDynamicRange.ofSession(track, decoderInput)` classifies `DOLBY_VISION` (MIME `video/dolby-vision` or `dvhe`/`dvh1`/`dvav`/`dva1`/`dav1` codecs), `HDR10` (PQ, so HDR10+ too), `HLG`, else `SDR`. The source track wins, so DV played as its base layer still reads `DOLBY_VISION`. `SeaStreamsPlayerManager.dynamicRange` (StateFlow) updates from `onTracksChanged` (selected video track) and `AnalyticsListener.onVideoInputFormatChanged`, and resets to `SDR` on `playStream`/`playTrailer`/`stop`. `PlayerViewModel` copies it into `PlayerUiState.dynamicRange`; `PlayerUiState.dimUi = hdrWhiteDimming && dynamicRange.isHdr`.
- **HDR White Dimming:** `Modifier.hdrUiDim(enabled)` = `graphicsLayer(compositingStrategy = Offscreen)` + `drawWithContent { drawContent(); drawRect(Black @ HDR_UI_DIM, blendMode = SrcAtop) }`. `SrcAtop` darkens only the pixels the UI drew (whites → 75%), so transparent areas, and the video behind them, are untouched. `PlayerScreen` applies it to one layer holding the loading overlay, subtitle cue, centre indicator, status pill, HUD and every panel (Streams included); `TransientMessages.hdrDim` (set by `PlayerScreen`, cleared on dispose) dims toasts in `TransientMessageHost`. Draw-only: focus and keys are untouched.
- **Teardown order:** `PlayerViewModel.exit()` sets `PlayerUiState.videoDetached` and calls `SeaStreamsPlayerManager.stop()` (`clearVideoSurface()` → `stop()` → `clearMediaItems()`) before sending `exits`. `PlayerScreen` stops composing `VideoSurface` while `videoDetached`, so the SurfaceView (and its last HDR-tagged frame) is destroyed in the same frame, before `PlaybackHost` removes the player and restores focus. `close()` then `release()`s (`clearVideoSurface()` → `release()`). Every exit path (Back, `CANCEL_LOADING`, `onEnded`, fallback exhausted, trailer failure) goes through `exit()`.
- **Dolby Vision:** `PlayerSettings.dolbyVisionPlayback` (`p{id}/player_dolby_vision_playback`: `AUTO` default / `NATIVE` / `HDR10_BASE_LAYER`) plus the separate `convertDvProfile7ToHdr` toggle. `PlayerEngineConfig` carries both and `displaySupportsDolbyVision` (`DisplayHdrSupport`, read once per session). `DolbyVisionCompatVideoRenderer` runs `DolbyVisionPolicy.decide(profile, baseLayerTransfer, …)` in `supportsFormat` / `getDecoderInfos` / `onInputFormatChanged`: P5 and AVC/AV1 profiles → native; P7 → base layer when the toggle is on or the mode is `HDR10_BASE_LAYER`; P8 → base layer for `HDR10_BASE_LAYER`, or `AUTO` without display DV support, but only with a known PQ/HLG transfer. `BASE_LAYER` rewrites the format to HEVC Main10 (`hvc1`/`hev1`), keeping the container `ColorInfo` (incl. HDR static info); a missing `ColorInfo` is filled in (BT.2020/PQ/limited) for P7 only. `PlayerInfo`'s *Dynamic range* row (`VideoDynamicRange.label`) shows the path (`Dolby Vision 8 → HDR10 base layer`, `Dolby Vision 5 (native)`, …).
- **Cancel during initial load:** `open()` returns before building a player when `exit()` already ran during the settings/client load, so a cancelled session never attaches a surface.

## 8. Stream Fallback & Automatic Stream Failover (PRD §9)
- **Setting:** `PlayerSettings.autoStreamFailover` (`p{id}/player_auto_stream_failover`, default `true`; General Settings → `PLAYBACK` → *Automatic stream failover*, directly above *Stream fallback timeout* `p{id}/player_fallback_timeout_s`). The timeout row is shown only while failover is on; turning failover off keeps the stored timeout. Like every General Settings key it is in `ProfileSettingsKeys.ALL` (legacy migration) and removed by `clearProfile`.
- **Who decides:** `SeaStreamsPlayerManager` only emits `PlayerEvent.Ready` / `PlayerEvent.Failed`. `PlayerViewModel` feeds them to `StreamFallbackController`, which reads `failover()` (the session's settings snapshot) each time `playIndex` starts a stream. Trailers set `enabled = false` and bypass it entirely.
- **On:** a timer of `fallbackTimeoutSeconds` runs until `Ready`. A timeout or a `Failed` event calls `onAdvance(from, to)` (status `Stream N didn't start/failed. Trying stream N+1 of T…`), and at the end of the list `onExhausted` shows a toast and exits.
- **Off:** no timer is started. `Failed` calls `onStopped(index)` and never advances or exhausts. `PlayerStreamFailure.onStreamStopped` sets `PlayerUiState.streamFailed`, shows the status `Stream N of T couldn't play. Automatic failover is off — pick another stream.` and opens the in-player Streams overlay (from an event, not a key, so no trailing `KeyUp` acts). While `streamFailed` the initial-loading key gate lets Select/D-pad open the HUD, there is no Pause badge or rebuffering logo, and `selectStream` on the same index retries it. Any new stream (`onNewStream`) clears `streamFailed`. Back keeps its tiers: overlay → HUD → leave.
