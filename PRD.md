# PRD.md — SeaStreams Product Requirements Document

## 1. Visual Design System (Derived from `docs/ui-references/`)
- **Theme:** Deep dark theme (`#000000` default background, `#161A23` surface cards, crisp white `#FFFFFF` primary text, `#A0A8B8` secondary text, `#E5E9F0` high-contrast pill focus states). Selectable background theme swatches in Settings: `#000000` Black (default), `#171535` Midnight indigo, `#351529` Plum, `#351515` Oxblood, `#153535` Deep teal, `#826098` Muted purple, `#0E1621` Midnight slate, and `#17212B` Steel blue.
- **Top Navigation Bar (`home-hero.jpg`, `home-catalogs.jpg`):**
  - **Top-Left:** Active profile circular avatar + live system clock in 12-hour `h:mm a` format (e.g. `12:15 AM`, `Locale.US`), never 24-hour time. All user-facing clock times across the app use this 12-hour format.
  - **Top-Right:** Rounded translucent pill container holding: Search (magnifying glass icon), `Home`, `Movies`, `TV Shows`, `Library`, and Settings (gear icon). *(Note: When an age-restricted Kids profile is active, `Movies` and `TV Shows` tabs are hidden).*
  - **Back Button Navigation:** Pressing Remote `Back` from content on any top-level screen (`Home`, `Movies`, `TV Shows`, `Library`) moves D-pad focus directly to the Top Navigation Bar onto **that screen's own pill** (`Home` on Home, `Movies` on Movies, `TV Shows` on TV Shows, `Library` on Library) — never a previously focused pill, such as the `Settings` gear left focused after closing `SettingsScreen`. A second `Back` while that pill is focused leaves the screen (Home → profile switcher; other tabs → Home). A D-pad `Up` from the content into the bar likewise lands on the active screen's pill (the bar keeps no last-focused-pill memory). Closing `Settings` with `Back` returns focus to the `Settings` gear that opened it.
  - **Tab Entry Focus:** Opening `Home` (first load after profile selection or startup) and switching to any top-level tab (`Home`, `Movies`, `TV Shows`, `Library`) keeps D-pad focus on that tab's own pill in the Top Navigation Bar; nothing hands it to the content afterwards (no late jump onto the Home hero's `View Details` once the hero loads). `Down` from the pill enters the content (the hero on Home, `Popular` item #1 on Movies/TV Shows). Returning from a row's `View More` or from `DetailsScreen` still restores the originating card/hero.
  - **Long-Press Back → Search (global shortcut):** On every screen reached after a profile is chosen — `Home`, `Movies`, `TV Shows`, `Library`, `View More`, `Details`, `Episodes`, `Settings` (and its sub-panels) and `Search` itself — pressing and **holding** Remote `Back` past the system long-press timeout opens `SearchScreen` directly with D-pad focus on the Microphone button (the search field on devices without voice input, e.g. Fire OS, §7). Any open `Details` / `Episodes` / `Settings` pages are closed and Search opens on top of the tab or `View More` page underneath, so a later short `Back` from Search returns there (an unconfirmed background-colour preview is discarded, as with `Back`). Already on Search, the hold just moves focus to the Microphone, or the search field without one (a no-op if it is already there) and never pops Search.
    - **Short press unchanged:** A `Back` released before the timeout behaves exactly as described elsewhere (nav-bar pill, close a page, Home → profile switcher). The press is held back until release, so nothing reacts to it early and nothing reacts twice.
    - **No phantom actions:** Once the hold fires, every further repeat and the trailing `KeyUp` are consumed: no short-press `Back` action runs, the stack is not popped, the app does not exit, and nothing on Search is clicked when `Back` is released.
    - **Exclusions:** The shortcut is off — `Back` (short or held) keeps its existing behaviour — during video playback (the built-in player for movies, episodes and full-screen trailers, §9), the initial stream-lookup loading screen and `Finding streams…` / `Loading trailer…` lookups, the stream selection modal (§6), the splash (§2, `Back` consumed), onboarding, and the Profile Gate (`ProfileSelectScreen`, `ProfileCreateScreen`), so it can never skip mandatory profile creation or selection. Dropdown popups and the on-screen keyboard keep `Back` to themselves.
  - **Full-Bar Wrap Loop:** The whole bar is one horizontal row for the §1 Edge-Stop-Then-Wrap Rule, from the top-left **Profile Avatar** (left-most focusable item) through the pills to **Settings** (right-most focusable item): Adult `Avatar`, `Search`, `Home`, `Movies`, `TV Shows`, `Library`, `Settings`; Kids `Avatar`, `Search`, `Home`, `Library`, `Settings`. A fresh `Right` on `Settings` wraps to the Avatar, and a fresh `Left` on the Avatar wraps to `Settings`. Held `Left`/`Right` stops on that edge item. `Avatar` ⇄ `Search` is ordinary navigation in both directions (the clock is not focusable).
- **Global Edge-Stop-Then-Wrap Rule (applies to every screen, including all Milestone 4+ screens):** Focus never wraps automatically while a direction key is held down.
  - **Held key (`KeyEvent.nativeKeyEvent.repeatCount > 0`):** Focus stops and stays on the edge item: the last item of a horizontal row (`Right`) or the bottom-most row/element of a page (`Down`), and, on surfaces that wrap both ways, the first item of the row (`Left`) or the top-most element (`Up`). Auto-repeat events at the edge are consumed so focus neither wraps nor escapes elsewhere.
  - **Fresh press at the edge (`repeatCount == 0`):** Only when focus is *already* on the edge item and the user presses that same outward direction again as a new key press does focus wrap: `Right` → item #1 of the row; `Down` → the top of the page. **Bidirectional surfaces** also wrap backwards: `Left` on item #1 → the last *currently visible* item of the row; `Up` on the top-most element → the bottom-most visible element. Bidirectional today: the Top Navigation Bar (Avatar ⇄ `Settings`), the `DetailsScreen` action stack (§6), the Player HUD bottom action bar (§9), the stream selection modal opened from Details/Episodes (§6), the in-player `Streams` overlay (§9), both columns of the More Episodes screen (season pills and episode rows, §6), the in-player `Episodes` card (§9: season pills `Left`/`Right` first ⇄ last; vertical loop `Episode 1` →`Up`→ highlighted season pill →`Up`→ last episode →`Down`→ `Episode 1`), the Library A–Z quick-jump bar (§7: `#` ⇄ `Z`), the Library filter sidebar ⇄ A–Z quick-jump bar (§7: `Left` on `All` / `Movies` / `TV Shows` ⇄ `Right` on any letter), the in-player Subtitles overlay (§9: `Off` ⇄ `Background`), the Settings Category Tab Bar (§11: `Home` ⇄ `Other`, horizontal), the Settings background color swatch strip (§11: `#000000` ⇄ `#17212B`, horizontal), the `Subtitle styling` Text color swatches (§11: `White` ⇄ `Light grey`, horizontal), the Manage addons sub-panel (§11: first addon row ⇄ `Install more addons`), every shared long-press action menu (§3 `Continue Watching`, §6 Season pill and Episode row menus: first option ⇄ last option), the `Choose a Profile` column (§2: first profile ⇄ `+`, or ⇄ the fifth profile at the cap), and the Stream filter value lists and `Stream sorting` panel (§11/§13). On these vertical lists a fresh `Up` on the first entry wraps to the last entry and a fresh `Down` on the last entry wraps to the first; held `Up`/`Down` stops on the edge entry. The stream modal and `Streams` overlay hold two such lists side by side (§6 Two-Column Stream Panel): the `Addons` column and the `Choose a stream` column each wrap `Up`/`Down` on their own, `Left`/`Right` switch between them, and the outer `Left` (in `Addons`) and outer `Right` (in `Choose a stream`) are consumed. A single-item row or list consumes both directions and keeps focus in place. **One-way (bottom-to-top) exception — General Settings category lists (§11):** in every Settings category list only the bottom edge wraps: a fresh `Down` on the last row wraps to the first row (held `Down` stops on the last row), while a fresh `Up` on the first row moves focus up to the active category pill in the Settings Category Tab Bar instead of wrapping (held `Up` stops on the first row). The bottom edge follows conditional sub-settings such as `Failover timeout duration` under `Playback` or `Mute auto-play trailers` / `Trailer auto-play delay` under `UI`; with a single row, `Up` goes to the active pill and `Down` keeps focus on that row.
  - Implementation: shared `Modifier.onDpadEdgeWrap(key, wrap)` in `ui/theme/FocusModifiers.kt` (any direction: put it on the edge item with that edge's outward key); two-way vertical lists use `Modifier.verticalListEdgeWrap(index, lastIndex, toFirst, toLast)` + `rememberListEdgeWrap(...)` in `ui/theme/ListEdgeWrap.kt`, built on it. New rows/grids/pages must use these rather than hand-rolled wrap handlers.
  - **Key-Up / Phantom Click Guard (Global):** Opening any overlay, HUD, or modal via `DPAD_CENTER`/`Enter` (`KeyDown` or `onLongClick`) must consume or ignore the trailing `KeyUp` event from that same physical press so newly focused controls (e.g., the Player HUD `Play/Pause` button or the 1st item in a stream selection modal) never fire an accidental click on key release. Shared via `Modifier.ignoreInitialKeyUp()` in `ui/theme/FocusModifiers.kt`. Long-press state belongs to the press on the focused control and is cleared whenever focus moves, so returning to a control after the modal or menu its long-press opened never swallows the next `OK` (shared via `Modifier.selectLongPress()` in `ui/theme/SelectLongPress.kt`).
- **Watched Artwork Indicator (Global):** Whenever a movie, TV show, or episode is marked as watched (`>= 90%` progress or manually marked watched), display a crisp white checkmark (`Icons.Rounded.Check` / `#FFFFFF`) inside a subtle dark translucent circular pill at the **top-right corner** of its artwork (with uniform `6dp–8dp` corner padding so it remains legible over bright posters/stills). Do **not** render a bottom progress line for completed/watched items (reserve bottom progress bars strictly for active, in-progress items `< 90%` in `Continue Watching` or partially watched episodes).
  - **Artwork Progress Bar Styling (`ArtworkProgressBar` in `ui/components/WatchedIndicator.kt`):** Uses its own opaque `ArtworkProgress*` tokens in `ui/theme/Color.kt`, separate from the player seek bar's tiers (§9, which keep their blue buffered range), never a translucent white track. Watched portion is `ArtworkProgressWatched` (`#FFFFFF`, crisp white); unwatched track is `ArtworkProgressTrack` (`#4A5263`, a lighter slate grey that stays distinct from both the backing and the white fill); a `1dp` `ArtworkProgressBorder` (`Obsidian`, `#0B0D12`) backing surrounds it so it stays separated from bright posters and backdrops. The fill is `6dp` tall (`8dp` with the backing), pill-capped, and drawn in a single draw-only node so the `2:3 ↔ 16:9` width animation stays at 60fps.
  - **Focus-Ring Clearance:** The bar is inset `5dp` from the artwork's bottom edge (the `3dp` `#E5E9F0` focus ring plus a `2dp` gap) and `10dp` from each side (inside the ring's `12dp` rounded corners), so the focus ring of a focused poster or expanded 16:9 card never covers, clips, or touches any part of it. Card height is unchanged. Overlays anchored to the artwork bottom (the Continue Watching `S7:E10` badge and the expanded card's title logo) sit above the bar's `13dp` clearance (`ArtworkProgressClearance`).
  - **Visibility:** `0% < progress < 90%` → bar only (fraction clamped to `0..1`); `>= 90%` or manually marked watched → checkmark only, no bar; no saved progress or unknown duration → neither.
- **App Icon & TV Banner (Launcher Artwork):** Generated from two brand references (never hand-drawn): `docs/ui-references/tv_icon.png` (1:1, cyan-to-blue wave play triangle above the lowercase `seastreams` wordmark on pure `#000000`) and `docs/ui-references/tv_banner.png` (16:9, the same triangle left of the wordmark on pure `#000000`).
  - **Square icon (`@mipmap/ic_launcher`, `@mipmap/ic_launcher_round`):** Adaptive icon with a `#000000` background layer and a `108dp` foreground whose artwork is scaled so every non-black pixel stays inside the `66dp` safe-zone circle (`31dp` radius). Circle, squircle, and rounded-square masks (Google TV "Your apps", Monet, Projectivy circle/square modes, Android Settings > Apps) never clip the triangle or the wordmark. Legacy `48dp` square and circle rasters ship in `mdpi`–`xxxhdpi` as fallbacks.
  - **TV banner (`@drawable/tv_banner`):** `160x90dp`, i.e. the Android TV `320x180px` xhdpi spec (`160x90` mdpi → `640x360` xxxhdpi px), pure `#000000` preserved, the lockup centred at ~80% of the banner width (~10% side margins).
  - **Launcher compatibility:** `android:banner` is set on both `<application>` and the `LEANBACK_LAUNCHER` `MainActivity`, because third-party launchers read either `ActivityInfo.banner` or `ApplicationInfo.banner` in 16:9 card mode and fall back to the activity/application icon in 1:1 or circle mode. The launcher icon never appears on the system splash (see §2 *System launch window*).

## 2. Onboarding & Profiles (Max 5 Profiles)
- **Startup Splash Screen (precedes the Profile Gate):** Every cold launch shows a native Jetpack Compose splash (`SeaStreamsSplashScreen`) before `ProfileCreateScreen` / `ProfileSelectScreen`.
  - **System launch window:** Pure black `#000000` window background with no system splash icon (Android 12+ `windowSplashScreenAnimatedIcon` is transparent), so there is no duplicate centre-icon flash before the Compose splash appears.
  - **Layout:** Pure black `#000000` full-screen background (independent of the user's Settings background colour). Centred row: the SeaStreams icon (`R.drawable.ic_seastreams_icon`, `96dp`) then `24dp` gap then the lowercase wordmark `seastreams` in white Fredoka SemiBold (`R.font.fredoka_semibold`, `64sp`), each letter its own `androidx.tv.material3.Text` with font padding disabled. Because the wordmark is all x-height letters (no ascenders/descenders), its ink sits below the centre of its line box. The icon is shifted `10dp` down so its top corner sits above the `s`, its bottom corner below, and its right-hand tip and horizontal centreline run through the middle of the lowercase `a` counter, the centre of the x-height letters (`docs/ui-references/tv_banner.png`).
  - **Pop-in and bobbing animation (one-shot, no loop):** The splash holds pure black for `420ms`, so the Android TV launch crossfade and startup work finish before any letter moves. Letters then appear left-to-right over `2840ms` (`110ms` stagger, `1850ms` each; `9 × 110ms + 1850ms = 2840ms`). In the first 26% of its life, each letter fades in and rises boldly out of the water from `0.25x` / `18dp` below / `-14°` to a crest (`1.12x`, `13dp` up, tilted ~`10°` right). It then bobs like a float on a slow swell (dips ~`7.8dp` below the baseline, rises ~`2.7dp` back above), rocking side-to-side (~`6°`, then ~`2°`) with a slight lag, and settles exactly flat. Every animated letter property (alpha, Y-translation, scale, rotation) is read only inside `Modifier.graphicsLayer`, never `Modifier.offset` / `scale` / `alpha`, so animation frames never recompose or re-layout the letters.
  - **Lightweight mode (reduced motion / Fire OS / low RAM):** When animations are off at the OS level (`Settings.Global.ANIMATOR_DURATION_SCALE == 0`), or on Fire OS (`Build.MANUFACTURER` is `Amazon`, ignoring case, or the device declares the `amazon.hardware.fire_tv` system feature, which covers OEM Fire TV sets such as Insignia) or low-RAM hardware (`ActivityManager.isLowRamDevice`), the per-letter pop-in and bobbing is skipped. After the same `420ms` black start, the static icon + `seastreams` lockup fades in once as a whole over `600ms` on a single graphics layer, or appears at once when animations are off. The black background, `10dp` icon alignment, `3350ms` minimum hold / `AppGate` wait, `Back` consumption and Profile Gate preload are identical in both modes.
  - **Hold & exit:** After the motion settles (`420ms + 2840ms`), the still wordmark holds for ~`90ms`: the splash stays up for at least `3350ms` from first frame *and* until the initial profile/TMDB-key gate state has loaded (`AppGate != Loading`), then hands off to the Profile Gate. It shows once per process: it is not replayed after configuration changes or when returning from Home to the profile switcher.
  - **Profile Gate preload:** When profiles already exist (`AppGate.Ready`), the splash creates the Profile Gate's ViewModel, so the child-safe featured backdrop (same `GetProfileGateBackdropUseCase` filtering, rule 6) is fetched and decoded into Coil's memory/disk cache behind the splash. `ProfileSelectScreen` then draws its artwork on its first frame with no empty or loading flash. The preload does not run during first-run onboarding, because the Kids-aware filter must see the real profile list.
  - **Input:** Remote `Back` is consumed during the splash (no accidental exit); the splash has no focusable elements, so no D-pad focus is set until the Profile Gate draws.
- **Profile Gate (`profiles.jpg`):** On startup, if no profile exists, launch directly into Profile Creation. If profiles exist, display the vertical "Choose a Profile" selector on the left with full-bleed featured backdrop art on the right, plus an edit pencil icon and `+` button (up to 5 profiles).
  - **Fits the 540dp viewport (1–5 profiles + `+`):** Every profile row and the `+` tile are always fully visible, sized and D-pad focusable on the `960×540dp` TV viewport, and nothing scrolls. Avatars use the full `76dp` resting / `108dp` focused size and `18dp` gaps while the column fits. With more rows the gaps drop to `8dp` and the avatars shrink together, keeping their ratio and never going below `48dp` / `56dp`. Each row reserves the focused avatar's scaled (`1.08×`) size, so a focused avatar never overlaps its neighbours. For example, 4 profiles + `+` or 5 profiles use ~`64dp` focused avatars. The rule lives in `profileGateMetrics` in `ui/screens/profiles/ProfileGateLayout.kt`.
  - **D-pad:** `Up`/`Down` move between rows. The column follows the §1 two-way Edge-Stop-Then-Wrap rule: a fresh `Up` on the first profile wraps to the last row, which is `+`, or the fifth profile at the cap; a fresh `Down` on the last row wraps to the first profile; a held key stops on the edge row. The edge rule covers both the avatar and its edit pencil (`Left` of the avatar).
  - **Delete profile (editor):** `Delete profile` is a two-press pill. The first press changes the label to `Press again to delete`, and the second deletes. The pill is always as wide as the longer label, so it never resizes, and every state draws its outline with the same stadium shape: no straight-line artifact along the bottom edge. Moving focus away from the pill disarms it.
  - **Editor bottom clearance:** below its last row, the editor's scrolling form has `32dp` of scrollable space. Whenever focus enters the `Save` / `Continue` / `Delete profile` row, and when `Delete profile` is armed, the form scrolls all the way to the end. The focused pills (scaled ~1.1× with their focus ring) therefore always show their full rounded bottom, clear of the bottom edge of the `540dp` viewport, and are never cut flat.
  - **Opened from Settings (`Settings → Home → Profiles`, §11):** The `Profiles` row opens the same `ProfileSelectScreen` (same artwork filtering, edit pencil and `+` button) as a full-screen layer over `SettingsScreen`, which stays open underneath. Remote `Back` on `ProfileSelectScreen` returns directly to `SettingsScreen` with D-pad focus on the `Profiles` row (never exiting the app or jumping to Home). Selecting any profile (including the current one) switches to it and enters that profile's `Home` exactly as from the startup gate, with Settings closed.
  - **Child-Safe Profile Gate Artwork:** Backdrop artwork displayed on `ProfileSelectScreen` must never pull from Adult `Continue Watching` history and must exclude all **Horror** (TMDB genre ID `27`) and **Romance** (TMDB genre ID `10749`) titles (plus `Thriller` `53` and `Crime` `80`), while enforcing a strict family-safe certification ceiling (`PG` / `TV-PG`, `allowUnrated = false`) via `AgeRestrictionEngine` whenever at least one Kids/age-restricted profile exists on the device (or capping at `PG-13` / `TV-14` with `allowUnrated = false` if only Adult profiles exist). This is re-evaluated live: the moment a Kids profile is added (or a profile is switched to Kids), any artwork chosen under the Adult-only ceiling is hidden and a stricter backdrop is fetched. If that fetch fails, the dark background stays; the adult artwork is never shown again.
- **Mandatory TMDB Key & Web Portal Input:** During first profile creation, the user must enter a valid TMDB API key (validated via a test call to `/configuration`) before proceeding. Users can type via on-screen keyboard OR scan a QR code / visit the local LAN IP (`http://<tv-ip>:8765`) to type the API key and profile name from a phone/PC browser.
- **Profile Age Restrictions:**
  - Profiles can be standard (Adult) or Kids (Age-Restricted with max certification ceiling, e.g., `G`, `PG`, `PG-13` / `TV-Y`, `TV-Y7`, `TV-G`, `TV-PG`, plus a toggle to `Allow/Disallow Unrated Items`).
  - **Hard Filtering:** On Kids profiles, any movie/show outside the allowed rating—or unrated when disallowed—is stripped at the data layer even if returned by an external Stremio addon or MDBList.

## 3. Home Screen Architecture
- **Adult Profile Home Layout:**
  1. **Hero Carousel (`home-hero.jpg`):** Large rounded-corner featured card spanning screen width. Pools the first 15 items of `https://mdblist.com/lists/official/movies/justwatch-streaming-charts` and the first 15 of `https://mdblist.com/lists/official/shows/justwatch-streaming-charts` (30 total, de-duplicated), shuffles them, and caps the carousel at 10 items per Home screen load (only titles with backdrop art qualify). Horizontal D-pad scrolling cycles items; displays logo/title, match/rating %, year, genres, certification, runtime, truncated synopsis, and a focused `View Details` pill button. The hero is never focused automatically on load or tab return (§1 Tab Entry Focus); `Down` from the `Home` pill focuses `View Details`. Sized so that, on a 960×540dp screen, only the first row's header and a ~20dp strip of its showcase slot and posters show below the hero (`desired_hero_size.jpg`).
     - **Focus Ring:** While the hero holds D-pad focus, the card shows the same crisp `3dp` `#E5E9F0` focus border used by focused catalog cards (shared `FocusBorderWidth` / `Modifier.focusRing` in `ui/theme/FocusModifiers.kt`), drawn on the hero's own rounded shape.
     - **Continuous 5-Second Auto-Advance:** The hero advances to the next item every 5 seconds, wrapping from item #10 back to #1, for as long as Home is on screen — including while focus is on the Top Navigation Bar or the catalog rows below. Only direct interaction with the hero (Left/Right on the hero card, or pressing its button) restarts the 5-second countdown. The timer pauses when Home leaves the foreground (`ON_PAUSE`/`ON_STOP`) or the user navigates to another screen.
  2. **Continue Watching (`home-genres-continue.jpg`):** Horizontal row of the user's last 10 in-progress movies/episodes with progress bars (§1 Artwork Progress Bar Styling, on both the 2:3 posters and the expanded 16:9 card) and season/episode badges (`S7:E10`, sitting above the bar). Clicking an item either starts playback immediately (if *Auto-play from Continue Watching* is ON, the default) or opens its Details page (if OFF).
     - **Direct-to-Playback (Auto-play from Continue Watching ON):** `OK`/`Enter` on a card goes straight from `Home` to playback of **that card's** movie or exact episode — never opening, flashing, or stacking `DetailsScreen`. The title is loaded age-checked for the profile at the use-case layer (`ResolveContinueWatchingTargetUseCase`), its IMDb ID is fetched lazily via `/external_ids` for that single title only, and the **top stream result** auto-plays (regardless of *Auto-play top stream*, honoring the preferred auto-play addon) — or that movie/episode's `LAST USED` stream (§6) whenever the freshly fetched list holds it — from the saved resume position, in the built-in player or the configured external player / system chooser. A `Finding streams…` badge shows meanwhile with focus left on the card. Pressing `Back` from playback returns directly to `Home` with D-pad focus restored to that `Continue Watching` card (no trailing `KeyUp` click); if the title is restricted, can't be loaded, or has no streams, a brief message shows and focus stays on the card.
     - **Next Up Cards (Milestone 13):** With *Show next up in continue watching* ON (default, §11), any TV show whose most recently watched episode is finished (`>= 90%`) gets a `Next Up` card for its **next aired episode** (`S1:E3` → `S1:E4`, a season finale → `S2:E1` once it has aired), whether or not the show is in the Library. Shows in the profile's Library are always checked, so a caught-up Library show resurfaces when a new episode airs; a Library show needs at least one finished episode (unwatched Library shows never get an `S1:E1` card). A show whose newest episode is unfinished keeps its in-progress card instead, so a show never has both. Next Up cards share the 10-card cap with in-progress cards, sorted by most recent activity (the last watch, or the air day of a newly aired next episode), and show the `S7:E10` badge with **no** progress bar (0%). Each card costs one HTTP-cached `/tv/{id}` lookup, age-checked at the use-case layer (`GetNextUpUseCase`, CLAUDE.md rule 6); `/external_ids` is never fetched on Home and runs only for the single card the user plays. `OK` behaves like any Continue Watching card (auto-play the episode from the start, or open Details, whose `Play` picks the same episode).
     - **Long-Press Action Menu (`onLongClick`):** Pressing and holding `OK`/`Enter` on a `Continue Watching` card opens the shared centered D-pad action menu (same focus trap, two-way `Up`/`Down` edge-stop-then-wrap, `ignoreInitialKeyUp()` held-`OK` guard, and `Back` dismiss behavior as `EpisodesScreen` in §6) with three options, in order (a `Next Up` card has nothing to clear, so it offers only `View details` and `Remove`):
       - `View details`: Dismisses the menu and opens `DetailsScreen` for that movie or TV show, whether *Auto-play from Continue Watching* is ON or OFF. `Back` from Details returns focus to the exact `Continue Watching` card.
       - `Remove`: Hides/dismisses the item from the `Continue Watching` row without altering its watch progress or watched status (`WatchProgressDao` record remains intact). If the user plays that movie or episode again later, it reappears in `Continue Watching` as normal. On a `Next Up` card, `Remove` records a per-show dismissal and never touches watch history: the card stays gone across Home reloads until the user watches any episode of the show again or a newer episode airs.
       - `Clear progress`: Removes the item from `Continue Watching` **and** marks that specific movie or single episode as unwatched by deleting its progress record in `WatchProgressDao` (for TV shows, only the specific focused episode is cleared, not other episodes or the whole series).
     - **Description Stays Visible:** While the menu is open, the long-pressed card stays the row's wide 16:9 card and its title, metadata line, and synopsis stay shown beneath its artwork (dimmed under the menu's scrim), exactly as while the card held focus; they hide only once D-pad focus actually leaves the row.
     - **Post-Action & Dismiss Focus Restoration:**
       - Pressing `Back` dismisses the menu without making changes and returns D-pad focus to the exact `Continue Watching` item that opened it.
       - Selecting either `Remove` or `Clear progress` dismisses the menu, removes the card from the row, and returns D-pad focus to the `Continue Watching` row onto the **next item to the right** (or onto the **previous item to the left** if the removed item was the last item in the row; if the row becomes empty, focus moves cleanly to the next available row below or the `HeroCarousel` above).
  3. **Most Watched Movies:** Horizontal row pulling from `https://mdblist.com/lists/official/movies/most-watched-week`.
  4. **Most Watched Shows:** Horizontal row pulling from `https://mdblist.com/lists/official/shows/most-watched-week`.
  5. **Metadata Addon Catalogs:** Any catalogs exposed by enabled Stremio metadata/catalog addons populate exclusively on the `Home` screen directly beneath `Most Watched Shows` (in installed addon order, using the standard `ExpandingCatalogRow` with 20-item cap + `View More`).
- **Kids Profile Home Layout:**
  1. **Kids Hero Carousel:** Pools the first 15 entries of `https://mdblist.com/lists/snoak/trending-kids-movies` and the first 15 of `https://mdblist.com/lists/tvgeniekodi/trending-kids-tv-shows` (30 total), strictly filtered through `AgeRestrictionEngine` against the profile's ceiling, shuffles them, and caps the carousel at 10 items per Home screen load. Same focus ring and continuous 5-second auto-advance as the Adult hero.
  2. **Continue Watching:** Last 10 watched items for that Kids profile.

Because addon streams carry no stable ID and debrid/proxy URLs are re-signed on every fetch, a freshly fetched list is matched in tiers, all within the same addon: (1) the exact stream URL (compared by fingerprint: only a SHA-256 of the URL is stored, never the URL, which can carry debrid keys or tokens); (2) the same stream name + description; (3) the same stream name + description with every number ignored (torrent addons put live seeder/peer counts in the description); (4) the same stream name + first description line (the release / file name); (5) the same stream name. Tiers 3–5 match only when exactly one listed stream qualifies, so the cue never guesses between candidates. The Details target is built only once the title, its IMDb ID **and its saved progress** have loaded, so `Resume S2:E4` always looks up (and plays) S2:E4, never S1:E1.
    - **Auto-play prefers `LAST USED`:** Every auto-play start — `Play`/`Resume` with *Auto-play top stream* on, the episode menu's `Auto-play`, *Auto-play from Continue Watching* (§3), `Next Episode`, the Episodes overlay and Auto-Play Next Episode (§9) — starts the `LAST USED` stream when the fresh list holds it, otherwise the top stream (Preferred Auto-Play Addon first). With *Automatic Stream Failover* on (§9), the automatic stream fallback continues down the list from whichever stream started.
    - **Visual cue:** The matching card shows a compact pill reading `LAST USED` in dark bold text on a gold (`#F5C518`) background in the card's **top-right corner**, vertically centred on the addon-name row. The pill keeps its full width and never truncates; the addon name takes the remaining width and soft-wraps beside it, never running under it. Its colours are fixed, so it reads the same on the unfocused translucent card and on the focused `#E5E9F0` pill. A card can show both the playing check (§9) and `LAST USED`.
    - **Initial auto-focus:** When the stream selection modal (Details, Episodes, long-press `Play`, `View streams`) or the in-player `Streams` overlay opens, the `LAST USED` stream's addon is selected (the `Addons` column scrolls so its card is visible) and the stream column scrolls to and places D-pad focus on the `LAST USED` card; with no match, the top addon is selected and focus lands on its 1st stream (on the top addon card itself when that addon returned no results). The auto-focused card ignores the held `OK` that opened the list (§1 Key-Up guard), and so does every addon card, so no stream or addon is ever chosen on release.
  - **Exact Focus Restoration on Back:** Pressing Remote `Back` to exit `DetailsScreen` must return D-pad focus to the exact originating item/card/button from which `DetailsScreen` was opened (`Home` hero or catalog row item, `Movies`, `TV Shows`, `View More`, `Search`, or `Library`).
  - Opening this screen triggers the lazy fetch of `/external_ids` (IMDb ID) so Stremio stream addons can be queried. (The only other `/external_ids` caller is the single-title lookup when a `Continue Watching` card plays directly, §3.)
- **Episodes Screen (`EpisodesScreen.kt`):**
  - Left pane: Show title, metadata, and vertical Season selector pills (`Season 1`, `Season 2`, etc.).
  - **Two-way wrap (§1 rule) on both columns:** A fresh `Up` on the first season pill wraps to the last season pill and a fresh `Down` on the last wraps to the first; the episode list does the same (first episode row ⇄ last episode row). Held `Up`/`Down` stops on the edge pill/row. Wrapping onto a season pill selects that season, exactly as moving focus onto it does. Search categories and Library filters keep their `Down`-only wrap.
  - Right pane: Vertical list of episodes showing episode number badge, 16:9 still thumbnail (blurred if unwatched and *Blur Unwatched Thumbnails* is enabled), episode title, air date, runtime, and synopsis, displaying the global top-right white checkmark badge on the thumbnail for watched episodes (and a bottom progress bar only for partially watched in-progress episodes).
  - **Long-Press Action Menus (shared behavior):** Pressing and holding `OK`/`Enter` opens a centered, D-pad-focusable action menu over a dimmed screen. Initial focus lands on the first option, focus cannot leave the menu, and the options follow the §1 two-way Edge-Stop-Then-Wrap rule: a fresh `Up` (`repeatCount == 0`) on the first option wraps to the last, a fresh `Down` on the last option wraps to the first, and a held `Up`/`Down` (`repeatCount > 0`) stops on the edge option without wrapping or leaving the menu. Releasing the held `OK` never triggers an option. The Season pill and Episode row menus and `Continue Watching` (§3) share one `ActionMenu` composable (`ui/components/ActionMenu.kt`, `Modifier.verticalListEdgeWrap`). Remote `Back` dismisses the menu and returns focus to the exact season pill or episode row that opened it; choosing an option also returns focus there (or to the stream modal the option opened).
  - **Season Pill Long-Press (`onLongClick`):**
    - `Mark Season Watched`: unconditionally marks every episode in that season as watched in `WatchProgressDao`, whatever each episode's current state.
    - `Mark Season Unwatched`: unconditionally marks every episode in that season as unwatched (clears its watch progress) in `WatchProgressDao`, even if only some episodes were watched.
    - `Shuffle Season`: picks a random aired episode from that season only and starts playback — auto-playing the top stream when *Auto-play top stream* is enabled, otherwise opening the stream selection modal. It starts a **season-scoped shuffle session**: the player HUD `Next Episode` and Auto-Play Next Episode keep picking random aired episodes strictly from that season, never the episode that just played, and avoiding episodes already played in this shuffle until the whole season has played once (§9).
  - **Episode Row Long-Press (`onLongClick`):**
    - `View streams`: bypasses auto-play and opens the stream selection modal for that episode.
    - `Auto-play`: resolves streams and immediately plays the top stream result (regardless of the *Auto-play top stream* setting), honoring the preferred auto-play addon and the configured internal/external player.
    - `Mark watched` / `Mark unwatched`: the label toggles with the episode's current watched status; choosing it updates `WatchProgressDao`, and the watched indicator and thumbnail blur state update immediately.
    - `Mark previous in season watched`: unconditionally marks every episode in that season with `episodeNumber <= selectedEpisode.episodeNumber` as watched.
    - `Mark previous in season unwatched`: unconditionally marks every episode in that season with `episodeNumber <= selectedEpisode.episodeNumber` as unwatched (clears its watch progress), whether that range is all watched or a mix of watched and unwatched episodes.
  - "Watched" means a finished `WatchProgressDao` record (position = duration, which satisfies the `>= 90%` completion rule in §9); "unwatched" deletes the record, as if the episode was never started.

A short "Voice search isn't available on this device." note appears (cleared by typing, a search or a recent chip), and the keyboard opens on the search field.

D-pad focus moves over it without opening the keyboard; `OK` always opens the on-screen keyboard, including on Fire TV where a D-pad click must force it open, and leaving the field in any way (search, `Back`, D-pad out, leaving Search) always closes it, so it never lingers. The keyboard's `Search` key, or a hardware `Enter` / `OK` press (acting on release), runs the search, closes the keyboard and leaves focus on the field, so `Down` moves straight into the results. While typing, `Left` at the very start, `Right` at the very end, `Up` and `Down` leave the field exactly as they do from the resting field (Microphone, clear-query `X`, first recent chip / content). `Back` (once the keyboard is closed) only leaves typing, never Search.

Releasing the held `Back` never clicks anything here.
  - Below search bar: Horizontal chips of recent searches with a clear-all `X` button.
  - **Top bar ⇄ recent chips (deterministic focus):** While recent chips are shown, `Down` from the Microphone button, the search field, or the clear-query `X` always focuses the **first (leftmost) recent chip**, scrolling the chip row back to its start first. It never skips the chip row or lands on a middle chip under the wide search field. `Up` from any chip (or the clear-all `X`) returns focus to the top-bar control it came down from: the Microphone by default, or the search field when the clear-query `X` it came from has since disappeared. With no recent chips, `Down` from the top bar keeps its existing behaviour (into the category sidebar / poster grid, or item #1 of the top results row).
  - **Content top edge → chips / top bar (deterministic focus):** `Up` from the top-most category (`Trending Movies`) or from any poster in the top row of the 5-column grid goes to the **first (leftmost) recent chip**, scrolling the chip row back to its start, whenever recent chips are shown. With no recent chips it goes to the top-bar control focus last came from: the Microphone by default, the search field, or the clear-query `X` while it is shown. If a target can't take focus it falls back one step (chip → top-bar control → Microphone), and if nothing can, focus stays where it was, so it is never lost. `Up` on lower categories and lower grid rows (same-column moves) is unchanged.
  - Left sidebar: Hover-activated category list starting with `Trending Movies` (default selected), `Trending Shows`, followed by all TMDB movie genres (`Action Movies`, `Adventure Movies`, etc.). Moving D-pad focus onto a category immediately loads its 5-column poster grid on the right.
- **Library Page:**
  - Left sidebar: Hover-activated filter buttons (`All` [default focused], `Movies`, `TV Shows`). Moving D-pad focus between them is instant: focus and the selected highlight follow every press with no main-thread work, because each filter's grid, A–Z index and genre list are computed ahead of time off the main thread. The grid switches to the focused filter once focus has rested on it for ~100ms, so pressing `Up`/`Down` across filters never composes the grids passed through. Leaving the sidebar applies the focused filter at once. A `Right` while the switch is still pending is consumed and lands on the new grid's first poster, never on a poster of the grid being replaced. `Left` (wrap to the A–Z bar), `Back` and `Up` to the Top Navigation Bar also apply it at once. Choosing `All Genres` clears it. Besides TMDB genres, the Genre dropdown offers **Christmas** under `All` and `Movies` whenever a saved movie is tagged with TMDB keyword `1441` (christmas-party), `207317` (christmas) or `193048` (christmas-spirit); shows never match, so `TV Shows` never offers it and treats a selected Christmas like any genre it lacks. Keyword ids are saved with each movie (from the same TMDB details request) and included in backups; movies saved before this was added are looked up once in the background, one title at a time, and join Christmas as their keywords arrive. The Genre filter resets to `All Genres` whenever the user leaves the Library page (another tab, Search, Settings, or a profile switch). Opening a title's Details and coming back keeps it.

Picking a different Sort order or Genre (including `All Genres`) scrolls the grid straight back to the top (no animation) and moves focus to the first poster in the new list once it is shown. Re-picking the current choice changes nothing and focus stays on that control. That includes `All Genres` when no genre is applied: it still forgets a remembered genre that this filter doesn't have, but the grid doesn't change. With no titles, focus also stays on the control. Switching `All` / `Movies` / `TV Shows` never moves focus off the sidebar.

  - Far right edge: Vertical quick-jump letter strip, `#` then `A`–`Z` top to bottom. Focusing a letter highlights it at once; the grid scrolls (instantly, no animation) to that letter's first title only after focus has rested on it for ~100ms, so holding `Up`/`Down` scrubs smoothly through the bar without moving the grid or loading posters for each letter passed through. `OK` cancels any pending scroll, jumps immediately and moves focus onto that title. Only one grid scroll is ever in flight. Letters with no titles are dimmed but stay focusable, so the bar's edges are always `#` and `Z`.

Holding `Up`/`Down` (`repeatCount > 0`) stops on the edge letter and never wraps or leaves the bar. A single-letter bar would consume both `Up` and `Down` and keep focus in place.

It cancels any pending 100ms preview scroll, scrolls the grid immediately (no animation) to that letter's first title, and moves focus onto that exact poster. It uses the same letter matching as `OK`: titles file under their first letter after a leading `The`/`A`/`An` is dropped, `#` holds every title that doesn't start with `A`–`Z`, and "first" means first in the current filter/genre/sort display order.

For example, with only `B` and `D` populated, `Left` on `C` lands on `D`'s first title and `Left` on `#` lands on `B`'s. `OK` on a dimmed letter still does nothing.

Each jump (`Left` or `OK`) focuses only its own target poster, so consecutive jumps between nearby letters never land on the previous letter's poster, even while it is still on screen. A fresh `Left` (`repeatCount == 0`) on any filter (`All`, `Movies`, `TV Shows`) wraps to the quick-jump bar, scrolling to and focusing the letter that last held focus there (`#` until a letter has been focused); holding `Left` (`repeatCount > 0`) stops on the filter. A fresh `Right` on any letter wraps back to whichever filter last held focus before the bar (the currently selected filter, `All` by default, until one has); holding `Right` stops on the bar. Both are consumed, so focus never leaves the page sideways. `Right` from a filter still moves into the controls/grid, `Left` from a letter still goes to that letter's first title in the grid (above), and the bar's `#` ⇄ `Z` wrap is unchanged. With an empty library the bar is not shown and `Left` on a filter does nothing.

## 8. Stremio Addons, MDBList Library Import & LAN Web Portal
- **Stremio Protocol Support:** Parse `manifest.json` (including `catalogs`, `resources`, and `types`), fetch `/catalog/{type}/{id}.json`, `/stream/{type}/{id}.json`, and `/subtitles/{type}/{id}.json`. Every new profile starts with TMDB metadata built-in and OpenSubtitles (or default Stremio subtitle addon) pre-installed and enabled. Metadata addon catalogs render exclusively on `Home` beneath the built-in Home rows.
- **HTTPS & Cleartext HTTP Addons:** Addons may be served over `https://` or plain `http://` (self-hosted or LAN addons such as `http://192.168.4.173:3000/manifest.json`). An explicit scheme is kept exactly as entered and never upgraded or downgraded. A link with no scheme (e.g. `192.168.4.173:3000`) or a `stremio://` link gets `http://` when its host is on the user's machine or LAN (`localhost`, `*.local`, loopback `127/8` and `::1`, private `10/8`, `172.16/12`, `192.168/16`, link-local `169.254/16` and `fe80::/10`, unique-local `fc00::/7`) and `https://` otherwise. A missing `/manifest.json` is appended. The stream, subtitle and catalog requests to such an addon, and the stream and subtitle URLs it returns, may also be cleartext HTTP. The app's network security config permits this (ARCHITECTURE §2).
- **Per-Profile Addons:** Stremio addons are installed per profile, not app-wide. Installing, removing, enabling/disabling, renaming or reordering an addon affects only that profile; Home addon catalogs, stream lists and addon subtitles use only the active profile's enabled addons, in its order. The built-in TMDB metadata addon is present, enabled and non-removable on every profile. While Usenet streaming is configured (`Enable Usenet` ON, ≥ 1 enabled provider and ≥ 1 enabled indexer, §12), every profile also lists the built-in `Usenet` entry: added at the bottom of the list (so results keep their original place after the Stremio addons), non-removable, but it can be moved, renamed or switched off for that profile. Its position orders the Usenet card and results like any addon. The built-in `Debrid` entry (`debrid://builtin`, §14) works the same way: it is listed on every profile while `Enable Debrid` is ON and ≥ 1 Debrid provider is enabled, added at the bottom, non-removable, and movable/renamable/switchable per profile. A hidden built-in entry keeps its position, name and on/off state, and reappears with them once its source is configured again. Deleting a profile deletes its addons. When the app moved from app-wide to per-profile addons, every existing profile received a copy of the previously installed addons (with their order, enabled state and custom names).
- **In-App Addon Manager:** Enable/disable and reorder the active profile's installed addons (addon order also determines the display order of metadata addon catalogs on that profile's `Home`). Opened from `Settings -> Home -> Manage addons` (§11): one row per addon (a toggle pill plus `Move up`, `Move down` and, except for built-ins, `Remove` buttons), closed by an `Install more addons` row that opens the Web Portal. The list follows the §1 two-way edge-stop-then-wrap rule (§11 Manage addons sub-panel).
- **One-Time MDBList Library Import:** Users can import an `mdblist.com` list URL directly into a profile's `Movies` or `TV Shows` Library via the Local Web Portal. This is strictly a one-time batch import: once the list's new items are resolved and inserted into `LibraryDao`, SeaStreams does **not** store a subscription, track list changes, or sync future updates. Titles already in the profile's Library are skipped, never duplicated, replaced or removed: they keep their original date added (`Last Added` order), watch progress, watched state and last used stream. A title listed more than once is imported once, imports never touch other profiles, and the portal reports how many titles were added versus already in the library.
- **Local Web Portal (QR Code + LAN IP):** Single-page web app served by Ktor on the TV's local IP allowing the user to:
  1. Enter/update TMDB API key & profile fields.
  2. Install Stremio addons via manifest URL (`https://`, `http://`, `stremio://`, or a bare LAN `IP:port` such as `192.168.4.173:3000`; the field is plain text so the browser doesn't reject scheme-less addresses), remove, rename, disable, or reorder addons for one selected profile (the editor shows which profile it is editing and defaults to the TV's active profile; changes never reach other profiles).
  3. Import `mdblist.com` list URLs into a profile's `Movies` or `TV Shows` Library (one-time import with no ongoing list tracking/syncing).
  4. Configure the app-wide **Usenet sources** (§12):
     - add, edit, enable/disable, reorder and remove NNTP providers and Newznab indexers, starting from a preset;
     - pick the `Search` / `Download` request header presets and trigger *Update now*;
     - choose a Usenet performance profile or edit its values.
  5. Configure the app-wide **Debrid library** (§14):
     - add, enable/disable, reorder, test and remove Real-Debrid, AllDebrid, TorBox, Premiumize, Debrid-Link, Offcloud and put.io accounts (one per service);
     - sign in by pasting an API key / personal token, or with a device code (Real-Debrid, AllDebrid PIN, TorBox; Debrid-Link and put.io once client IDs are configured): the portal shows the code and the service's link page, the TV app completes the sign-in;
     - switch `Enable Usenet` and `Enable Debrid` on or off. Clearing a source is TV-only (it needs the 5-second Undo, §11).

     Passwords, API keys and tokens can be typed or replaced here but are never sent back to the browser: the portal only shows whether one is stored. A blank password, API key or token field keeps the stored one. The only exception is an explicit *Include credentials* backup download (item 6).
  5a. Edit one profile's **stream filtering, sorting & formatter** (§13). This covers every setting the TV offers, so nothing has to be finished on the TV.
  - **Section order (top to bottom):** TMDB key, Profiles, Stremio addons, Usenet, Debrid, Stream filters / sorting / formatter, MDBList import, and **Backup & restore**, which is always the last section of the page.
  6. **Backup & restore** (also opened from `Settings -> Other -> Backup & restore`; ARCHITECTURE §13): download or restore a versioned `.json` backup.
     - **Scope:** *Current profile (<name>)* (`seastreams-profile-<name>.json`: that profile's General Settings (UI, Playback, Audio, Subtitles, Appearance), addons (including the built-in `Usenet`/`Debrid` entries' order and on/off state), stream filters/sorting/formatter, saved Library titles (including MDBList imports) and Watch Progress (resume points, watched state and Continue Watching removals, including removed `Next Up` cards)) or *Full app backup (all profiles & sources)* (`seastreams-full-backup.json`: every profile, in order, also with its name, avatar, Kids flag, age ceilings and `allowUnrated`). Both include the app-wide `Enable Usenet` / `Enable Debrid` toggles, Usenet performance and header presets, and every NNTP provider, Newznab indexer and Debrid account.
     - **Include credentials** (unchecked by default): when checked, the file also holds the TMDB key, provider passwords, indexer API keys and Debrid keys/tokens in plain text, and the portal warns to keep it private; otherwise none of them are in the file.
     - **Restore:** the file's own scope decides what happens. A profile backup restores into the profile selected in the portal, never changes that profile's name, avatar or Kids limits, and never touches other profiles. A full backup updates same-named profiles (ignoring case, including their Kids limits) and creates the others; profiles not in the file are left alone, and a backup that would take the TV over 5 profiles is refused. Both merge the Usenet/Debrid sources (providers matched by server + port + username, indexers by address, Debrid accounts by service; others are added and the TV's other sources are kept) and save a non-blank TMDB key. Secrets in the file are re-encrypted on the TV. A file without credentials keeps the TV's stored ones, and sources new to the TV show *Password needed* / *Sign-in needed*. A restored profile that lacks the built-in `Usenet` or `Debrid` entry gets it right away once that source is configured. Library and Watch Progress are merged, never replaced: a title already in the profile's Library keeps its own date added (missing ones, such as MDBList imports, arrive with their original date added), and for each movie or episode the more recently updated progress wins (the further-watched one on a tie), so restoring onto a TV in use never rewinds or un-watches anything; for each show the more recent `Next Up` removal wins. A Kids profile only receives Library titles within its rating limits.
     - The whole file is validated first (version 1, structure, regexes, names, URLs; out-of-range numbers are clamped). An invalid file is rejected with a clear message and nothing is changed. Files up to 16 MB are accepted. LAST USED streams stay on the TV and are not backed up; backup files written before Library and Watch Progress were included still restore. The Playback skip/Next episode prompt settings (Milestone 14) travel with General Settings; files from before them restore their defaults.

## 9. Playback Engine (Media3 ExoPlayer) & Audio/Subtitle Controls
- **Default & External Players (with Full Watch Progress Sync):**
  - ExoPlayer is default; Settings supports launching streams via any installed external Android video player—listing preset/detected video players (Just Player, MX Player, Vimu, VLC, Kodi, plus any other installed app registered for `video/*` via `PackageManager.queryIntentActivities`) as well as an **Other (System App Chooser)** option using `Intent.createChooser`.
  - Launches via `ActivityResultContracts.StartActivityForResult` with `ACTION_VIEW` (`video/*`), passing saved resume positions (`position` / `startfrom` extras) and `return_result = true`.
  - **External Player Progress Preservation:** Parse returned `position`, `duration`, and `end_by` result extras (`position / duration` calculation so exiting partway saves the exact resume timestamp without falsely marking the item watched). If any external player omits position extras on exit, fall back to safe elapsed-time estimation or preserve prior progress—never corrupting or wiping watch status.
  - **In-App Trailer Playback (`PlaybackRequest.Trailer` & Inline Row Previews):**
    - **Details Screen (`PlaybackRequest.Trailer`):** Clicking `Trailer` on `DetailsScreen` always plays full-screen with audio enabled inside the built-in Media3 ExoPlayer (bypassing external player settings and ignoring inline trailer auto-play/mute/delay settings) using adaptive video+audio streams extracted via `NewPipeExtractor` (`MergingMediaSource`). It never writes to `WatchProgressDao`, disables Stremio stream fallback and `autoPlayNextEpisode`, hides Stremio audio/subtitle track pickers and Clean SDH toggles in the OSD, exits automatically back to `DetailsScreen` (restoring D-pad focus to the `Trailer` button) when playback ends, and falls back silently to external YouTube (opening the top-ranked candidate) only if every trailer candidate fails extraction.
    - **Trailer Candidates (multi-candidate fallback):** TMDB's YouTube videos for the title are ranked official `Trailer` → other `Trailer` → `Teaser` (teasers only matter when no trailer is listed), newest `published_at` first within each tier, duplicates removed. Up to **3** candidates are extracted one after another until one yields a playable stream; the next candidate is tried when extraction throws or nothing playable is found. Only when all candidates fail does Details open the external YouTube app, and catalog previews keep their static artwork. This matters because YouTube uploads flagged *made for kids* (COPPA, common on Disney/Pixar/DreamWorks channels) currently can't be extracted by `NewPipeExtractor` v0.27.1 (`UNPLAYABLE`), while the same title usually has another official trailer that can (e.g. Toy Story 5's `Official Trailer` when its `Final Trailer` is kids-flagged). One `/videos` request per title, unchanged.
    - **Runtime compatibility (Fire OS / Android API < 33):** Trailer extraction must never crash the app. `NewPipeExtractor` v0.27.1 calls `URLDecoder.decode(String, Charset)` / `URLEncoder.encode(String, Charset)`, which Android only ships from API 33 and core library desugaring does not backport; the build rewrites those two calls to an API 1-compatible shim, so extraction works on API 26–32 (Fire OS 7/8). As a guard against any future gap, a `LinkageError` (`NoSuchMethodError`, `NoClassDefFoundError`, `ExceptionInInitializerError`) raised by the extractor counts as a failed extraction: the remaining candidates are skipped (the runtime gap would fail them too), catalog previews silently keep their static 16:9 artwork (never opening YouTube), and Details `Trailer` falls back to the external YouTube app with the top-ranked candidate. Cancellation is never swallowed.
    - **Stream choice per candidate (SDR only, §10):** the tallest decodable SDR adaptive video-only stream (≤ `2160p` full-screen, smaller cap inline) paired with the best M4A audio stream (`MergingMediaSource`). If no such pair exists — no adaptive streams, every adaptive stream HDR or undecodable, or no M4A audio — the tallest decodable SDR progressive/muxed stream is played as a single `MediaSource`. HDR/Dolby Vision streams are never used in either path; a candidate with neither counts as failed.
    - **Catalog Row Previews (`Home`, `Movies`, `TV Shows`):** Uses a single shared lifecycle-aware `ExoPlayer` instance to play extracted trailers inside the focused 16:9 catalog card after the configured `1s–7s` hover delay (`2s` default), honoring *Auto-Play Trailers* and *Mute Auto-Play Trailers*, showing a top-right white muted speaker icon when muted, recording zero watch progress, and failing silently back to static 16:9 artwork without ever launching external YouTube. Playback is bound to a single card via its composite (row ID + item index + item ID) slot plus active D-pad focus (see *Single-Card Binding* in §4), never by title alone.
- **Auto-Play, Auto-Next Episode & Stream Fallback:**
  - **Auto-Play Next Episode (Enabled by Default):** Toggle in Settings (`true` by default). When a TV episode **plays to its end on its own** — the built-in ExoPlayer reaching `STATE_ENDED`, or an external player returning `end_by == "playback_completion"` (for players that send no `end_by`, such as VLC: a reported position within 1 s of the reported duration) — automatically resolve the next episode (the next one in sequence, or — during a `Shuffle` / `Shuffle Season` session — a random aired episode from the whole show / that season, as described under *Next Episode Selection* below), fetch streams, and auto-play the **top stream result** (honoring the preferred auto-play addon setting). Works seamlessly in both internal ExoPlayer and external players (upon receiving the completed `ActivityResult` from the external player). **`Back` in any player — built-in or external, at any position — always exits playback and never triggers Auto-Play Next Episode**; it saves progress, and at `>= 90%` that still marks the episode watched. An elapsed-time estimate (no position returned) never advances either. Watch progress is only ever saved for the stream the built-in player actually holds: while a new episode's streams are being looked up or its Usenet/Debrid release is being opened, the previous episode's position is never written under the new one, and a late end-of-stream event from the previous stream is ignored.
  - **Credits countdown (built-in player only):** the `Next episode` prompt's countdown (see *Skip & Next Episode Prompts*) is the only way Auto-Play Next Episode starts before the episode's end; it follows the same toggle. `Back` still never advances.
  - **Next Episode Selection (shared by the HUD `Next Episode` button and Auto-Play Next Episode, built-in ExoPlayer and external players alike):** Every playback session has a shuffle mode that travels with it across episode and stream changes:
    - **Sequential (`None`, default):** Details `Play`/`Resume`, Episodes episode click / episode menu, Continue Watching, and any in-player `Episodes` overlay pick. The next episode in the season, then episode 1 of the following season; at the last aired episode the user is told they're all caught up.
    - **Show (`Shuffle` on Details):** A random aired episode across all regular seasons.
    - **Season (`Shuffle Season` on Episodes):** A random aired episode of that season only; it never moves to another season.
    - Under either shuffle mode the episode that just played is never picked again straight away, and episodes already played in this shuffle session are avoided until every episode in the pool has played, after which a new cycle starts. When the pool holds only the episode that just played (a one-episode show or season), there is nothing to shuffle to and the user is told they're all caught up (auto-next leaves the player).
    - Each shuffled transition resolves streams lazily for the newly picked episode only, honors *Preferred Auto-Play Addon*, *Automatic Stream Failover* and *Failover timeout duration*, shows the loading screen (backdrop + pulsing logo/title) until the first frame, and updates the player title, `Info` overlay and `Episodes` overlay (opening on the new episode's season) to the newly playing season and episode.
  - **Auto-Play Top Stream & Preferred Addon:** Option to auto-play on manual `Play` click (while long-pressing `Play` still opens the stream list), plus a setting to select *which* preferred addon supplies the top stream. Auto-play starts the movie's/episode's `LAST USED` stream (§6) when the freshly fetched list holds it and only otherwise the top stream (preferred addon first); the same rule applies to `Next Episode`, the Episodes overlay and Auto-Play Next Episode. *Auto-play from Continue Watching* (§3) always auto-plays directly from `Home` (LAST USED, else top stream), independent of this toggle.
  - **Automatic Fallback (Automatic Stream Failover, enabled by default):** While the per-profile *Automatic Stream Failover* toggle is `ON` (default), if a stream fails to buffer/start or throws a playback/decoder error within a configurable timeout (*Failover timeout duration*, default `10s`, selectable `10s` / `15s` / `20s`), the player automatically advances to and plays the next stream in the list; after the last stream it shows a message and leaves the player.
    - **Failure reasons:** every skip, stop and final message names a brief, human-readable reason when one is known, e.g. `Stream 3 didn't start (password-protected archive). Trying stream 4 of 12…`, `Stream 1 failed (HTTP 403 (access denied)). Trying stream 2 of 5…`, and `None of the streams would play (last: 7z archive not supported)` when every stream failed (a run of timeouts with no other reason still reads `None of the streams started in time`). Reasons come from the Usenet/Debrid preflight (`compressed 7z not supported`, `password-protected archive`, `wrong archive password`, `compressed RAR not supported`, `missing articles`, `file not found on Debrid`, …) and from ExoPlayer errors (`HTTP 404 (not found)`, `connection timed out`, `server not found`, `unsupported video codec (HEVC)`, `unsupported container`, `damaged or incomplete file`, …). Unknown messages are shortened and stripped of URLs, keys, tokens and account details first, so a signed link or credential never appears on screen. When a whole source fails in milliseconds (e.g. an indexer whose every release is a passworded 7z set), the single status line is replaced for each skip (never stacked), each stream is reported once, and the run ends with one summary toast.
    - **Failover `OFF`:** No fallback timer runs, so a slow stream keeps loading until it starts or the user presses `Back`, and the player never advances on its own. A playback/decoder error stops playback on that stream and shows a clear status naming the reason when one is known (`Stream N of T couldn't play (password-protected archive). Automatic failover is off — pick another stream.`). The in-player `Streams` overlay then opens so the user can pick any stream by hand, including retrying the failed one. Manual stream selection works exactly as it does with failover on. With the overlay closed, Select/D-pad opens the HUD (its `Streams` button stays reachable). `Back` steps overlay → HUD → leaves the player. Trailers are unaffected.
  - **Playback Buffer Profile (`DefaultLoadControl`):** Configurable read-ahead buffer size in Settings (`Standard` [~50s / 64 MB], `Large` [2 min / 150 MB], `Max` [5 min / 250 MB], default `Large`) with an elevated rebuffer threshold (`5,000ms` on `Large`/`Max`) so ExoPlayer banks video during high-speed bursts to absorb transient ISP/VPS peering dips without stalling. The byte target takes priority over the time thresholds (`prioritizeTimeOverSizeThresholds = false`), and each profile's min and max buffer durations are equal, so ExoPlayer keeps draining the parallel reader's read-ahead ring until the byte target is reached and tops up as soon as playback consumes.
  - **Parallel HTTP Range Reader (`ParallelRangeDataSource`):** Configurable parallel HTTP byte-range connection count (`Off (1x)`, `2x`, `3x`, `4x`, default `4x`) for HTTP/HTTPS media streams. Splits sequential reads into concurrent `Range: bytes=start-end` sub-requests using the shared `OkHttpClient`. The `N` workers run independently of ExoPlayer's read pace: whenever one finishes a chunk, it immediately starts the next sequential range, until the downloaded-but-unread bytes reach a bounded read-ahead ring high-water mark set by the Playback Buffer Profile (`Standard` 24 MB, `Large` 64 MB, `Max` 128 MB; capped at a quarter of the app heap but never below 4 MB per connection; no ring at `1x`). The first 16 MB after every open or seek are fetched as 4 MB chunks for a fast first frame, and later chunks are 8 MB (or smaller when needed to fit one chunk per connection under the high-water mark), so connections spend more time at peak TCP throughput. Every chunk buffer, whether in flight or pooled, counts toward the high-water mark. A seek or close cancels all in-flight ranges at once. The reader transparently falls back to single-stream sequential reading if the upstream server omits `Accept-Ranges: bytes` / `206 Partial Content` or for local/non-HTTP URIs.
- **Skip & Next Episode Prompts (built-in player, movies & episodes only; Milestone 14):** Five D-pad prompts appear bottom-right over the video: `Skip intro`, `Skip recap`, `Skip to post-credits`, `Skip credits` and `Next episode`. Trailers and external players never show them.
  - **Where the times come from:** the file's own Matroska/WebM chapters (titles that are just the label: `OP`/`Opening`, `Intro` when there is no `OP`, `Recap`/`Previously on…`, `ED`/`Ending`/`Credits`/`End Credits`, and `Post-/Mid-/After-credits` for a post-credits scene; read once per stream after its first frame with two small range reads; never for Usenet streams), and IntroDB (`api.introdb.app/segments`, public and keyless, sent only the title's IMDb id plus season/episode, skipped while *Online skip times* is off). Episodes prefer chapters, movies prefer IntroDB; the other fills any missing kind. IntroDB times running more than 2 s past this file's end (another cut) are dropped; intros/recaps must start in the first half of the file and credits in the second. Credits overlapping a post-credits scene end where it starts. Anything missing or unreachable just means fewer prompts; no error is ever shown.
  - **Skip intro / Skip recap:** inside the segment until 2 s before its end; seeks to its end.
  - **Skip to post-credits:** during the credits when a post-credits scene is known (IntroDB `post_credits` or a chapter); seeks to the scene. A gap after the credits is never guessed to be a scene.
  - **Skip credits:** during the credits with no known scene. A movie seeks to its end (it finishes and is saved as watched). An episode offers it only when at least 20 s of programme follows the credits, and seeks past them.
  - **Next episode (TV episodes only, when a next episode exists):** from the credits start (when less than 20 s follows them), after a post-credits scene ends, or with no credits data in the last 30 s. It shows the next episode's badge (`S1:E4`): the very episode that will play, picked once per playing episode, so a `Shuffle` / `Shuffle Season` session draws once and the HUD `Next Episode` button plays the same pick. Pressing it saves the episode as watched and plays the next one's `LAST USED` stream, else its top stream (preferred auto-play addon first), exactly like *Next Episode Selection*.
  - **Countdown:** with *Auto-play next episode* on, a `Next episode` prompt opened by credits data counts down `Playing in 10s` (paused while playback is paused) and then plays the next episode as Auto-Play Next Episode does. Any remote key press turns it into a plain button. The last-30-s fallback never counts down (the natural end still auto-plays).
  - **Modes (§11):** `Skip intro & recap` and `Skip credits` are each `Off`, `Show button` (default) or `Auto-skip`. Auto-skip seeks once per segment and shows a status pill (`Skipped intro`); seeking back into a segment already skipped shows the button instead. Credits auto-skip of an episode with *Auto-play next episode* on goes straight to the next episode. `Next episode prompt` turns the Next episode prompt off.
  - **On screen:** a prompt shows for 8 s of unpaused playback once its stretch begins (the countdown keeps it up). It shows again whenever the HUD is visible and hides while any right-hand overlay (Subtitles, Audio, Speed, Streams, Episodes, Info) is open, during the initial load, after a failed stream and during an episode switch.
  - **Remote:** with the HUD hidden the prompt takes focus when it appears, but never within 1.5 s of a key press (so seeking is never interrupted). `OK` acts. `Left`/`Right` seek 10 s and open the HUD on the seek bar, and `Up`/`Down` open the HUD, exactly as without a prompt. With the HUD visible the prompt sits just above the seek row: `Up` from the seek bar reaches it and `Down` returns. The prompt ignores a select-key release whose press began elsewhere (`ignoreInitialKeyUp`), so the `OK` that opened the HUD never skips. `Back` while a prompt shows (focused or not, HUD shown or hidden) dismisses only the prompt; playback continues. A dismissed prompt stays hidden for the rest of its stretch, even when the HUD opens, and a running Next episode countdown stops (the episode then plays on only at its natural end, as usual). A focused prompt that goes away (Back, `OK` or timing out) returns focus to the player (HUD hidden) or `Play / Pause` (HUD visible), so focus never lands on nothing.
- **Audio DSP & Sync (Requires Audio Passthrough Toggle):**
  - Toggle to disable HDMI audio passthrough so PCM audio can be processed on-device.
  - **Effects switch passthrough off automatically:** turning on Dialogue Boost (any level but Off), Night Mode, Volume Boost (any level but Standard), or a non-zero Audio Delay switches Audio Passthrough off at once, so the effect is heard immediately. This happens in General Settings (saved per profile) and in the player's Audio overlay (this video only, applied live without restarting: the audio drops out briefly while it switches from bitstream to decoded PCM). The user can switch passthrough back on afterwards (Settings row, or the overlay's *Audio passthrough* toggle) and it stays on until another effect is turned on.
  - **Software Audio Decoding Fallback (FFmpeg):** Dolby Digital (AC-3), Dolby Digital Plus (E-AC-3, incl. Atmos/JOC), Dolby TrueHD, DTS and DTS-HD tracks never fail or play silent. When passthrough is off, or the connected TV/AVR/sink can't bitstream the codec and the device has no hardware decoder for it, the track is decoded in software (prebuilt FFmpeg Media3 decoder) to PCM. When passthrough is on and the sink supports the codec, it is still bitstreamed untouched. Dialogue Boost, Night Mode and Audio Delay apply to any PCM output, including FFmpeg-decoded tracks while passthrough is on. Multichannel PCM goes to multichannel outputs unchanged; for stereo-only outputs it is downmixed in-app with clip-safe normalised coefficients (no clipping even at full scale on every channel).
  - **Dialogue Boost:** Off, `+3 dB`, `+6 dB`, `+9 dB`, `+12 dB` center-channel/vocal frequency gain.
  - **Night Mode:** Dynamic range compression evening out loud explosions and quiet speech.
  - **Volume Boost:** `Standard` (default, x1.0 / 0 dB), `+25%` (x1.25), `+50%` (x1.5), `+75%` (x1.75), `+100%` (x2.0) overall linear gain, applied after Dialogue Boost and Night Mode and followed by the same soft limiter, so boosted peaks bend smoothly towards full scale and never wrap or clip harshly. The profile's *Default volume level* applies to every video it plays; the Audio overlay changes it for the current session only.
  - **Audio Delay:** Adjustable `-500ms` to `+500ms` (in `25ms` steps) to sync Bluetooth/wireless headphones. The delay stays the same in wall-clock time at any playback speed.
- **Playback Speed:** `-25%` (0.75x), `Standard` (1.0x, default), `+25%` (1.25x), `+50%` (1.5x), `+75%` (1.75x), `+100%` (2.0x); the speed is `1 + percentage` and the audio pitch always stays normal (time-stretched, not sped up). The profile's *Default playback speed* applies to every movie and episode it plays; the in-player `Speed` overlay changes it for the current session only. Trailers always play at 1.0x. Only decoded PCM can be time-stretched, so a session that starts at, or is switched to, a speed other than `Standard` turns Audio Passthrough off **for that session only** (the saved passthrough setting is never changed); the user can switch session passthrough back on, after which speed has no effect while the audio is bitstreamed.
- **Subtitles & HDR:**
  - Global toggle: *Always On* (if available) or *Always Off* (default *Always Off*).
  - Preferred Subtitle & Audio Language settings (both default English): Preferred subtitle language always sorts to the top of the player track list; toggle to *Hide non-preferred subtitle languages* (default `ON`).
  - **Clean SDH Toggle (default `ON`):** Regex/parser filter stripping bracketed/parenthetical sound cues (`[SIGHS]`, `(DOOR CREAKS)`, `♪`) and speaker labels (`JOHN:`) from `.srt`/`.vtt` cues in real time.
  - **Subtitle Styling:** Font size, bold, italic, text color, outline/drop-shadow, and background opacity configurable in General Settings (persistent default; out of the box `100%` size, bold `ON`, italic `OFF`, white `#FFFFFF` text, outline edge, `0%` background opacity) AND inside the Player OSD (session-only override that resets when exiting playback).
  - **Auto-Sync External Subtitles:** With *Auto-sync external subtitles* on (per-profile, default on), an active external (addon) subtitle track is synced automatically while it plays, with no user action and no pause, restart or re-buffer:
    - **Embedded reference first:** when the stream has a full embedded subtitle track (text or Blu-ray PGS bitmap subtitles; never a forced, signs/songs, foreign-parts or commentary track), its cue start times (played in the background, never shown) are correlated with the external cues' start times, so differing display durations and line breaks don't matter. A track in the same language is preferred. Without one, a full track in any other language is used (also when the external track's language is unknown), because a translation of the same release still follows the speech far better than audio; such a reference needs two agreeing checks before it applies anything. If that track shows fewer than 5 lines in its first 20 s, or hasn't locked within 30 s, auto-sync switches to audio at once. Audio has been listening from the start, so it can lock quickly. A same-language track that simply hadn't locked by 30 s keeps playing in the background for up to 2 minutes, so a file timed for another frame rate (see below) can still lock against it.
    - **Audio voice activity otherwise:** decoded PCM speech-energy vs. silence (a non-intrusive tap) is cross-correlated with the external cue intervals across `-60.0s` to `+60.0s` (the manual range) in `0.1s` steps, on a background thread. Offsets beyond ±30 s are only accepted on the fuller one-minute check.
    - **Spoken lines only:** sound-effect captions (`[DOOR SLAMS]`), music-note-only lines and on-screen text held 10 s or longer are left out of the timing analysis (never out of what is shown), since they mark no speech. A file that is mostly captions is analysed whole.
    - **Frame-rate mismatch:** a file timed for a 25 fps (PAL) release drifts ~2.6 s a minute against a 23.976/24 fps video, which no single offset fixes. Once a minute of reference is in, auto-sync also tries the 25↔23.976 and 25↔24 fps clocks (every 20 s while scanning, on every refine and drift check) and applies the clock together with the offset. A non-unit clock needs the full check, a clearly better match than the unit clock, and a clear lead over the opposite direction; the Info row then names it (e.g. `· 25→23.976 fps`).
    - **Fast lock, strict confidence:** analysis runs every 5 s. A first lock is allowed once ~15 s and at least 5 subtitle lines have been heard, but only when the match is unambiguous and most subtitle lines start on a speech (or embedded-cue) onset. Audio also needs two agreeing passes. The fuller check additionally needs both halves of the analysed window to agree on the offset on their own (within 0.4 s), which rejects a wrong frame rate or a timing jump inside the window. Typical dialogue locks in ~20 s, including after a seek. Music/action intros, silence and unrelated audio never cause a shift; otherwise the offset stays `0.0s`.
    - **Lands on dialogue starts:** every detected offset is snapped (in 50 ms steps within ±1.5 s, then rounded to 0.1 s) to when lines actually begin, matching subtitle start times against the embedded track's starts or the audio's speech onsets. Differences in how long lines linger on screen therefore never pull it off by tenths of a second.
    - **Refining:** after a fast lock, a fuller check every 20 s (once a minute of data is in) confirms the value or corrects it, unless the user has nudged the offset.
    - **Drift and jumps:** after locking, the last 2 minutes are re-checked every minute, and the offset is gently re-centred (0.1–1.5 s steps, confirmed twice) when a file drifts against the video (e.g. 23.976 vs 24 fps); the Info row shows `· tracking`. A larger jump (a scene the file's release has and the video doesn't, or the reverse) is followed only after three agreeing checks. This stops as soon as the user nudges the offset.
    - The detected shift moves every cue's start/end before Clean SDH filtering and refreshes the visible cue at once.
    - **Live status:** the HUD sync control shows a small caption under the value: `Syncing…` while scanning, `Auto` once locked, nothing when idle. The Info overlay's *Subtitle sync* row spells it out (e.g. `Syncing… · embedded (0 cues), 20 s`, `Syncing… · audio (18 cues, best +5.1s @ 0.42, 60% onsets), 25 s`, `+2.3s · Auto (embedded subtitles) · refining`, `+1.4s · Manual`, `0.0s · no confident match`), including the line count and best candidate while scanning so on-device problems are visible.
    - A manual `-`/`+` nudge always works, starts from the shown value (keeping any detected frame-rate clock), and stops further automatic changes for that track. Session-only, like the manual offset; a new stream of the same title re-detects unless the user nudged.
    - **Picking a track again:** each stream + external track remembers its result for the session. An auto result is applied at once and drift tracking resumes without a new scan. If the user nudged that track, *their* offset (and clock) comes back with `Manual`, never the earlier auto value, and nothing is re-detected.
  - **Convert Dolby Vision Profile 7 to HDR:** Toggle (enabled/`true` by default) that converts or falls back Dolby Vision Profile 7 (`dvhe.07` / `dvh1.07`) video tracks to standard HDR10/base-layer playback for compatibility with displays/devices that do not support Profile 7 FEL/MEL (see §10 *Dolby Vision Playback*).
  - **Dolby Vision Playback:** `Auto` (default) / `Always Dolby Vision` / `HDR10/HLG base layer` selector deciding whether Dolby Vision Profile 8 plays natively or as its HDR10/HLG base layer (§10).
  - **HDR White Dimming:** Dims the bright whites of the player **UI** (never the video) during HDR10, HDR10+, HLG and Dolby Vision playback (§10).

Wrap targets always follow the bar's current layout (`Next Episode`/`Episodes` only for TV episodes, `- 0.0s +` only while an external subtitle is active). The simplified trailer HUD bar is `Play / Pause` alone, so both directions keep focus there. Held `Left`/`Right` stops on the edge control.
  - **Bottom Action Bar Items (Left to Right):**
    1. **Play / Pause:** Dynamic toggle icon reflecting live playback state (`Pause` icon while playing, `Play` icon while paused).
    2. **Next Episode:** Appears only when playing a TV episode (hidden for movies); resolves and plays the next episode's top stream, picked exactly like Auto-Play Next Episode (sequential, or random during a shuffle session — see *Next Episode Selection*).
    3. **Subtitles:** Opens a non-blocking player overlay to switch subtitle tracks (internal + Stremio addon tracks, honoring preferred language sorting and *Hide non-preferred languages*), toggle *Clean SDH*, and adjust **session-only Subtitle Styling** (resets on player exit without overwriting General Settings). It opens scrolled to the **active track** with focus on it (`Off` when subtitles are off), and the key press that opened it never selects a track. Its list wraps both ways under the §1 rule (`Off` ⇄ `Background`; held keys stop at the edge). The title's subtitle choice, including an explicit Off, is remembered for the session: when another stream of the same title loads (fallback or stream switch), the matching track (same source and language, same name first) is re-selected instead of the *Always On/Off* default.

Displays `-` (slow down / delay subtitles) and `+` (speed up / advance subtitles) flanking the live offset value (`0.0s` default), adjusting in `0.1s` increments across `-60.0s` to `+60.0s` (session-only, resets on playback exit). With *Auto-sync external subtitles* on, the value starts at the auto-detected offset (a small caption under the value shows `Syncing…` while detecting and `Auto` once applied, inside the same fixed-width slot so the bar never grows); with it off, it starts at `0.0s`. Manual steps work the same either way.
    5. **Audio:** Opens a non-blocking player overlay to select audio tracks and adjust **session-only** audio settings (*Dialogue Boost*, *Night Mode*, *Volume Boost* and *Audio Delay*), starting from the profile's General Settings values (*Default volume level* for Volume Boost). Any adjustments made here are strictly session-only—they do not persist to future playback, and General Settings audio values take priority once playback exits.

It starts at the profile's *Default playback speed*. Choosing a speed applies it at once. The change is **session-only**: it is never written to General Settings, it carries over stream fallback, stream switches, episode switches and Auto-Play Next Episode within the same player session, and it resets to the profile default once playback exits. One `Back` press closes the overlay and returns focus to the `Speed` button; a held `OK` from before it opened never picks a speed. Not shown on the trailer HUD.

The overlay uses the exact same modal container as the Details stream selection modal (§6): a `760dp` right-hand `SurfaceCard` panel over a `60%` black scrim (playback keeps running behind it), `20dp` horizontal / `32dp` vertical padding, a "Choose a stream" header over the title and episode line, the same two columns (§6 Two-Column Stream Panel: a left `Addons` column with one `Addon name (count)` card per enabled stream addon in installed order, and the right `Choose a stream` column listing only the selected addon's streams, or `"<Addon name> returned no results"` for an empty one), `8dp` spacing between cards, and the same §6 Stream Panel D-Pad Map. Ranks count across the full list, so `#4` stays `#4` whichever addon is selected. A stream becomes `LAST USED` as soon as it reaches `Ready`, so after a switch or fallback the badge follows the stream that is actually playing. Focus stays inside the overlay, a held `OK` from before it opened never picks a stream, and one `Back` press closes it and returns focus to the `Streams` button.

Picking an episode here ends any active shuffle session: from that episode on, `Next Episode` and Auto-Play Next Episode are sequential again.
       - **Opening focus:** the card always opens on the season currently being watched (even if another season was browsed last time), with the season pill row scrolled horizontally so that season's pill is in view and focused; once the season's episodes load, the list scrolls to the episode currently being watched and focus moves onto it (unless the user has already pressed a key in the card).

A fresh `Up` on the first episode moves to the highlighted season pill (held `Up` stops on the first episode). A fresh `Up` on any season pill scrolls the episode list to the bottom and focuses the last episode of the listed season (held `Up` stops on the pill; while the list is loading or empty the press is consumed and focus stays on the pill). A fresh `Down` on the last episode scrolls back to the top and focuses the first episode of the same list, never the season row (held `Down` stops on the last episode). The season row wraps horizontally: a fresh `Left` on the first pill → the last pill and a fresh `Right` on the last pill → the first (scrolling the row as needed); a single season consumes both, and focus never leaves the card.
       - **Season row bounds:** the pill row spans the card's full width with the card's side padding as inner content padding (plus a small top/bottom clearance), so the first and last season pills, focused or not, are never clipped on any edge.
    9. **Info:** Opens an in-player technical metadata overlay displaying technical playback telemetry: in this order: selected stream title/source rank (e.g., `Stream #1 of 12`), player engine (`Media3 ExoPlayer`), then the live network rows — **live download throughput (`Mbps` rolling 2-second average)**, **active HTTP range connections (`1x`–`4x`; not shown for Usenet releases, which are read over NNTP)** and **live buffer health (`buffered seconds` & `buffered MB`)** — then source filename, file size (`58.42 GB` / `734 MB`, 1024-based; the same size the Bitrate row uses: the file's data source, else the addon/indexer/Debrid size, else the release name; `—` when unknown), video codec, dynamic range, resolution, bitrate, audio codec, channel layout, sample rate, audio language, active subtitle name, subtitle language, subtitle source (`Embedded` or `External`) and subtitle sync (offset + auto-sync state).

When ExoPlayer reports none (common for Matroska/WebM, Usenet and Debrid files) it is estimated as `file size × 8 ÷ duration` and marked `42.5 Mbps (est.)`. The size is the one the file's own data source reports (HTTP `Content-Length`/`Content-Range`, the Usenet file's length), else the addon's `videoSize` / the indexer's or Debrid size, else the size parsed from the release name. The duration is ExoPlayer's once known, else the TMDB runtime. With neither known it shows `—`.
       - **Layout (shared by `Subtitles`, `Audio`, `Speed`, `Episodes` and `Info`):** these cards reach further down than `Streams`: their bottom edge sits a clean 12 dp gap above the seek bar / remaining-time row (measured from the live HUD layout, so they never overlap or clip the time text, progress bar or bottom controls). `Streams` ends above the bottom action bar. Their rows scroll (`Up`/`Down`) to fit a 960×540 dp screen. While a card's rows overflow, a slim vertical scrollbar (track + proportional thumb) on its right edge follows each scroll step; it is hidden when everything fits. It is drawn in the HUD layer, so HDR White Dimming covers it. An active subtitle is drawn to the left of the card, never under it.

## 10. Video Output, HDR & Dolby Vision
- **Video Surface:** The built-in player always renders video through a `SurfaceView` (hardware overlay path), so HDR10/HDR10+/HLG static and dynamic metadata and Dolby Vision reach the display pipeline untouched and the TV applies its own tone mapping. Nothing is ever drawn over the video picture except the player UI listed below. The app window keeps `Window.colorMode = COLOR_MODE_DEFAULT` at all times: `COLOR_MODE_HDR` only changes how the app's own UI is rendered and is not needed for HDR video.
- **Dynamic Range Detection:** The playing stream is classified from its selected video track and the decoder's input format: `Dolby Vision` when the track is `video/dolby-vision` or its codecs start with `dvhe.`, `dvh1.`, `dvav.`, `dva1.` or `dav1.` (also while Profile 7/8 plays as its HDR10/HLG base layer), else `HDR10` for a PQ (`ST 2084`) transfer (HDR10 and HDR10+), else `HLG` for an HLG transfer, else `SDR`. It is live state: it updates as soon as the tracks or the video format change, and resets to `SDR` for every new stream.
- **HDR White Dimming (per profile, default `On`):** While on and the playing stream is HDR10/HDR10+/HLG/Dolby Vision, every bright white of the player UI is dimmed to `75%`: the HUD buttons, seek bar and time labels, the loading/buffering logo and pause badge, status pills, toasts, subtitle text, the Skip / Next episode prompts (§9), and all non-blocking overlays (`Subtitles`, `Audio`, `Streams`, `Episodes`, `Info`). The video picture itself is never dimmed, so HDR brightness matches other players. SDR playback and every non-player screen are unaffected. Dimming is visual only: D-pad focus and key handling are unchanged.
- **Leaving Playback Returns the TV to SDR:** Whenever playback ends (`Back` exit, cancelling during the initial load, a finished movie/episode/trailer, every stream failing, or leaving the app), the video surface is detached from the decoder and removed in the same frame, before the previous screen shows, and the player is then released. The window's color mode, brightness override and HDR headroom are reset to their defaults. No HDR/Dolby Vision layer is left on screen, so a TV following "match content dynamic range" drops back to its normal SDR UI brightness on Details, Home and every other screen.
- **SDR-Only Trailers:** YouTube trailer streams (full-screen and inline catalog previews) never use HDR formats (VP9 Profile 2, 10-bit HDR AV1, Dolby Vision), so menu screens never switch the TV into HDR.
- **Dolby Vision Playback (per profile, default `Auto`):**
  - **Profile 5:** always plays as Dolby Vision (it has no compatible base layer).
  - **Profile 7 (`dvhe.07` / `dvh1.07`):** plays as its HDR10 base layer while *Convert Dolby Vision Profile 7 to HDR* is on (default) or the mode is `HDR10/HLG base layer`; otherwise natively.
  - **Profile 8 (`dvhe.08` / `dvh1.08`):** `Always Dolby Vision` plays it natively. `HDR10/HLG base layer` plays its HDR10 (PQ) or HLG base layer through the standard HEVC decoder, keeping the stream's own color and mastering metadata. `Auto` plays it natively only when the connected display reports Dolby Vision support, else as the base layer. A Profile 8 track whose base-layer transfer is unknown always plays natively, so an SDR base layer is never mislabelled as HDR.
  - Other profiles (AVC/AV1 Dolby Vision) always play natively.
  - The `Info` overlay's *Dynamic range* row (below *Video codec*) shows the path in use, e.g. `Dolby Vision 8 → HDR10 base layer`, `Dolby Vision 7 → HDR10`, `Dolby Vision (native)`, `HDR10`, `HLG`.

## 12. Usenet Streaming (NNTP) — Sources
SeaStreams streams Usenet releases natively: Newznab indexer search → NZB → yEnc articles fetched from the user's NNTP providers. They play in the built-in ExoPlayer, and in external players through a loopback proxy. Everything in this section is **app-wide** (shared by all profiles), because provider connection limits belong to the account and the device. Delivered across Milestones 7–9; the `Enable Usenet` toggle and `Clear Usenet settings` (§11 `Sources`) arrive in Milestone 11.

- **Providers (NNTP):**
  - Fields: name, host, port (default `563`), TLS (default on), username, password, *Max connections* (`1..100`, default `20`), *Pipeline depth* (`1..16`, default `2`; requests kept in flight per connection), priority (`0..99`, lower = preferred), *Backup* flag, enabled.
  - Providers with the same priority share load. Backups are used only for articles the primaries can't supply.
  - Passwords are encrypted at rest with an Android Keystore key. A password that can't be decrypted (e.g. after a restore to a new device) shows as *Password needed*.
  - **Provider presets** fill in name, host, port `563`, TLS and max connections. The 29 entries are: Newshosting, Easynews, Tweaknews (Newshosting deal), Tweaknews (standalone), Eweka, UsenetServer, Giganews, Frugal Usenet, NewsDemon, Usenet.Farm, UsenetExpress, NewsgroupDirect, Newsgroup Ninja, Supernews, Pure Usenet, Sunny Usenet, XS News, ThunderNews, Astraweb, ViperNews, Cheapnews, Fast Usenet, UsenetNow, UsenetPrime, Easy Usenet, Bulknews, XLned, 123 Usenet, Hitnews. Every field stays editable.
- **Indexers (Newznab):**
  - Fields: name, base URL (`https://` or a LAN `http://` address), API path (default `/api`), API key (encrypted like passwords), priority, *Backup only* flag (searched only when no other indexer returned results), enabled.
  - **Indexer presets** fill in the API URL: abNZB, altHUB, AmeNZB, Anime Tosho, Aninzb, ClubNZB, Digital Carnage, DOGnzb, DrunkenSlug, GingaDADDY, Miatrix, NewzBay, NinjaCentral, NZB Atlas, Nzb.life, NZBFinder, NZBgeek, NzbNest, NzbNoob, NzbPlanet, NZBStars, PourCeSoir, SearchNZB, SquareEyed, Tabula Rasa, Treasure Maps, Usenet Crawler, Videothek, plus the LAN templates `NZBHydra2 (your server)` and `Prowlarr (your server)`.
- **Request headers:**
  - Indexer **searches** send the `Search` preset's headers (default `Prowlarr`). NZB **downloads** send the `Download` preset's (default `SABnzbd`).
  - Presets:

    | Preset | User-Agent |
    |---|---|
    | Prowlarr | `Prowlarr/{v} (alpine 3.24.4)` |
    | NZBHydra2 | `NZBHydra2 {v}` |
    | Sonarr | `Sonarr/{v} (alpine 3.24.4)` |
    | Radarr | `Radarr/{v} (alpine 3.24.4)` |
    | SABnzbd | `SABnzbd/{v}` |
    | NZBGet | `nzbget/{v}` |
    | SeaStreams | `SeaStreams/{app version}` |

    Prowlarr/Sonarr/Radarr/NZBHydra2 also send an RSS `Accept` header; SABnzbd/NZBGet send `Accept: */*`. `Accept-Encoding` is left to OkHttp (transparent gzip).
  - **Version auto-updater:** at most once every 24 h (on app start, and when the `Sources` tab opens), SeaStreams reads the latest stable release version of each tool from its public GitHub `releases/latest` endpoint, sending a generic `SeaStreams` User-Agent and no user data. Only a plain version (`2.7.0.5723`, a leading `v` stripped) is accepted.
  - A failed check keeps the last good version. The built-in fallbacks are Prowlarr `2.7.0.5723`, Sonarr `4.0.20.3014`, Radarr `7.0.3.10918`, SABnzbd `5.1.3`, NZBGet `26.3` and NZBHydra2 `9.3.1`.
  - `Update header versions` checks immediately.
- **Performance profiles:**
  - One profile governs every value of the `Usenet performance` sub-panel. Picking `Conservative` (default), `Balanced` or `High` overwrites all of them. Editing any single value switches the profile to `Custom` and keeps the edited values. Fresh installs and unreadable stored values get `Conservative`.
  - **Android TV memory:** the Google TV Streamer 4K gives the app a 512 MB heap. The old `High` (64 segments, unbounded downloads, census 12) caused GC lag and `OutOfMemoryError` there, so every template bounds its concurrent downloads (none uses `0` = auto) and keeps read-ahead ≤ 32 and census ≤ 6. Whatever the values, the in-memory segment cache is capped at a tenth of the heap (≤ 64 MB) and only the volume being played reads ahead.
  - The sub-panel is one list grouped under the screenshot sections (`aio-usenet-settings1–6.png`): **Performance**, **Connections & timeouts**, **Reliability**, **Archive handling**, **Verification**, **Import**.
  - Numbers and choices are `‹ value ›` steppers (`Left`/`Right` step, `OK` steps forward and wraps). Switches are toggles.
  - The list follows the §11 one-way bottom-to-top wrap. `Up` on the first row (`Performance profile`) is consumed, and `Back` returns to the `Usenet performance` row.

  | Setting | **Conservative** | Balanced | High | Custom range |

  | Read-ahead (segments) | 16 | 24 | 32 | 1–256 |
  | Max concurrent downloads (`0` = auto: Σ connections × depth) | 30 | 36 | 48 | 0–400 |
  | Segment disk cache | 512 MB | 1 GB | 2 GB | Off–4 GB |
  | Warm connections | 0 | 2 | 4 | 0 / 2 / 4 |
  | Streaming priority share | 0.90 | 0.80 | 0.80 | 0.50–1.00 |
  | Segment timeout | 30s | 30s | 15s | Never–120s |
  | Segment stall timeout | 30s | 30s | 10s | 5–60s |
  | Dial timeout | 15s | 15s | 15s | 5–60s |
  | Idle connection TTL | 1m | 1m | 1m | 15s–10m |
  | Stream idle timeout | 1h | 1h | 1h | Off–4h |
  | Circuit breaker threshold | 5 | 5 | 5 | 1–20 |
  | Circuit breaker cooldown | 30s | 30s | 30s | 10s–5m |

  | Matroska hole repair | On | On | On | toggle |

  | Max concurrent imports (`0` = unlimited) | 2 | 4 | 4 | 0–8 |

- **Storage bound:** the segment disk cache never exceeds the profile value, 25% of the device's free space, or whatever leaves 2 GB free, whichever is smallest. It is cleared by `Clear cache` (§11). The NZB cache keeps at most 40 files for 14 days.
- **Playback (Milestone 9):**
  - Usenet releases appear under a built-in `Usenet` card in the stream panel's Addons column only while `Enable Usenet` is `ON` (§11) and at least one provider and one indexer are enabled. The card, its results, `Preferred auto-play addon` and the `Addon` sort criterion follow the `Usenet` entry's position in the profile's addon list (§8; the bottom by default). A profile that switched the entry off is not searched.
  - Addon streams carrying an `nzbUrl` play through the same engine. While `Enable Usenet` is `OFF`, an `nzbUrl` stream that would need the user's own providers is dropped from the list; one that brings its own `servers` still plays (those servers belong to the addon).
  - Plain files, stored (uncompressed) RAR4/RAR5 sets, including obfuscated names, raw `.001` splits, and stored 7z archives (a single `.7z` or a `.7z.001`, `.002` … set, also found by signature inside splits or obfuscated files) are streamable.
  - **Password-protected 7z:** a stored 7z whose contents (and optionally headers) are encrypted plays when the NZB carries its password (`<meta type="password">`). The password unlocks the archive on the TV, the video is decrypted as it is read (seeking stays instant), and the password is never shown, logged or stored apart from the cached NZB.
  - *Not streamable* (dropped, and failover moves on): compressed 7z archives (LZMA, LZMA2, …), a password-protected 7z when the NZB has no password or the wrong one, and compressed or password-protected RARs (even with an NZB password: RAR decryption is not implemented).
  - **Search never grabs NZBs.** Stream search reads only the Newznab search XML and drops releases already known bad. Releases the indexer flags as passworded are kept, because their NZB may carry the password, but are listed after the clean releases from indexers of the same priority. It never downloads an NZB (`t=get`), so indexer grab quotas are spent only when a release is played. Some indexers (e.g. NinjaCentral) list 7z or password-protected uploads under clean scene titles, so these can only be identified once their NZB is grabbed.
  - **Pre-playback resolution (silent skip).** Before any player is given a `seastreams-nntp://` stream, SeaStreams opens its release: it grabs the NZB, which is then cached, parses it, assembles the media and runs the *Verify budget* census. This happens for the built-in ExoPlayer, at the start of auto-play or a pick, at every fallback advance, and for Streams-overlay switches. It happens the same way for external players.
    - A release that is refused (compressed 7z, 7z without its password or with a wrong one, compressed or encrypted RAR, articles missing beyond the damage policy, not an NZB) is recorded as unplayable for 6 h. ExoPlayer is never prepared with it, so there is no playback error, player re-init or audio-focus change.
    - With *Automatic stream failover* on, the next stream is tried at once. The loading screen or the player's status pill reads `Stream N didn't start (<reason>). Trying stream N+1 of T…` (e.g. `(compressed 7z not supported)`, `(password-protected archive)`, `(wrong archive password)`, `(missing articles)`), and `None of the streams would play (last: <reason>)` when none is left. With failover off, the stopped status names the reason too.
    - With failover off, playback stops on that stream and the Streams overlay opens (§9).
    - A release already known bad is skipped without being opened again.
  - External players reach Usenet streams at `http://127.0.0.1:8765/nntp/<token>/<name>`. The route answers loopback clients only; other clients get `403`. A foreground notification keeps it alive while the external player runs.
- **Out of scope:** the SABnzbd-compatible download API, *Hold SABnzbd hand-off for the census*, *Library recheck* (SeaStreams keeps no saved NZB library), and compressed 7z archives (no temporary extraction).

## 13. Stream Filtering, Sorting & Formatter (Milestone 10)
Per profile (`p{id}/` keys), edited from `Settings → UI` (`Stream filters`, `Stream sorting`, `Stream formatter`) and the Web Portal. Applied to every resolved stream list (Stremio addons, Usenet and, from Milestone 12, the Debrid library, §14) in this order: parse → filter → deduplicate → sort → result limits → format. Auto-play, failover order, LAST USED and the Addons column counts all use the processed list. The defaults are no filters, no sorting and the original addon text, so behaviour only changes once the user opts in.

- **Master toggles:** `Enable stream filtering`, `Enable stream sorting` and `Enable stream formatting`, per profile, each default `ON` (so upgraded profiles behave exactly as before). Turning one `OFF` bypasses only that stage and keeps every stored filter, sort criterion and formatter (preset or custom templates), so turning it back `ON` restores the same results:
  - Filtering `OFF`: no Required/Excluded/Included filters, no deduplicator, no result limits, and the *Preferred* lists (attribute lists, regexes, keywords) are ignored too, so preference-based sort criteria rank nothing.
  - Sorting `OFF`: the addon/source order is kept.
  - Formatting `OFF`: stream cards show the addon's own name and description.
  - Releases are parsed only when an enabled stage has something to do; with all three `OFF` the list is returned untouched.
  - Edited on the TV (`Settings → UI`) and in the Web Portal (a checkbox at the top of the Filters, Sorting and Formatter sections, saved as soon as it is ticked).

- **Filters** (`aio-filters.png`):
  - Groups: Stream type, Seeders, Age, Resolution, Quality, Encode, Visual tag, Audio tag, Audio channel, Language, Subtitle, Size, Bitrate, Keyword, Release group, Regex, Result limits, Deduplicator.
  - Each attribute filter has *Required*, *Excluded*, *Included* (kept regardless of every other filter) and *Preferred* (ordered, used by sorting) lists.
  - Languages are excluded only when every language of the stream is excluded, and required when any one matches.
  - Size limits can be set per resolution, separately for movies and series. Bitrate is estimated from size ÷ TMDB runtime.
- **Sorting** (`aio-sorting.png`):
  - `Global`, `Movies`, `Series` and `Anime` lists. A non-empty type list replaces `Global`.
  - Criteria: Quality, Resolution, Language, Subtitle, Visual tag, Audio tag, Audio channel, Encode, Stream type, Size, Bitrate (estimate), Seeders, Age, Addon, Keyword, Regex patterns. Each has its own direction.
  - Preferred-list criteria rank by position in the matching Preferred list.
- **Formatter** (`aio-formatter.png`):
  - Name and description templates use the AIOStreams template syntax: `{stream.resolution::=2160p["4K"||""]}`, `::exists`, `::join(' | ')`, `::rbytes`, `::time`, `{? … ?}` groups, `{tools.newLine}`.
  - Predefined: Torrentio, GDrive, Light GDrive, Minimalistic GDrive, Prism, Custom. The TV picks a predefined formatter with a live preview card; custom templates are typed in the Web Portal.
  - `{stream.indexer}` is the indexer / tracker a stream came from: the Newznab indexer of a built-in Usenet result (`NZBgeek`, `DrunkenSlug`), or the one a Stremio addon names in its text (`⚙️ ThePirateBay`). Built-in Usenet streams stay grouped under the single `Usenet` card in the Addons column, but every predefined formatter shows the indexer where it would show the addon name `Usenet`; the Custom default ends with the indexer for Usenet streams and `Addon · Indexer` when another addon states one.
  - **Spaces in custom templates are kept as typed:** between fields (`{stream.resolution}   {addon.name}`), inside `{? … ?}` groups (they render and disappear with the group), in check branches (`["  4K  "||""]`), separators (`::join('  ·  ')`) and literal prefixes/suffixes, and at the start of a line, in both the name and the description. Only whitespace at the end of a line is trimmed, and lines left empty (e.g. every field absent) are dropped. The Web Portal preview shows runs of spaces exactly as the TV card will. Each preview line is its own block in a `4px`-gap grid, so the Name and Description stay compactly stacked at every viewport width. On a phone, the long release filename wraps within its own line and never opens a blank gap.
- **Result limits:** total, per resolution, per quality and per addon, each stepped on the TV through Off → 1, 2, 3, 5, 10, 20, 30, 40, 50 (typed freely in the Web Portal; empty or `0` = unlimited, capped at 1,000).
- **Web Portal parity (Stream filters, sorting & formatter section, per selected profile):** every setting the TV offers is editable in the portal:
  - every option-backed attribute group (Stream type, Resolution, Quality, Encode, Visual tag, Audio tag, Audio channel, Language, Subtitle), with *Required* / *Excluded* / *Included* as checkbox grids and *Preferred* as an ordered list with ↑ / ↓ / remove and an add picker;
  - Keywords and Release groups (all four lists; a Preferred list ranks in typed order);
  - Regex patterns (all four lists, Preferred lines optionally named, with the `n` negate flag);
  - Seeders and Age (keep only / remove / always keep);
  - Size and Bitrate, global plus per resolution, for movies and series;
  - Result limits, and the Deduplicator (on/off, compare mode, match keys);
  - all four sort lists (`Global`, `Movies`, `Series`, `Anime`), with add/remove, ↑ / ↓ ordering and a direction toggle for each criterion.
  - `Save filters` and `Save sorting` each replace that stage's rules.
  - **Validation:** `POST /api/streams/filters` and `/api/streams/sort` refuse, with a `400` and a message naming the field (nothing is written):
    - a value that isn't one of the TV's choices for an option-backed group;
    - an unknown resolution in a per-resolution size/bitrate row;
    - a negative number, or a min above its max;
    - an invalid regex, or one with an unknown flag (only `i m s n`, plus the ignored `g u y`);
    - free-text entries over 200 characters, or lists over 200 entries;
    - the deduplicator switched on with nothing to match by;
    - a sort list naming a criterion twice.
  - Accepted rules are clamped and tidied exactly like an imported JSON backup.
- **Backup & copy:** a profile's three stages (rules plus each stage's master toggle) move as one unit; nothing else (General Settings, addons, other profiles) is touched.
  - TV: `Settings → UI → Copy stream settings from…` (§11) copies another profile's stages onto the active profile.
  - Web Portal (Stream filters, sorting & formatter section, for the selected profile): `Export JSON` downloads `seastreams-stream-settings-<profile>.json`; `Import JSON` uploads such a file (from this or another TV) and replaces the selected profile's stages. The file holds `version` (`1`) and `filters` / `sort` / `formatter`, each `{ "enabled": …, "rules": … }`. Import refuses invalid JSON, another version, unknown values and invalid regexes with a readable message (nothing is written); seeder, age, size, bitrate and result-limit numbers outside their valid range are clamped (negative → 0, over the maximum → the maximum, a reversed min/max pair is swapped), and templates over 8,000 characters are refused.
- **Out of scope:** the Stream Expression language and debrid cache filters.

## 14. Debrid Library (Milestones 11–12)
SeaStreams plays files the user **already has** in their Debrid accounts: their cloud files, finished torrents and downloads. It is a **library scanner, not a torrent cache scraper**. Everything in this section is **app-wide** (shared by all profiles), like Usenet (§12). Milestone 11 delivers provider management, sign-in, connection tests, the Sources overhaul (§11) and the Web Portal. Milestone 12 delivers the library scanner, the built-in `Debrid` addon entry, stream processing and playback.

- **Library-only rule:**
  - SeaStreams only lists and reads the user's own library on each enabled provider. It never queries public torrent indexers or scrapers, never asks a service whether an unowned hash is cached (no `instantAvailability` / `checkcached` / `cache` calls), never adds magnets, NZBs or links, and never starts a download or transfer.
  - A title the user hasn't added to a Debrid account themselves (on the service's website or another app) shows no Debrid results.
- **Providers** (one account per service; order set on TV or in the portal):

  | Service | Sign-in | Library scanned |
  |---|---|---|
  | Real-Debrid | Device code (open-source client) or API token | Finished torrents + downloads |
  | AllDebrid | PIN code or API key | Ready magnets + saved links |
  | TorBox | Device code or API key | Torrents, Usenet jobs and web downloads |
  | Premiumize | API key | Cloud files + finished transfers |
  | Debrid-Link | API key (device code once a client ID is configured) | Seedbox torrents + downloader links |
  | Offcloud | API key | Cloud history |
  | put.io | Personal OAuth token (OAuth code once a client ID is configured) | Files |

  - Keys and tokens are encrypted at rest with the Android Keystore key (`SecretCipher`, as Usenet passwords). They never appear in logs, stream URLs, LAST USED records or portal responses. A credential that can't be decrypted (e.g. after a restore to a new device) or that the service revoked shows as *Sign-in needed*.
  - Real-Debrid device sign-ins refresh their token automatically before it expires and after a `401`. A failed refresh shows *Sign-in needed*.
  - **Device code sign-in (Web Portal):** the portal shows the code and the service's link page (`real-debrid.com/device`, AllDebrid's PIN page, TorBox's link page) with a countdown. The TV app polls the service and saves the token, and the portal turns to *Signed in*. An expired, denied or cancelled code says so and offers to start again. Starting a new sign-in for the same service cancels the previous one, and a code that completes after the provider was removed or `Clear Debrid settings` ran is discarded.
- **Matching (Milestone 12):** when a title's streams are resolved, each enabled provider's library listing (cached for 60 seconds) is matched against the requested title:
  - Movies: normalised title, plus release year ±1.
  - Episodes: `SxxEyy` / `1x02` (multi-episode ranges included). Inside season packs and folders the matching episode file is picked.
  - An IMDb id (`tt1234567`) in a file or folder name matches that title outright.
  - Only video files count. `sample`/`proof` files and files under 5% of the largest file are dropped.
  - Each provider reads the file list of at most its 8 best-matching library items per lookup, so large libraries stay within the services' rate limits.
- **Addon list & streams (Milestone 12):**
  - While `Enable Debrid` is `ON` and ≥ 1 provider is enabled, every profile lists the built-in `Debrid` entry in *Manage addons* (§8): bottom by default, non-removable, movable, renamable and switchable per profile. A profile that switched it off is not searched.
  - Matching files appear under one `Debrid` card in the stream panel's Addons column, at the entry's position. `Preferred auto-play addon` and the `Addon` sort criterion treat it like any addon.
  - Results go through the §13 pipeline exactly like Stremio and Usenet streams: per-profile filters, deduplication, sorting, result limits and the formatter. Each stream's type is *Debrid*, its filename and size come from the library, and the service name (`Real-Debrid`, `TorBox`, …) is shown where the predefined formatters show the indexer (`{stream.indexer}`), as for Usenet.
  - Auto-play, LAST USED (the stream is remembered by a stable library identity, never by a temporary link), *Automatic stream failover* and the failover timeout work exactly as for other streams.
- **Playback (Milestone 12):**
  - A fresh HTTPS playback link is requested from the service just before playback starts: at auto-play, on a pick, on every failover advance and on Streams-overlay switches. Links are reused for up to 20 minutes.
  - A file that was deleted from the account, a revoked key or a refused link is skipped silently, like a refused Usenet release (§12 *Pre-playback resolution*): with failover on, the next stream is tried at once (`Stream N didn't start (file not found on Debrid). Trying stream N+1 of T…`). With failover off, playback stops with the reason in its status and the Streams overlay opens.
  - Plays in the built-in ExoPlayer (with *Parallel stream connections*) and in external players, which receive the resolved HTTPS link directly.
- **Out of scope:** cache checks for hashes the user doesn't own, adding magnets/links, starting or managing downloads, scraping public indexers, browsing the Debrid library as a catalog, and non-video files.
