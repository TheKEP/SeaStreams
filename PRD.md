# PRD.md — SeaStreams Product Requirements Document

## 1. Visual Design System (Derived from `docs/ui-references/`)
- **Theme:** Deep dark theme (`#000000` default background, `#161A23` surface cards, crisp white `#FFFFFF` primary text, `#A0A8B8` secondary text, `#E5E9F0` high-contrast pill focus states). Selectable background theme swatches in Settings: `#000000` Black (default), `#171535` Midnight indigo, `#351529` Plum, `#351515` Oxblood, `#153535` Deep teal, `#826098` Muted purple, `#0E1621` Midnight slate, and `#17212B` Steel blue.
- **Top Navigation Bar (`home-hero.jpg`, `home-catalogs.jpg`):**
  - **Top-Left:** Active profile circular avatar + live system clock in 12-hour `h:mm a` format (e.g. `12:15 AM`, `Locale.US`), never 24-hour time. All user-facing clock times across the app use this 12-hour format.
  - **Top-Right:** Rounded translucent pill container holding: Search (magnifying glass icon), `Home`, `Movies`, `TV Shows`, `Library`, and Settings (gear icon). *(Note: When an age-restricted Kids profile is active, `Movies` and `TV Shows` tabs are hidden).*
  - **Back Button Navigation:** Pressing Remote `Back` from content on any top-level screen (`Home`, `Movies`, `TV Shows`, `Library`) moves D-pad focus directly to the Top Navigation Bar onto **that screen's own pill** (`Home` on Home, `Movies` on Movies, `TV Shows` on TV Shows, `Library` on Library) — never a previously focused pill, such as the `Settings` gear left focused after closing `SettingsScreen`. A second `Back` while that pill is focused leaves the screen (Home → profile switcher; other tabs → Home). A D-pad `Up` from the content into the bar likewise lands on the active screen's pill (the bar keeps no last-focused-pill memory). Closing `Settings` with `Back` returns focus to the `Settings` gear that opened it.
  - **Long-Press Back → Search (global shortcut):** On every screen reached after a profile is chosen — `Home`, `Movies`, `TV Shows`, `Library`, `View More`, `Details`, `Episodes`, `Settings` (and its sub-panels) and `Search` itself — pressing and **holding** Remote `Back` past the system long-press timeout opens `SearchScreen` directly with D-pad focus on the Microphone button. Any open `Details` / `Episodes` / `Settings` pages are closed and Search opens on top of the tab or `View More` page underneath, so a later short `Back` from Search returns there (an unconfirmed background-colour preview is discarded, as with `Back`). Already on Search, the hold just moves focus to the Microphone (a no-op if it is already there) and never pops Search.
    - **Short press unchanged:** A `Back` released before the timeout behaves exactly as described elsewhere (nav-bar pill, close a page, Home → profile switcher). The press is held back until release, so nothing reacts to it early and nothing reacts twice.
    - **No phantom actions:** Once the hold fires, every further repeat and the trailing `KeyUp` are consumed: no short-press `Back` action runs, the stack is not popped, the app does not exit, and nothing on Search is clicked when `Back` is released.
    - **Exclusions:** The shortcut is off — `Back` (short or held) keeps its existing behaviour — during video playback (the built-in player for movies, episodes and full-screen trailers, §9), the initial stream-lookup loading screen and `Finding streams…` / `Loading trailer…` lookups, the stream selection modal (§6), the splash (§2, `Back` consumed), onboarding, and the Profile Gate (`ProfileSelectScreen`, `ProfileCreateScreen`), so it can never skip mandatory profile creation or selection. Dropdown popups and the on-screen keyboard keep `Back` to themselves.
  - **Full-Bar Wrap Loop:** The whole bar is one horizontal row for the §1 Edge-Stop-Then-Wrap Rule, from the top-left **Profile Avatar** (left-most focusable item) through the pills to **Settings** (right-most focusable item): Adult `Avatar`, `Search`, `Home`, `Movies`, `TV Shows`, `Library`, `Settings`; Kids `Avatar`, `Search`, `Home`, `Library`, `Settings`. A fresh `Right` on `Settings` wraps to the Avatar, and a fresh `Left` on the Avatar wraps to `Settings`. Held `Left`/`Right` stops on that edge item. `Avatar` ⇄ `Search` is ordinary navigation in both directions (the clock is not focusable).
- **Global Edge-Stop-Then-Wrap Rule (applies to every screen, including all Milestone 4+ screens):** Focus never wraps automatically while a direction key is held down.
  - **Held key (`KeyEvent.nativeKeyEvent.repeatCount > 0`):** Focus stops and stays on the edge item: the last item of a horizontal row (`Right`) or the bottom-most row/element of a page (`Down`), and, on surfaces that wrap both ways, the first item of the row (`Left`) or the top-most element (`Up`). Auto-repeat events at the edge are consumed so focus neither wraps nor escapes elsewhere.
  - **Fresh press at the edge (`repeatCount == 0`):** Only when focus is *already* on the edge item and the user presses that same outward direction again as a new key press does focus wrap: `Right` → item #1 of the row; `Down` → the top of the page. **Bidirectional surfaces** also wrap backwards: `Left` on item #1 → the last *currently visible* item of the row; `Up` on the top-most element → the bottom-most visible element. Bidirectional today: the Top Navigation Bar (Avatar ⇄ `Settings`), the `DetailsScreen` action stack (§6), the Player HUD bottom action bar (§9), the stream selection modal opened from Details/Episodes (§6), the in-player `Streams` overlay (§9), both columns of the More Episodes screen (season pills and episode rows, §6), the Library A–Z quick-jump bar (§7: `#` ⇄ `Z`), the Library filter sidebar ⇄ A–Z quick-jump bar (§7: `Left` on `All` / `Movies` / `TV Shows` ⇄ `Right` on any letter), the in-player Subtitles overlay (§9: `Off` ⇄ `Background`), the Settings Category Tab Bar (§11: `Home` ⇄ `Other`, horizontal), the Settings background color swatch strip (§11: `#000000` ⇄ `#17212B`, horizontal), the `Subtitle styling` Text color swatches (§11: `White` ⇄ `Light grey`, horizontal), and the Manage addons sub-panel (§11: first addon row ⇄ `Install more addons`). On these vertical lists a fresh `Up` on the first entry wraps to the last entry and a fresh `Down` on the last entry wraps to the first; held `Up`/`Down` stops on the edge entry. The stream modal and `Streams` overlay hold two such lists side by side (§6 Two-Column Stream Panel): the `Addons` column and the `Choose a stream` column each wrap `Up`/`Down` on their own, `Left`/`Right` switch between them, and the outer `Left` (in `Addons`) and outer `Right` (in `Choose a stream`) are consumed. A single-item row or list consumes both directions and keeps focus in place. **One-way (bottom-to-top) exception — General Settings category lists (§11):** in every Settings category list only the bottom edge wraps: a fresh `Down` on the last row wraps to the first row (held `Down` stops on the last row), while a fresh `Up` on the first row moves focus up to the active category pill in the Settings Category Tab Bar instead of wrapping (held `Up` stops on the first row). The bottom edge follows conditional sub-settings such as `Failover timeout duration` under `Playback` or `Mute auto-play trailers` / `Trailer auto-play delay` under `UI`; with a single row, `Up` goes to the active pill and `Down` keeps focus on that row.
  - Implementation: shared `Modifier.onDpadEdgeWrap(key, wrap)` in `ui/theme/FocusModifiers.kt` (any direction: put it on the edge item with that edge's outward key); two-way vertical lists use `Modifier.verticalListEdgeWrap(index, lastIndex, toFirst, toLast)` + `rememberListEdgeWrap(...)` in `ui/theme/ListEdgeWrap.kt`, built on it. New rows/grids/pages must use these rather than hand-rolled wrap handlers.
  - **Key-Up / Phantom Click Guard (Global):** Opening any overlay, HUD, or modal via `DPAD_CENTER`/`Enter` (`KeyDown` or `onLongClick`) must consume or ignore the trailing `KeyUp` event from that same physical press so newly focused controls (e.g., the Player HUD `Play/Pause` button or the 1st item in a stream selection modal) never fire an accidental click on key release. Shared via `Modifier.ignoreInitialKeyUp()` in `ui/theme/FocusModifiers.kt`. Long-press state belongs to the press on the focused control and is cleared whenever focus moves, so returning to a control after the modal or menu its long-press opened never swallows the next `OK` (shared via `Modifier.selectLongPress()` in `ui/theme/SelectLongPress.kt`).
- **Watched Artwork Indicator (Global):** Whenever a movie, TV show, or episode is marked as watched (`>= 90%` progress or manually marked watched), display a crisp white checkmark (`Icons.Rounded.Check` / `#FFFFFF`) inside a subtle dark translucent circular pill at the **top-right corner** of its artwork (with uniform `6dp–8dp` corner padding so it remains legible over bright posters/stills). Do **not** render a bottom progress line for completed/watched items (reserve bottom progress bars strictly for active, in-progress items `< 90%` in `Continue Watching` or partially watched episodes).
  - **Artwork Progress Bar Styling (`ArtworkProgressBar` in `ui/components/WatchedIndicator.kt`):** Uses its own opaque `ArtworkProgress*` tokens in `ui/theme/Color.kt`, separate from the player seek bar's tiers (§9, which keep their blue buffered range), never a translucent white track. Watched portion is `ArtworkProgressWatched` (`#FFFFFF`, crisp white); unwatched track is `ArtworkProgressTrack` (`#4A5263`, a lighter slate grey that stays distinct from both the backing and the white fill); a `1dp` `ArtworkProgressBorder` (`Obsidian`, `#0B0D12`) backing surrounds it so it stays separated from bright posters and backdrops. The fill is `6dp` tall (`8dp` with the backing), pill-capped, and drawn in a single draw-only node so the `2:3 ↔ 16:9` width animation stays at 60fps.
  - **Focus-Ring Clearance:** The bar is inset `5dp` from the artwork's bottom edge (the `3dp` `#E5E9F0` focus ring plus a `2dp` gap) and `10dp` from each side (inside the ring's `12dp` rounded corners), so the focus ring of a focused poster or expanded 16:9 card never covers, clips, or touches any part of it. Card height is unchanged. Overlays anchored to the artwork bottom (the Continue Watching `S7:E10` badge and the expanded card's title logo) sit above the bar's `13dp` clearance (`ArtworkProgressClearance`).
  - **Visibility:** `0% < progress < 90%` → bar only (fraction clamped to `0..1`); `>= 90%` or manually marked watched → checkmark only, no bar; no saved progress or unknown duration → neither.
- **App Icon & TV Banner (Launcher Artwork):** Generated from two brand references (never hand-drawn): `docs/ui-references/tv_icon.png` (1:1, cyan-to-blue wave play triangle above the lowercase `seastreams` wordmark on pure `#000000`) and `docs/ui-references/tv_banner.png` (16:9, the same triangle left of the wordmark on pure `#000000`).
  - **Square icon (`@mipmap/ic_launcher`, `@mipmap/ic_launcher_round`):** Adaptive icon with a `#000000` background layer and a `108dp` foreground whose artwork is scaled so every non-black pixel stays inside the `66dp` safe-zone circle (`31dp` radius). Circle, squircle, and rounded-square masks (Google TV "Your apps", Monet, Projectivy circle/square modes, Android Settings > Apps) never clip the triangle or the wordmark. Legacy `48dp` square and circle rasters ship in `mdpi`–`xxxhdpi` as fallbacks.
  - **TV banner (`@drawable/tv_banner`):** `160x90dp`, i.e. the Android TV `320x180px` xhdpi spec (`160x90` mdpi → `640x360` xxxhdpi px), pure `#000000` preserved, the lockup centred at ~80% of the banner width (~10% side margins).
  - **Launcher compatibility:** `android:banner` is set on both `<application>` and the `LEANBACK_LAUNCHER` `MainActivity`, because third-party launchers read either `ActivityInfo.banner` or `ApplicationInfo.banner` in 16:9 card mode and fall back to the activity/application icon in 1:1 or circle mode. The launcher icon never appears on the system splash (see §2 *System launch window*).

## 2. Onboarding & Profiles (Max 5 Profiles)
- **Startup Splash Screen (precedes the Profile Gate):** Every cold launch shows a native Jetpack Compose splash (`SeaStreamsSplashScreen`) before `ProfileCreateScreen` / `ProfileSelectScreen`.
  - **System launch window:** Pure black `#000000` window background with no system splash icon (Android 12+ `windowSplashScreenAnimatedIcon` is transparent), so there is no duplicate centre-icon flash before the Compose splash appears.
  - **Layout:** Pure black `#000000` full-screen background (independent of the user's Settings background colour). Centred row: the SeaStreams icon (`R.drawable.ic_seastreams_icon`, `96dp`) then `24dp` gap then the lowercase wordmark `seastreams` in white Fredoka SemiBold (`R.font.fredoka_semibold`, `64sp`), each letter its own `androidx.tv.material3.Text` with font padding disabled. Because the wordmark is all x-height letters (no ascenders/descenders), its ink sits below the centre of its line box. The icon is shifted `14dp` down so its top corner sits above the `s`, its bottom corner below, and its right-hand tip near the `s` waist (`docs/ui-references/tv_banner.png`).
  - **Pop-in and bobbing animation (one-shot, no loop):** The splash holds pure black for `420ms`, so the Android TV launch crossfade and startup work finish before any letter moves. Letters then appear left-to-right over `2840ms` (`110ms` stagger, `1850ms` each; `9 × 110ms + 1850ms = 2840ms`). In the first 26% of its life, each letter fades in and rises boldly out of the water from `0.25x` / `18dp` below / `-14°` to a crest (`1.12x`, `13dp` up, tilted ~`10°` right). It then bobs like a float on a slow swell (dips ~`7.8dp` below the baseline, rises ~`2.7dp` back above), rocking side-to-side (~`6°`, then ~`2°`) with a slight lag, and settles exactly flat.
  - **Hold & exit:** After the motion settles (`420ms + 2840ms`), the still wordmark holds for ~`90ms`: the splash stays up for at least `3350ms` from first frame *and* until the initial profile/TMDB-key gate state has loaded (`AppGate != Loading`), then hands off to the Profile Gate. It shows once per process: it is not replayed after configuration changes or when returning from Home to the profile switcher.
  - **Profile Gate preload:** When profiles already exist (`AppGate.Ready`), the splash creates the Profile Gate's ViewModel, so the child-safe featured backdrop (same `GetProfileGateBackdropUseCase` filtering, rule 6) is fetched and decoded into Coil's memory/disk cache behind the splash. `ProfileSelectScreen` then draws its artwork on its first frame with no empty or loading flash. The preload does not run during first-run onboarding, because the Kids-aware filter must see the real profile list.
  - **Input:** Remote `Back` is consumed during the splash (no accidental exit); the splash has no focusable elements, so no D-pad focus is set until the Profile Gate draws.
- **Profile Gate (`profiles.jpg`):** On startup, if no profile exists, launch directly into Profile Creation. If profiles exist, display the vertical "Choose a Profile" selector on the left with full-bleed featured backdrop art on the right, plus an edit pencil icon and `+` button (up to 5 profiles).
  - **Opened from Settings (`Settings → Home → Profiles`, §11):** The `Profiles` row opens the same `ProfileSelectScreen` (same artwork filtering, edit pencil and `+` button) as a full-screen layer over `SettingsScreen`, which stays open underneath. Remote `Back` on `ProfileSelectScreen` returns directly to `SettingsScreen` with D-pad focus on the `Profiles` row (never exiting the app or jumping to Home). Selecting any profile (including the current one) switches to it and enters that profile's `Home` exactly as from the startup gate, with Settings closed.
  - **Child-Safe Profile Gate Artwork:** Backdrop artwork displayed on `ProfileSelectScreen` must never pull from Adult `Continue Watching` history and must exclude all **Horror** (TMDB genre ID `27`) and **Romance** (TMDB genre ID `10749`) titles (plus `Thriller` `53` and `Crime` `80`), while enforcing a strict family-safe certification ceiling (`PG` / `TV-PG`, `allowUnrated = false`) via `AgeRestrictionEngine` whenever at least one Kids/age-restricted profile exists on the device (or capping at `PG-13` / `TV-14` with `allowUnrated = false` if only Adult profiles exist). This is re-evaluated live: the moment a Kids profile is added (or a profile is switched to Kids), any artwork chosen under the Adult-only ceiling is hidden and a stricter backdrop is fetched. If that fetch fails, the dark background stays; the adult artwork is never shown again.
- **Mandatory TMDB Key & Web Portal Input:** During first profile creation, the user must enter a valid TMDB API key (validated via a test call to `/configuration`) before proceeding. Users can type via on-screen keyboard OR scan a QR code / visit the local LAN IP (`http://<tv-ip>:8765`) to type the API key and profile name from a phone/PC browser.
- **Profile Age Restrictions:**
  - Profiles can be standard (Adult) or Kids (Age-Restricted with max certification ceiling, e.g., `G`, `PG`, `PG-13` / `TV-Y`, `TV-Y7`, `TV-G`, `TV-PG`, plus a toggle to `Allow/Disallow Unrated Items`).
  - **Hard Filtering:** On Kids profiles, any movie/show outside the allowed rating—or unrated when disallowed—is stripped at the data layer even if returned by an external Stremio addon or MDBList.

## 3. Home Screen Architecture
- **Adult Profile Home Layout:**
  1. **Hero Carousel (`home-hero.jpg`):** Large rounded-corner featured card spanning screen width. Pools the first 15 items of `https://mdblist.com/lists/official/movies/justwatch-streaming-charts` and the first 15 of `https://mdblist.com/lists/official/shows/justwatch-streaming-charts` (30 total, de-duplicated), shuffles them, and caps the carousel at 10 items per Home screen load (only titles with backdrop art qualify). Horizontal D-pad scrolling cycles items; displays logo/title, match/rating %, year, genres, certification, runtime, truncated synopsis, and a focused `View Details` pill button.
     - **Focus Ring:** While the hero holds D-pad focus, the card shows the same crisp `3dp` `#E5E9F0` focus border used by focused catalog cards (shared `FocusBorderWidth` / `Modifier.focusRing` in `ui/theme/FocusModifiers.kt`), drawn on the hero's own rounded shape.
     - **Continuous 5-Second Auto-Advance:** The hero advances to the next item every 5 seconds, wrapping from item #10 back to #1, for as long as Home is on screen — including while focus is on the Top Navigation Bar or the catalog rows below. Only direct interaction with the hero (Left/Right on the hero card, or pressing its button) restarts the 5-second countdown. The timer pauses when Home leaves the foreground (`ON_PAUSE`/`ON_STOP`) or the user navigates to another screen.
  2. **Continue Watching (`home-genres-continue.jpg`):** Horizontal row of the user's last 10 in-progress movies/episodes with progress bars (§1 Artwork Progress Bar Styling, on both the 2:3 posters and the expanded 16:9 card) and season/episode badges (`S7:E10`, sitting above the bar). Clicking an item either starts playback immediately (if *Auto-play from Continue Watching* is ON, the default) or opens its Details page (if OFF).
     - **Direct-to-Playback (Auto-play from Continue Watching ON):** `OK`/`Enter` on a card goes straight from `Home` to playback of **that card's** movie or exact episode — never opening, flashing, or stacking `DetailsScreen`. The title is loaded age-checked for the profile at the use-case layer (`ResolveContinueWatchingTargetUseCase`), its IMDb ID is fetched lazily via `/external_ids` for that single title only, and the **top stream result** auto-plays (regardless of *Auto-play top stream*, honoring the preferred auto-play addon) — or that movie/episode's `LAST USED` stream (§6) whenever the freshly fetched list holds it — from the saved resume position, in the built-in player or the configured external player / system chooser. A `Finding streams…` badge shows meanwhile with focus left on the card. Pressing `Back` from playback returns directly to `Home` with D-pad focus restored to that `Continue Watching` card (no trailing `KeyUp` click); if the title is restricted, can't be loaded, or has no streams, a brief message shows and focus stays on the card.
     - **Long-Press Action Menu (`onLongClick`):** Pressing and holding `OK`/`Enter` on a `Continue Watching` card opens the shared centered D-pad action menu (same focus trap, `Down` wrap, `ignoreInitialKeyUp()` held-`OK` guard, and `Back` dismiss behavior as `EpisodesScreen` in §6) with three options, in order:
       - `View details`: Dismisses the menu and opens `DetailsScreen` for that movie or TV show, whether *Auto-play from Continue Watching* is ON or OFF. `Back` from Details returns focus to the exact `Continue Watching` card.
       - `Remove`: Hides/dismisses the item from the `Continue Watching` row without altering its watch progress or watched status (`WatchProgressDao` record remains intact). If the user plays that movie or episode again later, it reappears in `Continue Watching` as normal.
       - `Clear progress`: Removes the item from `Continue Watching` **and** marks that specific movie or single episode as unwatched by deleting its progress record in `WatchProgressDao` (for TV shows, only the specific focused episode is cleared, not other episodes or the whole series).
     - **Description Stays Visible:** While the menu is open, the long-pressed card stays the row's wide 16:9 card and its title, metadata line, and synopsis stay shown beneath its artwork (dimmed under the menu's scrim), exactly as while the card held focus; they hide only once D-pad focus actually leaves the row.
     - **Post-Action & Dismiss Focus Restoration:**
       - Pressing `Back` dismisses the menu without making changes and returns D-pad focus to the exact `Continue Watching` item that opened it.
       - Selecting either `Remove` or `Clear progress` dismisses the menu, removes the card from the row, and returns D-pad focus to the `Continue Watching` row onto the **next item to the right** (or onto the **previous item to the left** if the removed item was the last item in the row; if the row becomes empty, focus moves cleanly to the next available row below or the `HeroCarousel` above).
  3. **Most Watched Movies:** Horizontal row pulling from `https://mdblist.com/lists/official/movies/most-watched-week`.
  4. **Most Watched Shows:** Horizontal row pulling from `https://mdblist.com/lists/official/shows/most-watched-week`.
  5. **Metadata Addon Catalogs:** Any catalogs exposed by enabled Stremio metadata/catalog addons populate exclusively on the `Home` screen directly beneath `Most Watched Shows` (in installed addon order, using the standard `ExpandingCatalogRow` with 20-item cap + `View More`).
- **Kids Profile Home Layout:**
  1. **Kids Hero Carousel:** Pools the first 15 entries of `https://mdblist.com/lists/snoak/trending-kids-movies` and the first 15 of `https://mdblist.com/lists/tvgeniekodi/trending-kids-tv-shows` (30 total), strictly filtered through `AgeRestrictionEngine` against the profile's ceiling, shuffles them, and caps the carousel at 10 items per Home screen load. Same focus ring and continuous 5-second auto-advance as the Adult hero.
  2. **Continue Watching:** Last 10 watched items for that Kids profile.
  3. **Trending Family Movies (TMDB, "New on Streaming" digital releases):** `GET /discover/movie` with `region=US`, `with_release_type=4` (Digital), `release_date.gte=<today − 90 days>`, `release_date.lte=<today>`, `watch_region=US`, `with_watch_monetization_types=flatrate|rent|buy` (subscription streaming plus digital rental/purchase, PVOD/VOD), `sort_by=popularity.desc`, `certification_country=US`, `certification.lte=PG`, `with_genres=28|12|16|35|18|10751|14|10402|9648|878|10770|53|37` (any of Action, Adventure, Animation, Comedy, Drama, Family, Fantasy, Music, Mystery, Science Fiction, TV Movie, Thriller, Western), `without_genres=80,99,36,27,10749,10752` (Crime, Documentary, History, Horror, Romance, War), `include_adult=false`, `language=en-US`, `page=N`. Dates come from the app clock. After the fetch, the repository layer drops any movie that carries a blocked genre (in any position) or none of the allowed genres. It then hydrates each title and keeps only US `G` / `PG` titles that are also inside the profile's own ceiling (`AgeRestrictionEngine`). A `G`-capped profile never sees `PG`, and unrated titles are dropped even when `Allow Unrated` is on.
  4. **Trending Family Shows (TMDB, "On The Air" with a 60-day lookback):** `GET /discover/tv` with `with_status=0` (Returning Series), `air_date.gte=<today − 60 days>`, `air_date.lte=<today + 7 days>`, `sort_by=popularity.desc`, `certification_country=US`, `certification.lte=TV-PG`, `with_genres=10759|16|35|18|10751|10762|9648|10765` (any of Action & Adventure, Animation, Comedy, Drama, Family, Kids, Mystery, Sci-Fi & Fantasy), `without_genres=80,99,10763,10764,10766,10767,10768` (Crime, Documentary, News, Reality, Soap, Talk, War & Politics), `include_adult=false`, `include_null_first_air_dates=false`, `language=en-US`, `page=N`. The same post-fetch genre check applies, plus a `TV-Y` / `TV-Y7` / `TV-G` / `TV-PG` allowlist intersected with the profile's TV ceiling (a `TV-Y7` profile never sees `TV-G` / `TV-PG`). Both family rows fetch only `page=1` (HTTP-cached 6–12h), show `View More` when `total_pages > 1`, and View More grows them to up to 100 titles (pages 2–5) with identical filtering. No `/external_ids` call is made.
  5. **Metadata Addon Catalogs:** Any catalogs exposed by enabled Stremio metadata/catalog addons populate on `Home` directly beneath `Trending Family Shows` (in installed addon order), strictly filtered through `AgeRestrictionEngine` against the profile's ceiling.

## 4. Expanding Catalog Rows & "View More" Grid
- **Fixed-Slot Catalog Row Layout (`catalog1.jpg`, `home-catalogs.jpg`):** On `Home`, `Movies`, and `TV Shows` tabs, every horizontal row is a **stationary 16:9 showcase slot** (`388 × 218dp`, backdrop + title logo) pinned permanently at the left gutter, followed by a horizontally scrolling strip of **uniform 2:3 posters** (`145 × 218dp`, plus the `View More` card). No strip item ever changes width, and slot and posters share one height, so rows never change height or shift.
  - **Focus & Slot Sync:** D-pad focus moves across the strip posters. When poster *i* gains focus, the slot crossfades to item *i* (backdrop, logo, watched checkmark, Continue Watching progress bar with §1 Focus-Ring Clearance, inline trailer) and the metadata block below it (rating %, year, genre, runtime, synopsis) updates to item *i*. The strip glides so poster *i* sits underneath the slot (focusable but never drawn) and poster *i + 1* sits right next to the slot; no poster ever appears to the left of the slot.
  - **Focus Ring:** The slot draws the `3dp` `#E5E9F0` focus ring only while its row holds D-pad focus on a media poster; the slots of unfocused rows show no ring. When the `View More` card is focused it sits right next to the slot and draws its own ring, while the slot drops its ring and keeps showing the row's last media item.
  - **Memory & Reset:** The slot shows item #1 by default, or the row's last-focused item, and keeps showing it (without the ring) when focus leaves the row with `Up`/`Down`; re-entering with `Up`/`Down` restores focus to that item. It resets to item #1 when the row's catalog data refreshes or when returning from that row's `View More` screen. The metadata block stays visible while a long-press action menu opened from the row is displayed (§3).
- **Catalog Row Scroll Speed (fixed, not user-configurable):** Each step glides the poster strip in `~120ms` (`FastOutSlowInEasing`, zero overshoot; a step that interrupts a glide still in flight retargets with `LinearOutSlowInEasing` to keep its momentum) and crossfades the slot in `~120ms`. Both are shorter than the `150ms` held-key step interval, so every step settles completely before the next held tick fires: focus never outruns the scroll, and posters slide crisply beside the stationary slot without jitter, clipping, drifting, or losing focus. There is no width animation anywhere in the row and no scroll speed setting.
- **Row Cap & Looping (`catalog2.jpg`):** Each horizontal row (Home, Movies, and TV Shows, including metadata addon catalogs and Kids rows) displays up to 20 items. If the source catalog has >20 items (for TMDB `/discover` and `/trending`, including the Kids `Trending Family Movies` / `Trending Family Shows` rows: `total_pages > 1`, so rows only fetch `page=1`), a `View More` (`>>`) card appears at position 21. Pressing `Right` past the end of the row (past `View More`, or past the last item if ≤20 items) wraps focus smoothly back to item #1, following the §1 Edge-Stop-Then-Wrap Rule (holding `Right` stops at the end; a fresh `Right` press there wraps).

That includes `All Genres` when no genre is applied: it still forgets a remembered genre that this filter doesn't have, but the grid doesn't change. With no titles, focus also stays on the control. Switching `All` / `Movies` / `TV Shows` never moves focus off the sidebar.
  - Center: 5-column poster grid (standard 2:3 posters only).
  - Far right edge: Vertical quick-jump letter strip, `#` then `A`–`Z` top to bottom. Focusing a letter highlights it at once; the grid scrolls (instantly, no animation) to that letter's first title only after focus has rested on it for ~100ms, so holding `Up`/`Down` scrubs smoothly through the bar without moving the grid or loading posters for each letter passed through. `OK` cancels any pending scroll, jumps immediately and moves focus onto that title. Only one grid scroll is ever in flight. Letters with no titles are dimmed but stay focusable, so the bar's edges are always `#` and `Z`.
  - **Two-way wrap (§1 rule):** A fresh `Up` (`repeatCount == 0`) on `#` scrolls the bar to and focuses `Z`; a fresh `Down` on `Z` scrolls back to and focuses `#`. Holding `Up`/`Down` (`repeatCount > 0`) stops on the edge letter and never wraps or leaves the bar. A single-letter bar would consume both `Up` and `Down` and keep focus in place.
  - **`Left` from a letter (deterministic):** `Left` on any letter (`#`, `A`–`Z`) never uses spatial focus search. It cancels any pending 100ms preview scroll, scrolls the grid immediately (no animation) to that letter's first title, and moves focus onto that exact poster. It uses the same letter matching as `OK`: titles file under their first letter after a leading `The`/`A`/`An` is dropped, `#` holds every title that doesn't start with `A`–`Z`, and "first" means first in the current filter/genre/sort display order.
    - **Dimmed letter (no titles):** `Left` targets the first title of the *nearest populated letter* on the bar (fewest letters away, in either direction). On a tie it takes the *following* letter. For example, with only `B` and `D` populated, `Left` on `C` lands on `D`'s first title and `Left` on `#` lands on `B`'s. `OK` on a dimmed letter still does nothing.
    - **No target:** if no letter has titles, `Left` is not consumed and ordinary focus search runs, so focus is never trapped. The bar is hidden on an empty grid anyway. If the target poster can't take focus within a few frames, focus stays on the letter, so it is never lost.
    - Only the fresh press (`repeatCount == 0`) jumps. Held repeats are consumed on the letter until the poster has focus; after that they are ordinary grid moves. Each jump (`Left` or `OK`) focuses only its own target poster, so consecutive jumps between nearby letters never land on the previous letter's poster, even while it is still on screen. The debounced preview, `OK` jump, `#` ⇄ `Z` wrap, and Sidebar ⇄ A–Z wrap are unchanged.
  - **Sidebar ⇄ A–Z wrap (two-way, §1 rule):** The left filter sidebar and the right-edge quick-jump bar are the two horizontal edges of the page. A fresh `Left` (`repeatCount == 0`) on any filter (`All`, `Movies`, `TV Shows`) wraps to the quick-jump bar, scrolling to and focusing the letter that last held focus there (`#` until a letter has been focused); holding `Left` (`repeatCount > 0`) stops on the filter. A fresh `Right` on any letter wraps back to whichever filter last held focus before the bar (the currently selected filter, `All` by default, until one has); holding `Right` stops on the bar. Both are consumed, so focus never leaves the page sideways. `Right` from a filter still moves into the controls/grid, `Left` from a letter still goes to that letter's first title in the grid (above), and the bar's `#` ⇄ `Z` wrap is unchanged. With an empty library the bar is not shown and `Left` on a filter does nothing.
  - Settings includes "Clear Library" with a 5-second Undo snackbar/toast before permanent deletion.
  - Remote `Back` from the sidebar, controls, or grid focuses the `Library` pill in the Top Navigation Bar (§1 Back Button Navigation), even right after visiting `Settings`.

## 8. Stremio Addons, MDBList Library Import & LAN Web Portal
- **Stremio Protocol Support:** Parse `manifest.json` (including `catalogs`, `resources`, and `types`), fetch `/catalog/{type}/{id}.json`, `/stream/{type}/{id}.json`, and `/subtitles/{type}/{id}.json`. Every new profile starts with TMDB metadata built-in and OpenSubtitles (or default Stremio subtitle addon) pre-installed and enabled. Metadata addon catalogs render exclusively on `Home` beneath the built-in Home rows.
- **HTTPS & Cleartext HTTP Addons:** Addons may be served over `https://` or plain `http://` (self-hosted or LAN addons such as `http://192.168.4.173:3000/manifest.json`). An explicit scheme is kept exactly as entered and never upgraded or downgraded. A link with no scheme (e.g. `192.168.4.173:3000`) or a `stremio://` link gets `http://` when its host is on the user's machine or LAN (`localhost`, `*.local`, loopback `127/8` and `::1`, private `10/8`, `172.16/12`, `192.168/16`, link-local `169.254/16` and `fe80::/10`, unique-local `fc00::/7`) and `https://` otherwise. A missing `/manifest.json` is appended. The stream, subtitle and catalog requests to such an addon, and the stream and subtitle URLs it returns, may also be cleartext HTTP. The app's network security config permits this (ARCHITECTURE §2).
- **Per-Profile Addons:** Stremio addons are installed per profile, not app-wide. Installing, removing, enabling/disabling, renaming or reordering an addon affects only that profile; Home addon catalogs, stream lists and addon subtitles use only the active profile's enabled addons, in its order. The built-in TMDB metadata addon is present, enabled and non-removable on every profile. While Usenet streaming is configured (≥ 1 enabled provider and ≥ 1 enabled indexer, §12), every profile also lists the built-in `Usenet` entry: added at the bottom of the list (so results keep their original place after the Stremio addons), non-removable, but it can be moved, renamed or switched off for that profile. Its position orders the Usenet card and results like any addon. Deleting a profile deletes its addons. When the app moved from app-wide to per-profile addons, every existing profile received a copy of the previously installed addons (with their order, enabled state and custom names).
- **In-App Addon Manager:** Enable/disable and reorder the active profile's installed addons (addon order also determines the display order of metadata addon catalogs on that profile's `Home`). Opened from `Settings -> Home -> Manage addons` (§11): one row per addon (a toggle pill plus `Move up`, `Move down` and, except for built-ins, `Remove` buttons), closed by an `Install more addons` row that opens the Web Portal. The list follows the §1 two-way edge-stop-then-wrap rule (§11 Manage addons sub-panel).
- **One-Time MDBList Library Import:** Users can import an `mdblist.com` list URL directly into a profile's `Movies` or `TV Shows` Library via the Local Web Portal. This is strictly a one-time batch import: once the list's new items are resolved and inserted into `LibraryDao`, SeaStreams does **not** store a subscription, track list changes, or sync future updates. Titles already in the profile's Library are skipped, never duplicated, replaced or removed: they keep their original date added (`Last Added` order), watch progress, watched state and last used stream. A title listed more than once is imported once, imports never touch other profiles, and the portal reports how many titles were added versus already in the library.
- **Local Web Portal (QR Code + LAN IP):** Single-page web app served by Ktor on the TV's local IP allowing the user to:
  1. Enter/update TMDB API key & profile fields.
  2. Install Stremio addons via manifest URL (`https://`, `http://`, `stremio://`, or a bare LAN `IP:port` such as `192.168.4.173:3000`; the field is plain text so the browser doesn't reject scheme-less addresses), remove, rename, disable, or reorder addons for one selected profile (the editor shows which profile it is editing and defaults to the TV's active profile; changes never reach other profiles).
  3. Import `mdblist.com` list URLs into a profile's `Movies` or `TV Shows` Library (one-time import with no ongoing list tracking/syncing).
  4. Configure the app-wide **Usenet sources** (§12):
     - add, edit, enable/disable, reorder and remove NNTP providers and Newznab indexers, starting from a preset;
     - pick the `Search` / `Download` request header presets and trigger *Update now*;
     - choose a Usenet performance profile or edit its values.

     Passwords and API keys can be typed or replaced here but are never sent back to the browser: the portal only shows whether one is stored. A blank password or API key field keeps the stored one.

## 9. Playback Engine (Media3 ExoPlayer) & Audio/Subtitle Controls
- **Default & External Players (with Full Watch Progress Sync):**
  - ExoPlayer is default; Settings supports launching streams via any installed external Android video player—listing preset/detected video players (Just Player, MX Player, Vimu, VLC, Kodi, plus any other installed app registered for `video/*` via `PackageManager.queryIntentActivities`) as well as an **Other (System App Chooser)** option using `Intent.createChooser`.
  - Launches via `ActivityResultContracts.StartActivityForResult` with `ACTION_VIEW` (`video/*`), passing saved resume positions (`position` / `startfrom` extras) and `return_result = true`.
  - **External Player Progress Preservation:** Parse returned `position`, `duration`, and `end_by` result extras (`position / duration` calculation so exiting partway saves the exact resume timestamp without falsely marking the item watched). If any external player omits position extras on exit, fall back to safe elapsed-time estimation or preserve prior progress—never corrupting or wiping watch status.
  - **In-App Trailer Playback (`PlaybackRequest.Trailer` & Inline Row Previews):**
    - **Details Screen (`PlaybackRequest.Trailer`):** Clicking `Trailer` on `DetailsScreen` always plays full-screen with audio enabled inside the built-in Media3 ExoPlayer (bypassing external player settings and ignoring inline trailer auto-play/mute/delay settings) using adaptive video+audio streams extracted via `NewPipeExtractor` (`MergingMediaSource`). It never writes to `WatchProgressDao`, disables Stremio stream fallback and `autoPlayNextEpisode`, hides Stremio audio/subtitle track pickers and Clean SDH toggles in the OSD, exits automatically back to `DetailsScreen` (restoring D-pad focus to the `Trailer` button) when playback ends, and falls back silently to external YouTube (opening the top-ranked candidate) only if every trailer candidate fails extraction.
    - **Trailer Candidates (multi-candidate fallback):** TMDB's YouTube videos for the title are ranked official `Trailer` → other `Trailer` → `Teaser` (teasers only matter when no trailer is listed), newest `published_at` first within each tier, duplicates removed. Up to **3** candidates are extracted one after another until one yields a playable stream; the next candidate is tried when extraction throws or nothing playable is found. Only when all candidates fail does Details open the external YouTube app, and catalog previews keep their static artwork. This matters because YouTube uploads flagged *made for kids* (COPPA, common on Disney/Pixar/DreamWorks channels) currently can't be extracted by `NewPipeExtractor` v0.27.1 (`UNPLAYABLE`), while the same title usually has another official trailer that can (e.g. Toy Story 5's `Official Trailer` when its `Final Trailer` is kids-flagged). One `/videos` request per title, unchanged.
    - **Stream choice per candidate (SDR only, §10):** the tallest decodable SDR adaptive video-only stream (≤ `2160p` full-screen, smaller cap inline) paired with the best M4A audio stream (`MergingMediaSource`). If no such pair exists — no adaptive streams, every adaptive stream HDR or undecodable, or no M4A audio — the tallest decodable SDR progressive/muxed stream is played as a single `MediaSource`. HDR/Dolby Vision streams are never used in either path; a candidate with neither counts as failed.
    - **Catalog Row Previews (`Home`, `Movies`, `TV Shows`):** Uses a single shared lifecycle-aware `ExoPlayer` instance to play extracted trailers inside the focused 16:9 catalog card after the configured `1s–7s` hover delay (`2s` default), honoring *Auto-Play Trailers* and *Mute Auto-Play Trailers*, showing a top-right white muted speaker icon when muted, recording zero watch progress, and failing silently back to static 16:9 artwork without ever launching external YouTube. Playback is bound to a single card via its composite (row ID + item index + item ID) slot plus active D-pad focus (see *Single-Card Binding* in §4), never by title alone.
- **Auto-Play, Auto-Next Episode & Stream Fallback:**
  - **Auto-Play Next Episode (Enabled by Default):** Toggle in Settings (`true` by default). When a TV episode finishes (`>= 90%` watched or `end_by == "playback_completion"`), automatically resolve the next episode (the next one in sequence, or — during a `Shuffle` / `Shuffle Season` session — a random aired episode from the whole show / that season, as described under *Next Episode Selection* below), fetch streams, and auto-play the **top stream result** (honoring the preferred auto-play addon setting). Works seamlessly in both internal ExoPlayer and external players (upon receiving the completed `ActivityResult` from the external player; exiting early via `Back` saves progress and cancels auto-next).
  - **Next Episode Selection (shared by the HUD `Next Episode` button and Auto-Play Next Episode, built-in ExoPlayer and external players alike):** Every playback session has a shuffle mode that travels with it across episode and stream changes:
    - **Sequential (`None`, default):** Details `Play`/`Resume`, Episodes episode click / episode menu, Continue Watching, and any in-player `Episodes` overlay pick. The next episode in the season, then episode 1 of the following season; at the last aired episode the user is told they're all caught up.
    - **Show (`Shuffle` on Details):** A random aired episode across all regular seasons.
    - **Season (`Shuffle Season` on Episodes):** A random aired episode of that season only; it never moves to another season.
    - Under either shuffle mode the episode that just played is never picked again straight away, and episodes already played in this shuffle session are avoided until every episode in the pool has played, after which a new cycle starts. When the pool holds only the episode that just played (a one-episode show or season), there is nothing to shuffle to and the user is told they're all caught up (auto-next leaves the player).
    - Each shuffled transition resolves streams lazily for the newly picked episode only, honors *Preferred Auto-Play Addon*, *Automatic Stream Failover* and *Failover timeout duration*, shows the loading screen (backdrop + pulsing logo/title) until the first frame, and updates the player title, `Info` overlay and `Episodes` overlay (opening on the new episode's season) to the newly playing season and episode.
  - **Auto-Play Top Stream & Preferred Addon:** Option to auto-play on manual `Play` click (while long-pressing `Play` still opens the stream list), plus a setting to select *which* preferred addon supplies the top stream. Auto-play starts the movie's/episode's `LAST USED` stream (§6) when the freshly fetched list holds it and only otherwise the top stream (preferred addon first); the same rule applies to `Next Episode`, the Episodes overlay and Auto-Play Next Episode. *Auto-play from Continue Watching* (§3) always auto-plays directly from `Home` (LAST USED, else top stream), independent of this toggle.
  - **Automatic Fallback (Automatic Stream Failover, enabled by default):** While the per-profile *Automatic Stream Failover* toggle is `ON` (default), if a stream fails to buffer/start or throws a playback/decoder error within a configurable timeout (*Failover timeout duration*, default `10s`, selectable `10s` / `15s` / `20s`), the player automatically advances to and plays the next stream in the list; after the last stream it shows a message and leaves the player.
    - **Failover `OFF`:** No fallback timer runs, so a slow stream keeps loading until it starts or the user presses `Back`, and the player never advances on its own. A playback/decoder error stops playback on that stream and shows a clear status (`Stream N of T couldn't play. Automatic failover is off — pick another stream.`). The in-player `Streams` overlay then opens so the user can pick any stream by hand, including retrying the failed one. Manual stream selection works exactly as it does with failover on. With the overlay closed, Select/D-pad opens the HUD (its `Streams` button stays reachable). `Back` steps overlay → HUD → leaves the player. Trailers are unaffected.
  - **Playback Buffer Profile (`DefaultLoadControl`):** Configurable read-ahead buffer size in Settings (`Standard` [~50s / 64 MB], `Large` [2 min / 150 MB], `Max` [5 min / 250 MB], default `Large`) with an elevated rebuffer threshold (`5,000ms` on `Large`/`Max`) so ExoPlayer banks video during high-speed bursts to absorb transient ISP/VPS peering dips without stalling. The byte target takes priority over the time thresholds (`prioritizeTimeOverSizeThresholds = false`), and each profile's min and max buffer durations are equal, so ExoPlayer keeps draining the parallel reader's read-ahead ring until the byte target is reached and tops up as soon as playback consumes.
  - **Parallel HTTP Range Reader (`ParallelRangeDataSource`):** Configurable parallel HTTP byte-range connection count (`Off (1x)`, `2x`, `3x`, `4x`, default `4x`) for HTTP/HTTPS media streams. Splits sequential reads into concurrent `Range: bytes=start-end` sub-requests using the shared `OkHttpClient`. The `N` workers run independently of ExoPlayer's read pace: whenever one finishes a chunk, it immediately starts the next sequential range, until the downloaded-but-unread bytes reach a bounded read-ahead ring high-water mark set by the Playback Buffer Profile (`Standard` 24 MB, `Large` 64 MB, `Max` 128 MB; capped at a quarter of the app heap but never below 4 MB per connection; no ring at `1x`). The first 16 MB after every open or seek are fetched as 4 MB chunks for a fast first frame, and later chunks are 8 MB (or smaller when needed to fit one chunk per connection under the high-water mark), so connections spend more time at peak TCP throughput. Every chunk buffer, whether in flight or pooled, counts toward the high-water mark. A seek or close cancels all in-flight ranges at once. The reader transparently falls back to single-stream sequential reading if the upstream server omits `Accept-Ranges: bytes` / `206 Partial Content` or for local/non-HTTP URIs.
- **Audio DSP & Sync (Requires Audio Passthrough Toggle):**
  - Toggle to disable HDMI audio passthrough so PCM audio can be processed on-device.
  - **Effects switch passthrough off automatically:** turning on Dialogue Boost (any level but Off), Night Mode, or a non-zero Audio Delay switches Audio Passthrough off at once, so the effect is heard immediately. This happens in General Settings (saved per profile) and in the player's Audio overlay (this video only, applied live without restarting: the audio drops out briefly while it switches from bitstream to decoded PCM). The user can switch passthrough back on afterwards (Settings row, or the overlay's *Audio passthrough* toggle) and it stays on until another effect is turned on.
  - **Software Audio Decoding Fallback (FFmpeg):** Dolby Digital (AC-3), Dolby Digital Plus (E-AC-3, incl. Atmos/JOC), Dolby TrueHD, DTS and DTS-HD tracks never fail or play silent. When passthrough is off, or the connected TV/AVR/sink can't bitstream the codec and the device has no hardware decoder for it, the track is decoded in software (prebuilt FFmpeg Media3 decoder) to PCM. When passthrough is on and the sink supports the codec, it is still bitstreamed untouched. Dialogue Boost, Night Mode and Audio Delay apply to any PCM output, including FFmpeg-decoded tracks while passthrough is on. Multichannel PCM goes to multichannel outputs unchanged; for stereo-only outputs it is downmixed in-app with clip-safe normalised coefficients (no clipping even at full scale on every channel).
  - **Dialogue Boost:** Off, `+3 dB`, `+6 dB`, `+9 dB`, `+12 dB` center-channel/vocal frequency gain.
  - **Night Mode:** Dynamic range compression evening out loud explosions and quiet speech.
  - **Audio Delay:** Adjustable `-500ms` to `+500ms` (in `25ms` steps) to sync Bluetooth/wireless headphones.
- **Subtitles & HDR:**
  - Global toggle: *Always On* (if available) or *Always Off* (default *Always Off*).
  - Preferred Subtitle & Audio Language settings (both default English): Preferred subtitle language always sorts to the top of the player track list; toggle to *Hide non-preferred subtitle languages* (default `ON`).
  - **Clean SDH Toggle (default `ON`):** Regex/parser filter stripping bracketed/parenthetical sound cues (`[SIGHS]`, `(DOOR CREAKS)`, `♪`) and speaker labels (`JOHN:`) from `.srt`/`.vtt` cues in real time.
  - **Subtitle Styling:** Font size, bold, italic, text color, outline/drop-shadow, and background opacity configurable in General Settings (persistent default; out of the box `100%` size, bold `ON`, italic `OFF`, white `#FFFFFF` text, outline edge, `0%` background opacity) AND inside the Player OSD (session-only override that resets when exiting playback).
  - **Auto-Sync External Subtitles:** With *Auto-sync external subtitles* on (per-profile, default on), an active external (addon) subtitle track is synced automatically while it plays, with no user action and no pause, restart or re-buffer:
    - **Embedded reference first:** when the stream has a full embedded subtitle track (text or Blu-ray PGS bitmap subtitles; never a forced, signs/songs, foreign-parts or commentary track), its cue start times (played in the background, never shown) are correlated with the external cues' start times, so differing display durations and line breaks don't matter. A track in the same language is preferred. Without one, a full track in any other language is used (also when the external track's language is unknown), because a translation of the same release still follows the speech far better than audio; such a reference needs two agreeing checks before it applies anything. If that track shows fewer than 5 lines in its first 20 s, or hasn't locked within 30 s, auto-sync switches to audio at once. Audio has been listening from the start, so it can lock quickly. A same-language track that simply hadn't locked by 30 s keeps playing in the background for up to 2 minutes, so a file timed for another frame rate (see below) can still lock against it.
    - **Audio voice activity otherwise:** decoded PCM speech-energy vs. silence (a non-intrusive tap) is cross-correlated with the external cue intervals across `-60.0s` to `+60.0s` (the manual range) in `0.1s` steps, on a background thread. Offsets beyond ±30 s are only accepted on the fuller one-minute check.
    - **Spoken lines only:** sound-effect captions (`[DOOR SLAMS]`), music-note-only lines and on-screen text held 10 s or longer are left out of the timing analysis (never out of what is shown), since they mark no speech. A file that is mostly captions is analysed whole.
    - **Frame-rate mismatch:** a file timed for a 25 fps (PAL) release drifts ~2.6 s a minute against a 23.976/24 fps video, which no single offset fixes. Once a minute of reference is in, auto-sync also tries the 25↔23.976 and 25↔24 fps clocks (every 20 s while scanning, on every refine and drift check) and applies the clock together with the offset. A non-unit clock needs the full check, a clearly better match than the unit clock, and a clear lead over the opposite direction; the Info row then names it (e.g. `· 25→23.976 fps`).
    - **Fast lock, strict confidence:** analysis runs every 5 s. A first lock is allowed once ~15 s and at least 5 subtitle lines have been heard, but only when the match is unambiguous and most subtitle lines start on a speech (or embedded-cue) onset. Audio also needs two agreeing passes. The fuller check additionally needs both halves of the analysed window to agree on the offset on their own (within 0.4 s), which rejects a wrong frame rate or a timing jump inside the window. Typical dialogue locks in ~20 s, including after a seek. Music/action intros, silence and unrelated audio never cause a shift; otherwise the offset stays `0.0s`.
    - **Lands on dialogue starts:** every detected offset is snapped (in 50 ms steps within ±1.5 s, then rounded to 0.1 s) to when lines actually begin, matching subtitle start times against the embedded track's starts or the audio's speech onsets. Differences in how long lines linger on screen therefore never pull it off by tenths of a second.
    - **Refining:** after a fast lock, a fuller check every 20 s (once a minute of data is in) confirms the value or corrects it, unless the user has nudged the offset.
    - **Drift and jumps:** after locking, the last 2 minutes are re-checked every minute, and the offset is gently re-centred (0.1–1.5 s steps, confirmed twice) when a file drifts against the video (e.g. 23.976 vs 24 fps); the Info row shows `· tracking`. A larger jump (a scene the file's release has and the video doesn't, or the reverse) is followed only after three agreeing checks. This stops as soon as the user nudges the offset.
    - The detected shift moves every cue's start/end before Clean SDH filtering and refreshes the visible cue at once.
    - **Live status:** the HUD sync control shows a small caption under the value: `Syncing…` while scanning, `Auto` once locked, nothing when idle. The Info overlay's *Subtitle sync* row spells it out (e.g. `Syncing… · embedded (0 cues), 20 s`, `Syncing… · audio (18 cues, best +5.1s @ 0.42, 60% onsets), 25 s`, `+2.3s · Auto (embedded subtitles) · refining`, `+1.4s · Manual`, `0.0s · no confident match`), including the line count and best candidate while scanning so on-device problems are visible.
    - A manual `-`/`+` nudge always works, starts from the shown value (keeping any detected frame-rate clock), and stops further automatic changes for that track. Session-only, like the manual offset; a new stream of the same title re-detects unless the user nudged.
    - **Picking a track again:** each stream + external track remembers its result for the session. An auto result is applied at once and drift tracking resumes without a new scan. If the user nudged that track, *their* offset (and clock) comes back with `Manual`, never the earlier auto value, and nothing is re-detected.
  - **Convert Dolby Vision Profile 7 to HDR:** Toggle (enabled/`true` by default) that converts or falls back Dolby Vision Profile 7 (`dvhe.07` / `dvh1.07`) video tracks to standard HDR10/base-layer playback for compatibility with displays/devices that do not support Profile 7 FEL/MEL (see §10 *Dolby Vision Playback*).
  - **Dolby Vision Playback:** `Auto` (default) / `Always Dolby Vision` / `HDR10/HLG base layer` selector deciding whether Dolby Vision Profile 8 plays natively or as its HDR10/HLG base layer (§10).
  - **HDR White Dimming:** Dims the bright whites of the player **UI** (never the video) during HDR10, HDR10+, HLG and Dolby Vision playback (§10).
- **Player Loading & Buffering UI (`PlayerLoadingOverlay.kt`, `video-loading.jpg`; movies & TV episodes only, `PlaybackRequest.Media`):**
  - **Initial Loading (before playback begins):** From the moment auto-play starts looking up streams (Details `Play`/`Resume`/`Shuffle`, Episodes, Continue Watching auto-play, Auto-Play Next Episode), through ExoPlayer preparing the stream and every automatic stream-fallback advance, until the stream renders its **first video frame**, the screen shows the title's full-screen backdrop artwork (no scrim) with its stylized title logo centred. Titles without a TMDB logo show the title as bold text instead. The logo/text pulses with an endless smooth fade-in/fade-out alpha loop. The same screen shows again whenever a new stream source starts in the open player (in-player `Streams` switch, `Episodes` overlay pick, `Next Episode`, Auto-Play Next Episode) until that stream's first frame. Fallback status (`Stream 1 didn't start. Trying stream 2…`) stays visible above it. While the list itself is loading, only the list shows.

The full-screen backdrop is never shown mid-playback, and the pause badge is hidden while the logo shows.
  - **Remote:** On the initial loading screen, `Enter` and the D-pad do nothing (no HUD, pause or seek before there is a picture, and the trailing `KeyUp` of the `Play` press can't fire anything). A fresh `Back` cancels at once: during stream lookup it cancels the lookup, and once the player is open it stops the player without saving watch progress or triggering Auto-Play Next Episode. Either way, D-pad focus returns to the control that started playback (`Play`, the episode row, or the Continue Watching card) with no loading state left behind.
  - **Trailers:** Full-screen `PlaybackRequest.Trailer` playback never uses movie/show loading branding. It keeps the plain loading ring.
- **Player HUD / OSD Controls & Remote Behavior (`PlayerScreen.kt` & `PlayerOverlayControls.kt`):**
  - **Remote Invocation & Back Behavior:**
    - Pressing `Enter`/`DPAD_CENTER` while media is playing pauses playback and opens the Player HUD without triggering the newly focused `Play/Pause` button when the key is released.
    - Pressing `Up` or `Down` while media is playing keeps playback running and opens the Player HUD.
    - **Three-tier single-press `Back` (media playback and the full-screen Details trailer alike):** (1) while a player sub-overlay (`Subtitles`, `Audio`, `Streams`, `Episodes`, or `Info`) is open, one `Back` press closes only that overlay (playback continues) and restores D-pad focus directly onto the bottom-bar button that opened it (`Play/Pause` if that button is not shown); (2) while the main Player HUD is visible with no sub-overlay open, one `Back` press dismisses only the HUD and playback keeps running; (3) while the Player HUD is hidden, one `Back` press exits playback and returns to the previous screen. When playback closes (Tier 3, a finished trailer, or nothing left to play), D-pad focus is restored to the control that started it (e.g. `DetailsScreen` `Play`/`Resume`, `Trailer`, `Shuffle`, or an Episodes row), falling back to the `DetailsScreen` primary `Play`/`Resume` button when that origin is unknown or no longer attached; focus is never left on nothing. Every `Back` event is consumed by the player, so held repeats and the trailing `KeyUp` never reach the previous screen.
  - **Seek Bar Styling (media & trailers, `PlayerSeekBar.kt`; tokens in `ui/theme/Color.kt`):** Three tiers that stay distinct on a real TV over bright or dark video. Every fill is fully opaque, and the tiers differ in both hue and brightness (never white-on-white or grey-on-grey). Drawn in this order, all round-capped, `4dp` thick (`6dp` while focused):
    1. **Backing (`SeekTrackBorder`):** a `1dp` `#0B0D12` (`Obsidian`) outline around the whole track, so it never washes out over white scenes.
    2. **Unbuffered track (`SeekTrack`):** opaque dark slate `#1E2430` across the full width.
    3. **Buffered range (`SeekBuffered`):** opaque brand wave blue `#2B6CB0` from the start to ExoPlayer's `bufferedPosition`.
    4. **Played progress (`SeekPlayed`):** pure `#FFFFFF` from the start to the playhead, drawn **on top of** the blue, so its round cap ends cleanly on the blue with no gap or blending.
    5. **Playhead marker:**
       - *Unfocused:* a `3dp`-wide white vertical tick, `8dp` taller than the bar and outlined `1dp` in `Obsidian`, sits exactly at the playhead. It is drawn once the duration is known and something is played or buffered.
       - *Focused:* the tick is replaced by a `9dp`-radius `#E5E9F0` (`FocusPill`) thumb with a `2dp` `#0B0D12` (`Obsidian`) ring.
    - **Clamping (`seekBarFractions`):** `0 ≤ played ≤ buffered ≤ duration`. A buffered position behind the playhead collapses onto it, and one past the end stops at the end. An unknown duration (`<= 0`) draws only the backing and the track. Zero-length segments are skipped, so a round cap never leaves a stray dot. While scrubbing, the scrub marker is the playhead.

Wrap targets always follow the bar's current layout (`Next Episode`/`Episodes` only for TV episodes, `- 0.0s +` only while an external subtitle is active). The simplified trailer HUD bar is `Play / Pause` alone, so both directions keep focus there. Held `Left`/`Right` stops on the edge control.

    1. **Play / Pause:** Dynamic toggle icon reflecting live playback state (`Pause` icon while playing, `Play` icon while paused).

## 10. Video Output, HDR & Dolby Vision
- **Video Surface:** The built-in player always renders video through a `SurfaceView` (hardware overlay path), so HDR10/HDR10+/HLG static and dynamic metadata and Dolby Vision reach the display pipeline untouched and the TV applies its own tone mapping. Nothing is ever drawn over the video picture except the player UI listed below. The app window keeps `Window.colorMode = COLOR_MODE_DEFAULT` at all times: `COLOR_MODE_HDR` only changes how the app's own UI is rendered and is not needed for HDR video.
- **Dynamic Range Detection:** The playing stream is classified from its selected video track and the decoder's input format: `Dolby Vision` when the track is `video/dolby-vision` or its codecs start with `dvhe.`, `dvh1.`, `dvav.`, `dva1.` or `dav1.` (also while Profile 7/8 plays as its HDR10/HLG base layer), else `HDR10` for a PQ (`ST 2084`) transfer (HDR10 and HDR10+), else `HLG` for an HLG transfer, else `SDR`. It is live state: it updates as soon as the tracks or the video format change, and resets to `SDR` for every new stream.
- **HDR White Dimming (per profile, default `On`):** While on and the playing stream is HDR10/HDR10+/HLG/Dolby Vision, every bright white of the player UI is dimmed to `75%`: the HUD buttons, seek bar and time labels, the loading/buffering logo and pause badge, status pills, toasts, subtitle text, and all non-blocking overlays (`Subtitles`, `Audio`, `Streams`, `Episodes`, `Info`). The video picture itself is never dimmed, so HDR brightness matches other players. SDR playback and every non-player screen are unaffected. Dimming is visual only: D-pad focus and key handling are unchanged.
- **Leaving Playback Returns the TV to SDR:** Whenever playback ends (`Back` exit, cancelling during the initial load, a finished movie/episode/trailer, every stream failing, or leaving the app), the video surface is detached from the decoder and removed in the same frame, before the previous screen shows, and the player is then released. The window's color mode, brightness override and HDR headroom are reset to their defaults. No HDR/Dolby Vision layer is left on screen, so a TV following "match content dynamic range" drops back to its normal SDR UI brightness on Details, Home and every other screen.
- **SDR-Only Trailers:** YouTube trailer streams (full-screen and inline catalog previews) never use HDR formats (VP9 Profile 2, 10-bit HDR AV1, Dolby Vision), so menu screens never switch the TV into HDR.
- **Dolby Vision Playback (per profile, default `Auto`):**
  - **Profile 5:** always plays as Dolby Vision (it has no compatible base layer).
  - **Profile 7 (`dvhe.07` / `dvh1.07`):** plays as its HDR10 base layer while *Convert Dolby Vision Profile 7 to HDR* is on (default) or the mode is `HDR10/HLG base layer`; otherwise natively.
  - **Profile 8 (`dvhe.08` / `dvh1.08`):** `Always Dolby Vision` plays it natively. `HDR10/HLG base layer` plays its HDR10 (PQ) or HLG base layer through the standard HEVC decoder, keeping the stream's own color and mastering metadata. `Auto` plays it natively only when the connected display reports Dolby Vision support, else as the base layer. A Profile 8 track whose base-layer transfer is unknown always plays natively, so an SDR base layer is never mislabelled as HDR.
  - Other profiles (AVC/AV1 Dolby Vision) always play natively.
  - The `Info` overlay's *Dynamic range* row (below *Video codec*) shows the path in use, e.g. `Dolby Vision 8 → HDR10 base layer`, `Dolby Vision 7 → HDR10`, `Dolby Vision (native)`, `HDR10`, `HLG`.

## 12. Usenet Streaming (NNTP) — Sources
SeaStreams streams Usenet releases natively: Newznab indexer search → NZB → yEnc articles fetched from the user's NNTP providers. They play in the built-in ExoPlayer, and in external players through a loopback proxy. Everything in this section is **app-wide** (shared by all profiles), because provider connection limits belong to the account and the device. Delivered across Milestones 7–9.

- **Providers (NNTP):**
  - Fields: name, host, port (default `563`), TLS (default on), username, password, *Max connections* (`1..100`, default `20`), *Pipeline depth* (`1..16`, default `2`; requests kept in flight per connection), priority (`0..99`, lower = preferred), *Backup* flag, enabled.
  - Providers with the same priority share load. Backups are used only for articles the primaries can't supply.
  - Passwords are encrypted at rest with an Android Keystore key. A password that can't be decrypted (e.g. after a restore to a new device) shows as *Password needed*.
  - **Provider presets** fill in name, host, port `563`, TLS and max connections. The 29 entries are: Newshosting, Easynews, Tweaknews (Newshosting deal), Tweaknews (standalone), Eweka, UsenetServer, Giganews, Frugal Usenet, NewsDemon, Usenet.Farm, UsenetExpress, NewsgroupDirect, Newsgroup Ninja, Supernews, Pure Usenet, Sunny Usenet, XS News, ThunderNews, Astraweb, ViperNews, Cheapnews, Fast Usenet, UsenetNow, UsenetPrime, Easy Usenet, Bulknews, XLned, 123 Usenet, Hitnews. Every field stays editable.
- **Indexers (Newznab):**
  - Fields: name, base URL (`https://` or a LAN `http://` address), API path (default `/api`), API key (encrypted like passwords), priority, *Backup only* flag (searched only when no other indexer returned results), enabled.
  - **Indexer presets** fill in the API URL: abNZB, altHUB, AmeNZB, Anime Tosho, Aninzb, ClubNZB, Digital Carnage, DOGnzb, DrunkenSlug, GingaDADDY, Miatrix, NewzBay, NinjaCentral, NZB Atlas, Nzb.life, NZBFinder, NZBgeek, NzbNest, NzbNoob, NzbPlanet, NZBStars, PourCeSoir, SearchNZB, SquareEyed, Tabula Rasa, Treasure Maps, Usenet Crawler, Videothek, plus the LAN templates `NZBHydra2 (your server)` and `Prowlarr (your server)`.
- **Request headers:**
  - Indexer **searches** send the `Search` preset's headers (default `Prowlarr`). NZB **downloads** send the `Download` preset's (default `SABnzbd`).
  - Presets:

    | Preset | User-Agent |
    |---|---|
    | Prowlarr | `Prowlarr/{v} (alpine 3.24.4)` |
    | NZBHydra2 | `NZBHydra2 {v}` |
    | Sonarr | `Sonarr/{v} (alpine 3.24.4)` |
    | Radarr | `Radarr/{v} (alpine 3.24.4)` |
    | SABnzbd | `SABnzbd/{v}` |
    | NZBGet | `nzbget/{v}` |
    | SeaStreams | `SeaStreams/{app version}` |

    Prowlarr/Sonarr/Radarr/NZBHydra2 also send an RSS `Accept` header; SABnzbd/NZBGet send `Accept: */*`. `Accept-Encoding` is left to OkHttp (transparent gzip).
  - **Version auto-updater:** at most once every 24 h (on app start, and when the `Sources` tab opens), SeaStreams reads the latest stable release version of each tool from its public GitHub `releases/latest` endpoint, sending a generic `SeaStreams` User-Agent and no user data. Only a plain version (`2.7.0.5723`, a leading `v` stripped) is accepted.
  - A failed check keeps the last good version. The built-in fallbacks are Prowlarr `2.7.0.5723`, Sonarr `4.0.20.3014`, Radarr `7.0.3.10918`, SABnzbd `5.1.3`, NZBGet `26.3` and NZBHydra2 `9.3.1`.
  - `Update header versions` checks immediately.
- **Performance profiles:**
  - One profile governs every value of the `Usenet performance` sub-panel. Picking `Conservative` (default), `Balanced` or `High` overwrites all of them. Editing any single value switches the profile to `Custom` and keeps the edited values. Fresh installs and unreadable stored values get `Conservative`.
  - **Android TV memory:** the Google TV Streamer 4K gives the app a 512 MB heap. The old `High` (64 segments, unbounded downloads, census 12) caused GC lag and `OutOfMemoryError` there, so every template bounds its concurrent downloads (none uses `0` = auto) and keeps read-ahead ≤ 32 and census ≤ 6. Whatever the values, the in-memory segment cache is capped at a tenth of the heap (≤ 64 MB) and only the volume being played reads ahead.
  - The sub-panel is one list grouped under the screenshot sections (`aio-usenet-settings1–6.png`): **Performance**, **Connections & timeouts**, **Reliability**, **Archive handling**, **Verification**, **Import**.
  - Numbers and choices are `‹ value ›` steppers (`Left`/`Right` step, `OK` steps forward and wraps). Switches are toggles.

- **Storage bound:** the segment disk cache never exceeds the profile value, 25% of the device's free space, or whatever leaves 2 GB free, whichever is smallest. It is cleared by `Clear cache` (§11). The NZB cache keeps at most 40 files for 14 days.
- **Playback (Milestone 9):**
  - Usenet releases appear under a built-in `Usenet` card in the stream panel's Addons column only while at least one provider and one indexer are enabled. The card, its results, `Preferred auto-play addon` and the `Addon` sort criterion follow the `Usenet` entry's position in the profile's addon list (§8; the bottom by default). A profile that switched the entry off is not searched.
  - Addon streams carrying an `nzbUrl` play through the same engine.
  - Plain files, stored (uncompressed) RAR4/RAR5 sets, including obfuscated names, and raw `.001` splits are streamable. Compressed or password-protected RARs (even with an NZB password: decryption is not implemented), and all 7z archives, are *not streamable*: they are dropped, and failover moves on.
  - **Search never grabs NZBs.** Stream search reads only the Newznab search XML (and drops passworded releases and releases already known bad). It never downloads an NZB (`t=get`), so indexer grab quotas are spent only when a release is played. Some indexers (e.g. NinjaCentral) list 7z or password-protected uploads under clean scene titles, so these can only be identified once their NZB is grabbed.
  - **Pre-playback resolution (silent skip).** Before any player is given a `seastreams-nntp://` stream, SeaStreams opens its release: it grabs the NZB, which is then cached, parses it, assembles the media and runs the *Verify budget* census. This happens for the built-in ExoPlayer, at the start of auto-play or a pick, at every fallback advance, and for Streams-overlay switches. It happens the same way for external players.
    - A release that is refused (7z, compressed or encrypted RAR, articles missing beyond the damage policy, not an NZB) is recorded as unplayable for 6 h. ExoPlayer is never prepared with it, so there is no playback error, player re-init or audio-focus change.
    - With *Automatic stream failover* on, the next stream is tried at once. The loading screen or the player's status pill reads `Stream N didn't start. Trying stream N+1 of T…`, and `None of the streams would play` when none is left.
    - With failover off, playback stops on that stream and the Streams overlay opens (§9).
    - A release already known bad is skipped without being opened again.
  - External players reach Usenet streams at `http://127.0.0.1:8765/nntp/<token>/<name>`. The route answers loopback clients only; other clients get `403`. A foreground notification keeps it alive while the external player runs.
- **Out of scope:** the SABnzbd-compatible download API, *Hold SABnzbd hand-off for the census*, *Library recheck* (SeaStreams keeps no saved NZB library), and 7z archives.

## 13. Stream Filtering, Sorting & Formatter (Milestone 10)
Per profile (`p{id}/` keys), edited from `Settings → UI` (`Stream filters`, `Stream sorting`, `Stream formatter`) and the Web Portal. Applied to every resolved stream list (Stremio addons and Usenet) in this order: parse → filter → deduplicate → sort → result limits → format. Auto-play, failover order, LAST USED and the Addons column counts all use the processed list. The defaults are no filters, no sorting and the original addon text, so behaviour only changes once the user opts in.

- **Filters** (`aio-filters.png`):
  - Groups: Stream type, Seeders, Age, Resolution, Quality, Encode, Visual tag, Audio tag, Audio channel, Language, Subtitle, Size, Bitrate, Keyword, Release group, Regex, Result limits, Deduplicator.
  - Each attribute filter has *Required*, *Excluded*, *Included* (kept regardless of every other filter) and *Preferred* (ordered, used by sorting) lists.
  - Languages are excluded only when every language of the stream is excluded, and required when any one matches.
  - Size limits can be set per resolution, separately for movies and series. Bitrate is estimated from size ÷ TMDB runtime.
- **Sorting** (`aio-sorting.png`):
  - `Global`, `Movies`, `Series` and `Anime` lists. A non-empty type list replaces `Global`.
  - Criteria: Quality, Resolution, Language, Subtitle, Visual tag, Audio tag, Audio channel, Encode, Stream type, Size, Bitrate (estimate), Seeders, Age, Addon, Keyword, Regex patterns. Each has its own direction.
  - Preferred-list criteria rank by position in the matching Preferred list.
- **Formatter** (`aio-formatter.png`):
  - Name and description templates use the AIOStreams template syntax: `{stream.resolution::=2160p["4K"||""]}`, `::exists`, `::join(' | ')`, `::rbytes`, `::time`, `{? … ?}` groups, `{tools.newLine}`.
  - Predefined: Torrentio, GDrive, Light GDrive, Minimalistic GDrive, Prism, Custom. The TV picks a predefined formatter with a live preview card; custom templates are typed in the Web Portal.
  - `{stream.indexer}` is the indexer / tracker a stream came from: the Newznab indexer of a built-in Usenet result (`NZBgeek`, `DrunkenSlug`), or the one a Stremio addon names in its text (`⚙️ ThePirateBay`). Built-in Usenet streams stay grouped under the single `Usenet` card in the Addons column, but every predefined formatter shows the indexer where it would show the addon name `Usenet`; the Custom default ends with the indexer for Usenet streams and `Addon · Indexer` when another addon states one.
- **Result limits:** total, per resolution, per quality and per addon, each stepped on the TV through Off → 1, 2, 3, 5, 10, 20, 30, 40, 50.
- **Out of scope:** the Stream Expression language and debrid cache filters.
